## Solove의 프라이버시 침해 분류 (A Taxonomy of Privacy)

| 범주 | 세부 침해 |
|---|---|
| **정보 수집**(Information Collection) | 감시(Surveillance), 심문(Interrogation) |
| **정보 처리**(Information Processing) | 집적(Aggregation), 식별(Identification), 불안전(Insecurity), 2차 이용(Secondary Use), 배제(Exclusion — 정보주체가 자기정보 처리에 관여 못함) |
| **정보 유포**(Information Dissemination) | 비밀 폭로(Disclosure), 폭로(Exposure), 접근성 증대, 협박(Blackmail), 도용(Appropriation), 왜곡(Distortion) |
| **침입**(Invasion) | 침입(Intrusion), 의사결정 간섭(Decisional Interference) |

- **집적(Aggregation)**: 개별로는 무해한 정보를 모으면 새로운 프로파일이 생긴다 → 빅데이터 시대 핵심 위협.
- **배제(Exclusion)**: 정보주체가 자기 정보가 어떻게 쓰이는지 알지 못하고 관여할 수 없는 상태.

## 생명주기별 침해(국내 실무 관점) — 1과목 '가치와 침해유형' 노트와 연결

- **수집**: 과다수집, 기망·눈속임(다크패턴) 동의, 아동 무단 수집
- **저장·관리**: 해킹·악성코드, 내부자 무단조회·반출, 수탁자 유출, 안전조치 미흡
- **이용·제공**: 목적 외 이용, 동의 없는 제3자 제공, 재식별
- **파기**: 미파기·방치, 복구 가능 상태

## 대표 침해 사례 패턴 (시험 지문)

| 패턴 | 위반 조항·원인 |
|---|---|
| 대량 DB 해킹 유출 | 안전조치의무(제29조), 통지·신고(제34조) |
| 직원의 고객정보 조회·판매 | 접근통제·최소권한·접속기록 실패 |
| 협력업체(수탁자) 통한 유출 | 위탁자의 관리·감독 의무(제26조) |
| 개발/테스트 서버에 운영 데이터 복제 | 가명·익명처리 없이 노출 |
| URL 파라미터 변조로 타인 정보 조회 | 취약한 접근제어(제29조·고시) |
| 이용약관에 묻힌 포괄 동의 | 동의의 유효요건 위반(제22조) |

## 2차 피해

유출된 개인정보 → **스팸·스미싱·피싱**, **명의도용**(대포폰·대출), **보이스피싱**, **계정 크리덴셜 스터핑**.
- 개인정보는 한 번 유출되면 **회수 불가** — 예방이 최선.

## 함정 포인트

- Solove 분류의 4대 범주: **수집 · 처리 · 유포 · 침입**.
- "집적(Aggregation)"은 정보 **처리** 단계 침해. "감시(Surveillance)"는 **수집** 단계.
- 다크패턴에 의한 동의는 "자유로운 의사"가 아니므로 **무효**.
