## 공개 웹을 통한 개인정보 노출 유형

| 유형 | 예 |
|---|---|
| **취약한 접근제어** | URL 파라미터(`?id=1001`) 변조로 타인 정보 조회, 순번형 문서 URL |
| **인증·인가 우회** | 로그인 없이 관리자 페이지 접근, 권한 상승 |
| **디렉터리 리스팅** | 웹서버가 폴더 내 파일 목록을 그대로 노출 |
| **백업·설정 파일 노출** | `.bak`, `.zip`, `.env`, `phpinfo()` |
| **검색엔진 색인** | 개인정보가 담긴 페이지가 구글에 노출 |
| **에러 메시지** | 스택 트레이스·쿼리·경로 노출 |
| **소스코드·주석** | 클라이언트 코드에 API 키·내부 URL |

## 대응

- **취약점 점검 정기 실시**(일정 규모 이상 처리자는 의무): 웹 스캐너 + 수동 점검, 발견 취약점 조치·재점검.
- **접근제어 강화**: 객체 참조에 대한 권한 검증(IDOR 방지), 예측 불가능한 식별자.
- **관리자 페이지**: 인터넷 노출 차단(IP 제한·VPN), `robots.txt` + `X-Robots-Tag: noindex`.
- **디렉터리 리스팅 비활성화**, 불필요 파일 삭제, 에러 페이지 커스터마이징.
- **검색엔진 노출 제거**: 색인된 개인정보는 삭제 + 검색엔진에 삭제 요청.
- **개발 단계 보안**(Secure SDLC): 설계 검토, 시큐어 코딩, SAST/DAST.

## 노출 사고 발생 시

- 즉시 해당 페이지·기능 차단, 노출 범위·기간 파악.
- 유출에 해당하면 **72시간 이내 통지·신고**(제34조).
- 원인(취약점) 제거, 재점검, 재발방지 대책.

## 함정 포인트

- URL 파라미터만 바꿔 타인 정보가 조회되면 = **취약한 접근제어(IDOR)** → 안전조치 위반.
- 관리자 페이지는 인터넷에 **노출·색인되면 안 된다**.
- 취약점은 발견에서 끝이 아니라 **조치 + 재점검**까지.
