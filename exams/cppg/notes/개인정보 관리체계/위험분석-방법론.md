> 2026-09 기준 · ISMS-P 1.2 + 위험관리 일반 이론(ISO 27005).

## 위험 = f(자산, 위협, 취약점, 영향)

- **자산(Asset)**: 개인정보·시스템·문서 등 보호 대상. 자산가치 산정(기밀성·무결성·가용성 + 법적 요구).
- **위협(Threat)**: 자산에 해를 끼칠 수 있는 잠재 원인(해킹, 내부자, 재해, 오류).
- **취약점(Vulnerability)**: 위협이 악용할 수 있는 약점(패치 미적용, 약한 인증).
- **영향(Impact)**: 사고 발생 시 손실(정보주체 피해, 과징금, 신뢰 손상).
- **위험도** = 발생 가능성 × 영향 (또는 자산가치 × 위협 × 취약점).

## 접근법 (ISO/TR 13335 · NIST)

| 방법 | 특징 | 장·단점 |
|---|---|---|
| **베이스라인 접근법** | 표준·체크리스트로 일괄 기본 통제 적용 | 빠름 / 조직 특성 반영 부족 |
| **비정형(전문가 판단) 접근법** | 경험 많은 전문가의 판단 | 신속 / 주관적, 일관성↓ |
| **상세 위험분석** | 자산·위협·취약점을 체계적으로 분석 | 정확 / 비용·시간 많이 듦 |
| **복합 접근법** | 고위험 영역은 상세, 나머지는 베이스라인 | 실무에서 가장 널리 사용 |

## 평가 방식

| | 정성적(Qualitative) | 정량적(Quantitative) |
|---|---|---|
| 척도 | 상/중/하, 1~5점 | 금액(원) |
| 대표 지표 | 위험 매트릭스(가능성×영향) | **SLE**(1회 손실=자산가치×노출계수 EF), **ARO**(연간 발생률), **ALE = SLE × ARO** |
| 장점 | 빠름, 이해 쉬움 | 비용편익 분석 가능 |
| 단점 | 비교·우선순위 모호 | 데이터 확보 어려움 |

- **위험 시나리오(Scenario) 분석**: "내부자가 대량 다운로드 후 유출" 같은 구체 시나리오별로 통제 점검.

## 절차

```
자산 식별·평가 → 위협·취약점 식별 → 위험 산정
→ 목표 위험수준(DoA) 대비 평가 → 위험 처리(감소·회피·전가·수용)
→ 보호대책 선정·이행 → 잔여위험 승인(경영진)
```

## 함정 포인트

- 실무 표준은 **복합 접근법**(고위험 상세 + 나머지 베이스라인).
- **ALE = SLE × ARO**, SLE = 자산가치 × EF(노출계수).
- 위험 처리 4방안: 감소·회피·전가·수용. 수용은 **경영진 승인** 필요.
- 정량적 = 금액, 정성적 = 등급.
