> 2026-09 기준 · ISMS-P 1.2(위험 관리) + 개인정보 영향평가 수행안내서.

## 왜 필요한가

- 위험 평가·영향평가의 **출발점**. 어떤 개인정보가 **어디서 수집 → 어떻게 저장·이용·제공 → 언제 파기**되는지 
  전 과정을 눈에 보이게 정리해야 통제 지점을 찾을 수 있다.

## 개인정보 흐름표 (표 형식)

업무별로 생명주기 단계마다 다음을 기재:

| 항목 | 내용 |
|---|---|
| 업무명 | 회원 가입, 상담, 배송, 마케팅 등 |
| 처리 단계 | 수집 / 보유·이용 / 제공 / 파기 |
| **개인정보 항목** | 성명, 연락처, 주민번호(근거), 민감정보 등 |
| 수집 경로·방법 | 웹폼, 지류, 제휴사(간접수집), API |
| 처리 목적 | 계약 이행, 법령 의무, 마케팅(선택) |
| 보유 근거·기간 | 동의/법령, 3년 등 |
| 취급자·부서 | 접근 권한자 |
| 저장 위치·시스템 | DB, 파일서버, 클라우드, 수기 문서 |
| 제공·위탁 여부 | 수탁자, 제공받는 자, 국외 이전 |
| 안전조치 | 암호화, 접근통제, 마스킹 |

## 개인정보 흐름도 (그림 형식)

- 정보주체 → 수집 채널 → 처리시스템 → 내부 이용부서 → 수탁자/제3자 → 파기
- 화살표에 **개인정보 항목·전송 방식(암호화 여부)** 표기.
- 시스템 경계(내부망/DMZ/외부), 국외 경계를 표시.

## 활용

- **누락·과다 수집** 발견(목적에 없는 항목 수집?)
- **불필요한 접근권한**·경로 식별
- **미흡한 안전조치** 지점(평문 전송, 마스킹 안 됨)
- 처리방침·위탁 공개·국외이전 고지의 **정합성 검증**
- 영향평가·정기 위험평가 시 갱신

## 함정 포인트

- 흐름표는 **생명주기 단계(수집→보유·이용→제공→파기)** 로 구성.
- 흐름 분석은 **위험 관리(Plan) 단계**의 필수 산출물이며, 환경 변화 시 갱신한다.
- 수기 문서·클라우드·간접수집 경로도 빠짐없이 포함.
