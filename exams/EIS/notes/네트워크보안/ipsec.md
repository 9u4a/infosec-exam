## 한 줄 정의

**IPSec** 은 3계층(IP)에서 인증·암호화를 제공하는 VPN 표준이다. 구성은 **보호 프로토콜(AH/ESP) × 동작 모드(전송/터널) × 키 교환(IKE)** 세 축이고, 시험은 각 축의 차이를 표로 묻는다. {{3-14}} {{4-11}} {{6-11}} {{12-2}} {{30-2}}

## 1. 보호 프로토콜 — AH vs ESP

| | **AH** (프로토콜 51) | **ESP** (프로토콜 50) |
|---|---|---|
| 무결성 · 인증 | O | O |
| **기밀성(암호화)** | **X** | **O** |
| 재전송 방지 | O (Sequence Number) | O (Sequence Number) |
| NAT 통과 | **불가** | 가능 (NAT-T) |

- **재전송 공격 방지** 필드 = AH/ESP 헤더의 **Sequence Number** {{30-2}}

> [!함정] AH 가 NAT 를 못 넘는 이유
> 인증 범위에 **IP 헤더(출발지·목적지 IP)** 가 포함돼, NAT 가 IP 를 바꾸면 무결성 검증이 실패한다. 구형 장비의 AH 문제는 IPSec 모듈을 업그레이드(NAT-T 지원)해 해결한다.

### IPSec 이 제공하는 보안 서비스 {{20-6}}

기밀성 · 데이터 근원지 인증 · 비연결형 무결성 · 재전송 방지(anti-replay) · 접근 제어 · **제한된 트래픽 흐름의 기밀성**(터널 모드)

## 2. 동작 모드 — 전송 vs 터널

| | 전송 (Transport) | 터널 (Tunnel) |
|---|---|---|
| 보호 대상 | IP **페이로드**(TCP 헤더 + 데이터) | **원본 IP 패킷 전체** |
| 새 IP 헤더 | 없음 | **추가됨** |
| 용도 | 호스트 ↔ 호스트 (End-to-End) | 게이트웨이 ↔ 게이트웨이 (VPN) |

### ESP 터널 모드 필드와 범위

```text
[새 IP 헤더][ESP 헤더][원본 IP 헤더][TCP 헤더][데이터][ESP 트레일러][ESP 인증]
             └────────── 암호화: ESP 헤더 다음 ~ 트레일러 ──────────┘
             └────────── 인증:  ESP 헤더 ~ 트레일러 (새 IP 헤더 제외) ──┘
```

## 3. 키 교환 — IKE (ISAKMP/Oakley, UDP 500)

2단계로 진행한다.

| 단계 | 목적 | 내용 |
|---|---|---|
| **Phase 1** | 양단 인증 + 안전한 **관리 채널**(ISAKMP SA) | **Main 모드**(6개 메시지, ID 보호) / **Aggressive 모드**(3개 메시지, 빠르지만 **ID 노출**). Diffie-Hellman 으로 공유 비밀 생성 |
| **Phase 2** | 실제 데이터용 **IPSec SA** 협상 | **Quick 모드**. AH/ESP·모드·알고리즘·수명 결정. PFS 옵션 시 DH 재수행 |

- **SA**: **단방향** 논리 연결 → 양방향 통신엔 SA 2개. **SPI** 로 식별
- **SAD**: 각 SA 의 파라미터 DB
- **SPD**: "어떤 트래픽에 IPSec 을 **적용 / 우회 / 폐기**할지" 정책 DB

## 4. VPN 터널링 프로토콜 계층 {{11-3}} {{15-10}}

| 프로토콜 | 계층 | 특징 |
|---|---|---|
| **L2F** | 2 | Cisco. 인증만, 암호화 없음 |
| **PPTP** | 2 | MS·3Com. GRE + PPP, 구현 쉬움, 보안 약함 (MS-CHAPv2 취약) |
| **L2TP** | 2 | L2F + PPTP 결합. 자체 암호화 없음 → 보통 **L2TP/IPSec** |
| **IPSec** | 3 | IETF 표준. AH/ESP 로 인증·암호화, 사이트 간 VPN 주력 |
| **SSL/TLS VPN** | 4~7 | 브라우저만으로 접속(Clientless), 사용자 단위 접근제어 |

11-3 빈칸 정답: (A) IPSec · (B) AH · (C) ESP. 2계층 터널링은 비-IP 프로토콜도 캡슐화하지만 자체 보안이 약해 IPSec 과 결합한다.

## 기출 포인트

> [!암기] 서술형 3줄 답안
> - **AH vs ESP**: 둘 다 무결성·인증·재전송 방지, **기밀성은 ESP 만**. AH 는 IP 헤더까지 인증해 **NAT 를 못 지난다**. 실무는 대부분 ESP.
> - **전송 vs 터널**: 전송은 페이로드만(호스트 간), 터널은 **원본 패킷 전체 암호화 + 새 IP 헤더**(게이트웨이 간 VPN).
> - **IKE**: Phase 1 에서 상호 인증·관리채널(ISAKMP SA), Phase 2 에서 실제 트래픽용 IPSec SA 협상.
