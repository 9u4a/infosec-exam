## 한 줄 정의

**VPC**(Virtual Private Cloud)는 퍼블릭 클라우드 안에 만드는 **논리적으로 격리된 가상 네트워크**다. 그 안을 **서브넷**으로 나누고, **라우팅 테이블**로 길을 정하고, **Security Group(인스턴스 단위)** 과 **NACL(서브넷 단위)** 로 트래픽을 통제한다. AWS 는 SG 를 **주 통제**, NACL 을 **보조 통제**로 권장한다.

## 구성 요소

| 구성 요소 | 역할 |
|---|---|
| **VPC** | 계정 전용 가상 네트워크, CIDR 대역(예 `10.0.0.0/16`) |
| **서브넷** | VPC 대역을 쪼갠 구간, **가용 영역(AZ) 하나에만** 속함 |
| **인터넷 게이트웨이(IGW)** | VPC ↔ 인터넷 양방향, IPv4 는 1:1 NAT 수행 |
| **NAT 게이트웨이** | 프라이빗 → 외부 **연결 개시만** 허용, 외부에서 먼저 접속 불가 |
| **라우팅 테이블** | 목적지 → 대상(IGW·NAT·피어링), 미지정 서브넷은 main 테이블 |
| **VPC 피어링 / Transit Gateway** | VPC 간 사설 연결 / 리전 가상 라우터(허브) |
| **VPC 엔드포인트** | 인터넷·NAT 없이 AWS 서비스에 사설 접근 (아래 절) |
| **VPN · 전용선** | 온프레미스 ↔ VPC (Site-to-Site VPN, Direct Connect) |

- IGW 를 쓰려면 인스턴스에 **공인 IP 또는 EIP** 가 있어야 한다
- 프라이빗 서브넷 인스턴스는 공인 IP 가 있어도 IGW 경로가 없으면 인터넷 불가
- Public NAT GW 는 **퍼블릭 서브넷**에 두고 **EIP** 를 붙인다(Private NAT 유형도 있음)
- IPv6 아웃바운드 전용은 **egress-only 인터넷 게이트웨이**

| 서브넷 유형 | 라우팅 | 배치 예 |
|---|---|---|
| **퍼블릭** | IGW 로 가는 직접 경로(`0.0.0.0/0 → IGW`) | 로드밸런서·Bastion·NAT GW |
| **프라이빗** | IGW 직접 경로 없음, 외부는 NAT 경유 | WAS·DB |
| **VPN 전용** | VGW 경유 VPN 경로만 | 사내 연동 서버 |
| **격리(Isolated)** | VPC 밖 경로 **전혀 없음** | 내부 전용 DB |

> [!팁] 온프레미스 DMZ 와 같은 발상
> 외부에 노출할 것만 퍼블릭 서브넷(DMZ), 나머지는 프라이빗 서브넷(내부망)에 둔다. 서브넷 유형은 **라우팅으로 결정**된다.

## Security Group vs NACL

| 구분 | **Security Group** | **NACL** (Network ACL) |
|---|---|---|
| 적용 단위 | **인스턴스(ENI)** | **서브넷** (서브넷당 NACL 1개) |
| 상태 | **Stateful** — 응답 트래픽 자동 허용 | **Stateless** — 응답도 규칙 필요 |
| 규칙 | **허용(Allow)만** | **허용 + 거부(Deny)** |
| 평가 | **모든 규칙을 종합** 평가 | **번호 낮은 순**, 첫 일치 규칙만 적용 |
| 규칙 번호 | 없음 | 1~32766, 마지막 `*` 거부(삭제 불가) |
| 출처 지정 | IP·CIDR · prefix list · **다른 SG ID** | IP·CIDR |

### 기본값 (자주 틀리는 부분)

| 대상 | 인바운드 | 아웃바운드 |
|---|---|---|
| **새로 만든 SG** | 규칙 없음 → 전부 거부 | 전체 허용 규칙 1개 |
| **기본(default) SG** | **같은 SG 소속끼리** 전체 허용 | 전체 허용 |
| **기본(default) NACL** | 전체 허용(규칙 100, IPv6 101) | 전체 허용(규칙 100, IPv6 101) |
| **사용자 생성 NACL** | **전부 거부** | **전부 거부** |

- 인스턴스 시작 시 SG 를 지정하지 않으면 VPC 의 **default SG** 에 붙는다
- 사용자 생성 NACL 은 서브넷에 자동 연결되지 않는다 — 명시적으로 연결

> [!함정] Stateless 의 임시 포트
> NACL 은 응답을 기억하지 않는다. 인바운드 80 을 열어도 응답이 나가는 **아웃바운드 임시 포트**를 따로 열어야 한다. 범위는 **클라이언트 OS** 가 정한다.

| 클라이언트 | 임시 포트 |
|---|---|
| 리눅스 커널 다수(Amazon Linux 포함) | 32768-61000 |
| Windows Server 2008 이후 | 49152-65535 |
| Windows Server 2003 까지 | 1025-5000 |
| ELB · NAT GW · Lambda | 1024-65535 |

- AWS 예시 NACL 은 32768-65535 를 쓴다
- 다양한 클라이언트를 받으려면 **1024-65535** 를 열 수 있다(AWS 설명)
- 그 범위 안 악성 포트 거부는 넓은 허용 규칙보다 **앞 번호**에 둔다
- VPC 인스턴스가 클라이언트면 반대로 **인바운드**에 임시 포트를 연다

> [!함정] 특정 IP 차단은 NACL — 단, 못 막는 것도 있다
> Security Group 에는 **거부 규칙이 없다**. 공격 IP 를 명시적으로 막으려면 NACL(또는 WAF). 그러나 SG·NACL 모두 **Amazon DNS·DHCP·인스턴스 메타데이터(IMDS)·Time Sync** 트래픽은 필터링하지 않는다.

### Azure · GCP 대응 개념

| 항목 | Azure NSG | GCP VPC 방화벽 규칙 |
|---|---|---|
| 상태 | **Stateful** (flow record) | **Stateful** |
| 동작 | 허용 + 거부 | 허용 + 거부 |
| 우선순위 | 100~4096, 낮은 숫자 우선, 첫 일치 | 0~65535(기본 1000), 낮은 숫자 우선 |
| 기본 규칙 | VNet·LB 허용, 65500 DenyAll(삭제 불가) | 묵시적 egress 허용 · ingress 거부 |
| 적용 | 서브넷 또는 NIC | VPC 네트워크에 정의, 인스턴스 단위 적용 |

- 둘 다 **상태 저장이면서 거부·우선순위를 지원** → AWS SG·NACL 어느 쪽과도 같지 않다

## VPC 엔드포인트 유형

| 구분 | **Gateway 엔드포인트** | **Interface 엔드포인트** |
|---|---|---|
| 대상 | **S3 · DynamoDB** 만 | 다양한 AWS·파트너 서비스 |
| 방식 | 라우팅 테이블에 경로 추가 | 서브넷에 **ENI** 생성, DNS 로 해석 |
| PrivateLink | **사용 안 함** | 사용 |

> [!함정] 엔드포인트 기본 정책은 "전부 허용"
> 기본 VPC 엔드포인트 정책은 모든 주체·모든 작업·모든 리소스를 허용한다. 데이터 유출 경로가 되지 않게 **엔드포인트 정책으로 범위를 좁힌다**.

## 3계층 웹 서비스 구성 예

| 계층 | 서브넷 | 보안 그룹 인바운드 |
|---|---|---|
| ALB | 퍼블릭 | 443 ← `0.0.0.0/0` |
| WAS | 프라이빗 | 8080 ← **ALB 보안 그룹** |
| DB | 프라이빗 | 3306 ← **WAS 보안 그룹** |
| Bastion | 퍼블릭 | 22 ← **관리자 IP 만** |

- 보안 그룹끼리 참조하면 IP 가 바뀌어도 규칙이 유지된다(AWS 공식 예와 같은 구조)
- 22·3389 은 특정 IP 대역만, 넓은 포트 범위 개방 금지(AWS 모범사례)
- Bastion 대신 세션 관리 서비스(SSM Session Manager 등)로 22번을 닫는 방식도 쓰인다

## 위협과 대응

| 위협 | 대응 |
|---|---|
| 보안 그룹 `0.0.0.0/0` 으로 22·3389·DB 포트 개방 | 관리 포트는 관리자 IP·Bastion 만, **CSPM** 상시 점검 |
| DB 를 퍼블릭 서브넷에 배치 | 프라이빗(또는 격리) 서브넷 + 퍼블릭 IP 미할당 |
| 서비스 데이터가 인터넷 경유 | **VPC 엔드포인트**로 사설 경로 + 엔드포인트 정책 |
| 이상 트래픽 가시성 부족 | **VPC Flow Logs** 수집 → SIEM 분석 |
| VPC 간 과도한 신뢰 | 피어링·Transit 라우팅 최소화, 세그먼트별 분리 |

### VPC Flow Logs

- 생성 단위: **VPC · 서브넷 · 네트워크 인터페이스(ENI)**
- 수집 유형: 허용(ACCEPT) · 거부(REJECT) · 전체(ALL)
- 전송 대상: CloudWatch Logs · S3 · Data Firehose
- 트래픽 경로 밖에서 수집 → 네트워크 성능에 영향 없음

> [!함정] Flow Logs 에 안 남는 트래픽
> **실시간 스트림이 아니다.** 또 Amazon DNS 서버 질의, `169.254.169.254` 메타데이터, DHCP, ARP, Windows 라이선스 활성화 트래픽은 **기록되지 않는다**.
