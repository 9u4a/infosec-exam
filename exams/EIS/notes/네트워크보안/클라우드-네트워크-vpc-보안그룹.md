## 한 줄 정의

**VPC**(Virtual Private Cloud)는 퍼블릭 클라우드 안에 만드는 **논리적으로 격리된 사설 네트워크**다. 그 안을 **서브넷**으로 나누고, **라우팅 테이블**로 길을 정하고, **Security Group(인스턴스 단위)** 과 **NACL(서브넷 단위)** 두 겹의 방화벽으로 트래픽을 통제한다.

## 구성 요소

| 구성 요소 | 역할 |
|---|---|
| **VPC** | 사설 IP 대역(CIDR, 예 `10.0.0.0/16`)을 가진 격리 네트워크 |
| **서브넷** | VPC 대역을 쪼갠 구간, 가용 영역(AZ) 하나에 속함 |
| **인터넷 게이트웨이(IGW)** | VPC ↔ 인터넷 양방향 연결 |
| **NAT 게이트웨이** | 프라이빗 서브넷의 **아웃바운드만** 허용 (외부에서 먼저 접속 불가) |
| **라우팅 테이블** | 서브넷별 목적지 → 경로(IGW·NAT·피어링) 지정 |
| **VPC 피어링 / Transit Gateway** | VPC 간 사설 연결 / 다수 VPC·온프레미스 허브 |
| **VPC 엔드포인트** | 인터넷을 거치지 않고 클라우드 서비스(S3 등)에 사설 접근 |
| **VPN · 전용선** | 온프레미스 ↔ VPC 연결 (Site-to-Site VPN, Direct Connect) |

| 서브넷 | 라우팅 | 배치 예 |
|---|---|---|
| **퍼블릭** | `0.0.0.0/0 → IGW` | 로드밸런서·Bastion·NAT GW |
| **프라이빗** | `0.0.0.0/0 → NAT GW` (또는 없음) | WAS·DB |

> [!팁] 온프레미스 DMZ 와 같은 발상
> 외부에 노출할 것만 퍼블릭 서브넷(DMZ), 나머지는 프라이빗 서브넷(내부망)에 둔다.

## Security Group vs NACL

| 구분 | **Security Group** | **NACL** (Network ACL) |
|---|---|---|
| 적용 단위 | **인스턴스(ENI)** | **서브넷** |
| 상태 | **Stateful** — 허용한 요청의 응답은 자동 허용 | **Stateless** — 응답 트래픽도 규칙 필요 |
| 규칙 | **허용(Allow)만** | **허용 + 거부(Deny)** |
| 평가 | **모든 규칙을 종합** 평가 | **번호 낮은 순**으로 처음 일치 규칙 적용 |
| 기본값 | 인바운드 전부 거부, 아웃바운드 전부 허용 | 기본 NACL 은 전부 허용 |
| 출처 지정 | IP 대역 또는 **다른 보안 그룹 ID** | IP 대역만 |

> [!함정] Stateless 의 임시 포트
> NACL 은 응답을 기억하지 않는다. 인바운드 80 을 열어도 응답이 나가는 **아웃바운드 임시 포트(1024~65535)** 를 따로 열어야 통신된다.

> [!함정] 특정 IP 차단은 NACL
> Security Group 에는 **거부 규칙이 없다**. 공격 IP 를 명시적으로 막으려면 NACL(또는 WAF)을 쓴다.

## 3계층 웹 서비스 구성 예

| 계층 | 서브넷 | 보안 그룹 인바운드 |
|---|---|---|
| ALB | 퍼블릭 | 443 ← `0.0.0.0/0` |
| WAS | 프라이빗 | 8080 ← **ALB 보안 그룹** |
| DB | 프라이빗 | 3306 ← **WAS 보안 그룹** |
| Bastion | 퍼블릭 | 22 ← **관리자 IP 만** |

- 보안 그룹끼리 참조하면 IP 가 바뀌어도 규칙이 유지된다
- Bastion 대신 **세션 관리 서비스**(SSM Session Manager 등)로 22번 포트 자체를 닫는 방식이 권장된다

## 위협과 대응

| 위협 | 대응 |
|---|---|
| 보안 그룹 `0.0.0.0/0` 으로 22·3389·DB 포트 개방 | 관리 포트는 관리자 IP·Bastion 만, **CSPM** 으로 상시 점검 |
| DB 를 퍼블릭 서브넷에 배치 | 프라이빗 서브넷 + 퍼블릭 IP 미할당 |
| 서비스 데이터가 인터넷 경유 | **VPC 엔드포인트**로 사설 경로 |
| 이상 트래픽 가시성 부족 | **VPC Flow Logs** 수집 → SIEM 분석 |
| VPC 간 과도한 신뢰 | 피어링·Transit 라우팅 최소화, 세그먼트별 분리 |
