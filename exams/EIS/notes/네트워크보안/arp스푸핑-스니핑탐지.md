## 한 줄 정의

**ARP 스푸핑**은 인증 없는 ARP 의 약점을 이용해 트래픽을 공격자 쪽으로 돌려 **MITM(중간자)** 이 되는 공격이고, **스니핑**은 그렇게 흘러온 패킷을 몰래 읽는 행위다. 시험은 "공격 절차 → 탐지 지표 → 탐지 기법 → 대응" 순으로 묻는다. {{1-16}} {{25-17}}

## ARP 기본 동작

| 구분 | 방식 | 목적지 MAC |
|---|---|---|
| ARP Request | **브로드캐스트** (MAC 을 모르므로) | `ff:ff:ff:ff:ff:ff` |
| ARP Reply | 요청자에게 **유니캐스트** | 요청자 MAC |
| RARP | 반대로 MAC → IP (디스크리스 부팅) | 지금은 BOOTP/DHCP 로 대체 |

## 공격 흐름 — ARP 스푸핑

**원리:** ARP 는 인증이 없어, 위조된 Reply(gratuitous ARP)도 캐시에 그대로 반영된다.

1. 피해자에게 "게이트웨이 IP = **공격자 MAC**" 이라는 위조 Reply 를 반복 전송
2. 게이트웨이에게 "피해자 IP = **공격자 MAC**" 이라는 위조 Reply 전송 → 양방향 가로채기
3. 공격자가 **IP 포워딩**을 켜서 트래픽을 그대로 중계 (피해자가 눈치 못 챔)
   - `echo 1 > /proc/sys/net/ipv4/ip_forward`
4. 이후 스니핑 · SSL stripping · 세션 쿠키 탈취

> [!시험] 판단 근거 (로그·ARP 테이블 문제)
> - **서로 다른 IP 가 같은 MAC** 을 가짐 → 그 MAC 의 호스트가 공격자
> - 게이트웨이 IP 의 MAC 이 **관리자가 아는 실제 MAC 과 다름**
> - 위조 Reply 를 **수 초 간격으로 계속** 보내므로 ARP 트래픽 폭증도 지표 (ARP 캐시가 만료되기 때문)

### 대응

- 정적 ARP 등록: `arp -s <게이트웨이IP> <실제MAC>` (재부팅하면 초기화됨)
- 스위치 **DAI**(Dynamic ARP Inspection) + **DHCP Snooping**
- 종단 암호화(SSH · HTTPS)로 가로채도 못 읽게
- ARP watch 류 도구로 MAC 변경 감시

## 세션 하이재킹

이미 **인증을 끝낸 세션**을 가로채 사용자 행세를 한다. {{19-10}} {{25-4}}

| 유형 | 수법 |
|---|---|
| TCP | 스니핑으로 SEQ/ACK 파악 → 위조 패킷 주입 (정상 클라이언트는 **ACK Storm**) |
| 웹 | 스니핑한 **세션 쿠키·토큰** 재사용 |

대응: 구간 암호화 · 세션 타임아웃 / 재인증 · 쿠키 `Secure`·`HttpOnly` · **로그인 후 세션 ID 재발급**

## 스니핑 탐지

### Promiscuous 모드 확인

- 로그 `device eth0 entered Promiscuous mode` (`/var/log/messages`)
- 의미: NIC 가 자기 것이 아닌 프레임도 전부 수신 = **스니핑 도구 설치 정황**
- 해제: `ifconfig eth0 -promisc` 또는 `ip link set eth0 promisc off`

### 탐지 기법 5가지

| 기법 | 방법 | 판단 |
|---|---|---|
| **Ping** | IP 는 맞고 **없는 MAC** 으로 ICMP Echo | 응답하면 스니퍼 |
| **ARP** | 위조 MAC 으로 ARP 요청 | 응답하면 스니퍼 |
| **DNS** | 스니퍼의 역방향 조회 관찰 | 조회 발생하면 스니퍼 |
| **Decoy** | 가짜 계정을 평문으로 흘림 | 그 계정 사용 시도 |
| **Latency** | 대량 트래픽 유발 | 응답 지연 증가 |

> [!팁] 왜 Ping·ARP 탐지가 통하나
> 정상 NIC 는 자기 MAC·브로드캐스트가 아닌 프레임을 **하드웨어에서 폐기**한다. promiscuous NIC 는 전부 커널로 올린다. 그래서 "MAC 은 틀리고 IP 는 맞는" 위조 프레임에 **답이 오면 폐기하지 않았다 = 스니핑 중**. DNS·Decoy 는 반대로 스니퍼가 **잡은 내용에 반응**하는지를 본다.

## 스니핑 전반 대응

- 허브 금지, **스위치 + 포트 보안**
- SSH · HTTPS · IPSec 등 **암호화 통신**
- MAC Flooding(Switch Jamming) 대비 → **포트당 MAC 수 제한**

## 기출 포인트

> [!암기] 서술형 3줄 답안
> - **ARP 스푸핑**: ARP 의 무인증을 악용해 위조 Reply 로 캐시를 오염시켜 트래픽을 공격자 경유로 만드는 **MITM**. 대응은 **정적 ARP · DAI + DHCP Snooping · 종단 암호화**.
> - **스니핑 탐지**: 정상 NIC 가 폐기할 위조 프레임에 응답하는지로 promiscuous 여부 판별 — Ping · ARP · DNS · Decoy · Latency.
> - 근본 대응은 **포트 보안 + 전 구간 암호화**. 스니핑에 성공해도 평문이 안 보이게 한다.
