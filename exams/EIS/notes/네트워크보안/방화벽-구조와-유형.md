## 한 줄 정의

방화벽은 **어느 계층까지 보느냐(유형)** 와 **어떻게 배치하느냐(아키텍처)** 로 나뉜다. 기출엔 조각으로만 나왔지만 정보보안기사 단골 범위라 체계로 정리해 둔다.

## 유형 — 동작 계층별

| 유형 | 계층 | 방식 | 장점 | 단점 |
|---|---|---|---|---|
| **패킷 필터링** | 3~4 | IP·포트·플래그로 정적 허용/차단 | 빠름·저비용·투명 | 상태 추적 불가, 세션 스푸핑·단편화 취약, 로깅 빈약 |
| **스테이트풀 인스펙션** | 3~4 + 세션 | 연결 상태 테이블 유지, 응답 패킷만 허용 | 패킷 필터 + 세션 추적, 성능 양호 | 애플리케이션 계층 공격은 못 막음 |
| **애플리케이션 게이트웨이** (프록시) | 7 | 서비스별 프록시가 연결을 대리, 페이로드 검사 | 강력한 인증·로깅·콘텐츠 필터 | 느림, 서비스별 프록시 필요 |
| **서킷 게이트웨이** | 5 (세션) | SOCKS 등 세션 단위 중계 (내용 검사 X) | 내부 IP 은닉, 범용 | 앱 검사 없음, 클라이언트 수정 필요 |
| **하이브리드** | 혼합 | 위 방식 조합 | 균형 | 복잡·고가 |
| **NGFW** | 3~7 | 앱 인식 + 사용자 인식 + IPS + TLS 검사 | 통합 가시성 | 성능 부하·고가 |

- **UTM**: 방화벽 + IPS + 안티바이러스 + VPN + 웹필터를 한 장비로 (중소 규모)
- **WAF**: 웹 애플리케이션 전용(7계층), SQLi·XSS 방어 — 범용 방화벽과 별개

## 정책 원칙

- **화이트리스트** — 기본 전부 차단(Deny All), 필요한 것만 명시 허용
- 최소 규칙 · 규칙 순서 최적화 (자주 매칭되는 것을 위로) · 마지막은 `deny any + log`
- **송신(egress) 필터링**도 설정 — 내부 → 외부 비인가 트래픽(C2·데이터 유출) 차단
- 규칙 정기 검토, 불필요·중복·shadow 규칙 제거

## 구축 아키텍처

세 가지를 *안전한 순서*로 외운다: **스크리닝 라우터 < 스크린드 호스트 < 스크린드 서브넷**

### 베스천 호스트

내부망과 외부망 사이의 **요새 호스트**다. 강하게 하드닝하고 불필요 서비스를 제거하며 로깅을 집중한다. 공격의 1차 표적이므로 침해돼도 피해가 최소화되게 설계한다.

### 스크리닝 라우터

경계 라우터에서 ACL 로 1차 패킷 필터링을 한다. **단독으로는 취약**하다.

### 스크린드 호스트

```text
인터넷 ─ 스크리닝 라우터 ─ 베스천 호스트 ─ 내부망
```

- 라우터(패킷 필터) + 베스천(프록시) **2단계 방어**
- 라우터가 뚫리면 내부망이 직접 노출될 위험 (단일 홈드)
- **듀얼 홈드 호스트**: NIC 2개인 베스천이 유일한 통로이고 라우팅을 꺼서 **반드시 프록시를 경유**

### 스크린드 서브넷 (DMZ)

```text
인터넷 ─ 외부 라우터 ─ [ DMZ: 웹·메일·DNS ] ─ 내부 라우터 ─ 내부망
```

- 외부·내부 라우터 사이에 **완충 지대(DMZ)**
- 외부 접근이 필요한 공개 서버는 DMZ 에, 내부망은 따로 보호
- **가장 안전** — 외부 라우터가 침해돼도 내부 라우터가 방어
- 대신 **비용·관리 복잡도가 최고**

## 방화벽의 한계

내부자 위협 · 백도어·터널링(HTTPS·DNS 터널) · 암호화 트래픽 미검사 · 무선 AP·모뎀 우회 · 애플리케이션 취약점

→ IDS/IPS · 엔드포인트 · NAC · 로그 분석과 **다계층으로 병행**한다.
