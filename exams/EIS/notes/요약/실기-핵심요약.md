> 📌 개인 학습 요약을 다듬어 등록한 참고 노트. 특정 기출 문항에 매이지 않는 5개 영역
> 공통 정리이며, 세부 내용·기출 연결은 각 카테고리의 개별 노트를 함께 참고한다.

## 0. 공통 용어

| 용어 | 설명 |
|---|---|
| **CVE** | Common Vulnerabilities and Exposures. 공개된 보안 취약점의 공통 식별자. 표기 `CVE-[연도]-[일련번호]`. 미국 비영리기관 **MITRE**가 관리 |
| **CWE** | Common Weakness Enumeration. 소스코드 수준의 취약점 **유형** 분류(예: SQL 인젝션 자체). CVE는 "이 제품의 이 취약점", CWE는 "결함의 종류" |
| **CVSS** | Common Vulnerability Scoring System. 취약점 심각도를 0~10점으로 채점. **FIRST**가 개발·관리, 실제 점수 조회는 **NIST 산하 NVD** |

- CVE는 해커·보안업체마다 다르게 부르던 명칭을 표준화한 목록이며, 호환성 시험을 거친 보안 제품·서비스만 CNA(번호 발급 기관)로 참여할 수 있다.

### 사이버 킬체인 · ATT&CK · APT

| 용어 | 설명 |
|---|---|
| **사이버 킬체인** | APT 대비를 위해 **록히드마틴**이 제시한 공격 단계 모델. 한 단계만 끊어도 공격을 무력화할 수 있다는 것이 핵심 |
| **MITRE ATT&CK** | Adversarial Tactics, Techniques, and Common Knowledge. MITRE가 실제 공격 사례로 킬체인을 더 세분화한 전술·기법 프레임워크 |
| **APT** | Advanced Persistent Threat(지능형 지속 위협). 특정 대상을 겨냥해 다양한 기법으로 장기간 지속 공격 |
| **YARA** | 바이러스토탈(VirusTotal) 제작 도구. 악성코드의 특성·행위 패턴으로 악성코드를 분류 |

**사이버 킬체인 7단계**

정찰 → 무기화 → 전달 → 공격(익스플로잇) → 설치 → 명령 및 제어(C2) → 목표 장악

### 악성 소프트웨어(멀웨어)

| 유형 | 특징 |
|---|---|
| 바이러스 | 감염된 파일 실행 등 **사용자 상호작용**으로 확산, 시스템 손상·제어 |
| 웜 | 사용자 개입 없이 네트워크로 **자가 복제** 확산 → 네트워크 정체·시스템 충돌 |
| 트로이 목마 | 무해한 프로그램으로 위장, 자가 복제는 없음 → 백도어 생성·정보 탈취 |
| 멀버타이징(Malvertising) | 합법 온라인 광고에 악성코드를 삽입하거나 클릭을 유도하는 가짜 광고 |

### 기타 공통 용어

| 용어 | 설명 |
|---|---|
| **MITM** | 두 당사자 간 통신을 가로채 도청·조작. 대응: SSL/TLS 암호화, HTTPS, SW 최신화, 공용 Wi-Fi 회피 |
| **TMS** | Threat Management System. 전사 위협정보 수집·분석·경보 통합 관리 — 최근 EDR 등에 밀려 단독 제품군은 거의 남지 않음 |
| **정적 분석** | 실행하지 않고 소스코드 자체의 잠재적 취약점을 분석 |
| **동적 분석** | 공격자처럼 실제로 실행해 결과를 관찰 |
| **공급망 공격** | SW 빌드·배포 과정에 악성코드를 삽입해 정상 업데이트를 통해 이용자를 공격 |

**클라우드**

- 배포 형태: 퍼블릭 / 프라이빗 / 하이브리드 클라우드
- 서비스 형태: **IaaS**(인프라 제공) · **PaaS**(플랫폼·환경 제공) · **SaaS**(완성된 SW 제공)

## 1. 시스템 보안

### Linux 디렉터리 · 권한

- `/proc` — 현재 실행 중인 프로세스 정보를 담는 가상 파일시스템
- 권한 값: r=4(읽기) w=2(쓰기) x=1(실행)

**특수 권한**

| 권한 | 의미 |
|---|---|
| **SUID** | 실행 중 해당 파일 **소유자** 권한으로 인식 |
| **SGID** | 실행 중 해당 파일 **소유 그룹** 권한으로 인식 |
| **Sticky Bit** | 디렉터리 전용. 누구나 파일 생성·수정·읽기 가능하지만 **삭제는 소유자·root만** 가능 |

**접근권한 표기 읽기**

| 표기 | 해석 |
|---|---|
| `-r-sr-xr-x root sys /etc/chk/passwd` | 소유자 실행자리 `s` → **SUID**. 일반 사용자가 실행해도 **root** 권한으로 동작 |
| `-r-xr-sr-x root mail /etc/chk/mail` | 그룹 실행자리 `s` → **SGID**. 실행해도 **mail 그룹** 권한으로 동작 |
| `drwxrwxrwt sys sys /tmp` | 모두 읽기·쓰기·실행 가능 + 기타 실행자리 `t` → **Sticky Bit**. 소유자·root 외엔 삭제 불가 |

### 계정 파일

**`/etc/passwd`**

```
계정명 : 비밀번호 : UID : GID : 주석 : 홈디렉터리 : 쉘
```

사용자 계정 식별 정보를 담는다.

**`/etc/shadow`**

```
계정명 : 비밀번호 : 마지막변경일 : 최소사용일 : 최대사용일 : 만료경고일 : 유예기간 : 만료일
```

암호화된 패스워드와 정책 정보를 담는다. `pwconv`(passwd→shadow 전환) / `pwunconv`(원복)로 활성화·비활성화한다.

두 번째 필드(예 `$6$CWA90qcuqNsVFrEw$NvfCN4S1iJH...`) 구조:

| 항 | 값 예시 | 의미 |
|---|---|---|
| 1항 | `$6$` | 해시 알고리즘 — `$1$`=MD5, `$5$`=SHA-256, **`$6$`=SHA-512** |
| 2항 | `CWA90qcuqNsVFrEw` | Salt 값 |
| 3항 | `NvfCN4S1iJHbRfgDGrzaFGOxVJ0jv0` | 암호화된 비밀번호 |

**특수 표기**

| 표기 | 의미 |
|---|---|
| `!` , `!!` | 비밀번호 미설정 상태로 계정 잠금 |
| `*` | 이 계정으로 로그인 자체 불가 |
| 빈 값 | 비밀번호 없이 로그인 가능한 위험 상태 |

**`/etc/login.defs`** — 로그인 시 적용되는 기본 정책 파일. 최소·최대 비밀번호 길이, 만료 정책, 계정 잠금 정책을 담는다.

> 💡 비밀번호 정책을 **설정**하는 파일은 `login.defs`, `shadow`는 그 정책이 적용된 결과(각 계정의 값)를 **확인**하는 파일로 구분해 기억한다.

### 로그 파일

| 로그 | 내용 | 조회 명령 |
|---|---|---|
| **utmp** | 현재 로그인한 사용자 상태 | `who` |
| **wtmp** | 로그인/로그아웃 + 시스템 boot/shutdown 이력 | `last` |
| **btmp** | 로그인 **실패** 정보 | `lastb` |
| **lastlog** | 계정별 마지막 로그인 성공 정보 | `lastlog` |

### logrotate.conf

로그 파일이 계속 커지는 것을 막기 위한 순환·관리 설정.

| 옵션 | 의미 |
|---|---|
| `rotate [N]` | 로그 파일이 N개 이상이면 오래된 것부터 삭제 |
| `maxage [N]` | 로그 파일이 N일 이상 지나면 삭제 |
| `size [N]` | 지정 용량보다 크면 rotate 수행 |
| `create [권한] [유저] [그룹]` | rotate된 로그파일의 권한·소유자 지정(예 `create 644 root root`) |
| `compress` | rotate된 로그파일 압축 |
| `dateext` | 백업 파일명에 날짜 삽입 |
| `monthly` / `weekly` / `daily` | rotate 주기 |

### 기타 명령어

```bash
umask 022          # 새 파일 기본 권한 666 - 022 = 644
chmod 400 test.txt  # 파일 허가권 변경
chown redstone test.txt  # 파일 소유자 변경

# PAM 계정 잠금(pam_tally) 옵션
# deny=5           5회 실패 시 계정 잠금
# unlock_time=120  120초 후 잠금 해제
# no_magic_root    root 계정은 잠금 예외
# reset            로그인 성공 시 실패 횟수 초기화

find / -mtime -7                 # 최근 7일 이내 변경된 파일
find / -user root -perm -4000    # 소유자 root + SUID 설정된 파일

strace -e trace=open ps | more   # 프로세스의 시스템 콜·시그널 추적
history                          # 입력했던 명령어(파라미터 포함) 이력 조회
```

### Windows — BitLocker

Windows 전용 볼륨(드라이브) 암호화 기능. **TPM**(신뢰할 수 있는 플랫폼 모듈)을 사용하며 AES 알고리즘으로 암호화한다.

### 익스플로잇 코드 (버퍼 오버플로우)

| 용어 | 설명 |
|---|---|
| **Shell Code** | 어셈블리어/기계어로 작성된 익스플로잇 본체 프로그램 |
| **`0x90`** | NOP(No Operation)에 해당하는 x86 헥스 코드 — NOP Sled로 활용 |
| **RET / EIP / ESP** | 스택 복귀 주소(RET, EIP에 저장)를 조작해 ESP(스택 포인터)가 가리키는 위치(셸코드)로 실행 흐름을 옮기는 것이 공격 핵심 |

### 데이터베이스 보안 (개요)

| 공격 | 설명 |
|---|---|
| **집성(Aggregation)** | 낮은 등급 정보 조각들을 조합해 높은 등급 정보를 알아냄 |
| **추론(Inference)** | 기밀이 아닌 정보로부터 기밀 정보(비밀번호 등)를 유추 |
| **데이터 디들링** | 입·출력값을 위변조해 잘못된 결과를 유도 |

**통제 수단**: 접근통제(인증·권한에 따른 접근 허용) · 추론통제(질의 길이 제한 등으로 추론 차단) · 흐름통제(높은 등급 → 낮은 등급 정보 흐름 제어). 상세는 애플리케이션 보안 절 참고.

## 2. 네트워크 보안

### IPSec (IP Security)

네트워크 계층에서 IP 패킷을 암호화·인증해 안전한 통신 채널을 제공하는 프로토콜.

| 모드 | 대상 | 보호 범위 |
|---|---|---|
| **전송 모드**(Transport) | 종단 간(호스트-호스트) | payload만 보호. 전송 계층 데이터가 IPSec을 거쳐 IPSec 헤더가 붙고, 이를 payload 취급해 IP 헤더가 붙음 |
| **터널 모드**(Tunnel) | 라우터-라우터, 호스트-라우터 등 | IP 헤더 포함 **IP 계층 전체** 보호. 원본 IP 헤더까지 payload 취급, IPSec 헤더 + **새 IP 헤더** 추가 |

**두 가지 보안 프로토콜**

| 프로토콜 | 제공 기능 |
|---|---|
| **AH**(Authentication Header) | 발신지 인증 + 무결성. **암호화(기밀성)는 제공하지 않음** |
| **ESP**(Encapsulating Security Payload) | 인증·무결성·**기밀성** 모두 제공 |

**구성요소**

| 구성요소 | 역할 |
|---|---|
| SA | 두 IPSec 장치 간 통신을 보호하는 보안 매개변수 집합(단방향) |
| IKE | 키 관리 프로토콜, UDP 500 포트 |
| SPD | 보안 정책 데이터베이스 — 보호할 트래픽과 방법 결정 |

> 🔑 **기능 암기 — [기무인재접]**
> 기밀성(ESP, 대칭키 암호화) · 무결성(AH, 메시지 인증 코드 MAC) · 인증(AH, 정상 사용자 송신 보장) · 재전송 공격 방지(보안 연관 순서번호) · 접근제어(보안정책 — 패킷 허용·폐기)

**전송 필드 구성** (TCP 헤더+데이터 = IP Payload로 이해)

```
[AH 전송모드]  IP헤더 | AH헤더 | TCP헤더 | 데이터
              → 인증 범위: 전체, 암호화 없음

[AH 터널모드]  NewIP헤더 | AH헤더 | IP헤더 | TCP헤더 | 데이터
              → 인증 범위: 전체

[ESP 전송모드] IP헤더 | ESP헤더 | TCP헤더 | 데이터 | ESP트레일러 | ESP인증
              → 암호화: TCP헤더~ESP트레일러 / 인증: ESP헤더~ESP트레일러

[ESP 터널모드] NewIP헤더 | ESP헤더 | IP헤더 | TCP헤더 | 데이터 | ESP트레일러 | ESP인증
              → 암호화: IP헤더~ESP트레일러 / 인증: ESP헤더~ESP트레일러
```

### SSL/TLS

웹 브라우저 통신에 기밀성·무결성·인증을 제공하는 프로토콜. 전송 계층 위에 별도 TLS 계층을 둔다. TLS를 쓰는 응용 프로토콜은 이름 끝에 `S`가 붙는다(HTTP→HTTPS).

**TLS 키 교환 과정**

1. 클라이언트가 지원 암호 알고리즘·매개변수 목록 전송
2. 서버가 그중 하나를 선택하고 공개키 + 디지털 인증서 전송
3. 클라이언트가 인증서 확인 후 임의의 암호화된 메시지 생성해 전송
4. 서버가 개인키로 복호화 → 양측 동일한 세션키 완성

**관련 용어**

| 용어 | 설명 |
|---|---|
| **0-RTT** | TLS 1.3 추가 기능. 핸드셰이크를 간소화해 암호화 시작까지의 시간을 단축 |
| **DTLS** | Datagram TLS. UDP 기반 통신에 SSL/TLS와 유사한 보안 기능 제공 |
| **POODLE** | TLS 연결을 SSL 3.0으로 강제 다운그레이드시켜 그 취약점으로 암호문 해독 |
| **HeartBleed**(CVE-2014-0160) | OpenSSL Heartbeat 확장이 요청 메시지의 데이터 길이를 검증하지 않아 메모리 최대 64KB 탈취 가능. **OpenSSL 1.0.1f 이전** 버전이 영향받음 |

### ARP (Address Resolution Protocol)

논리 주소(IP) → 물리 주소(MAC) 변환 프로토콜. 반대(MAC→IP)는 **RARP**.

- 목적지 MAC을 모를 때 `00:00:00:00:00:00`을 목적지로, 브로드캐스트(`FF:FF:FF:FF:FF:FF`)로 전체 노드에 요청 → MAC 주소를 획득해 ARP 캐시에 저장

| 공격 | 원리 | 대응 |
|---|---|---|
| **ARP Spoofing** | 피해자에겐 "내가 게이트웨이", 게이트웨이엔 "내가 피해자"라고 MAC을 속여 중간에서 트래픽 가로챔(MITM). 정상 중계까지 해 주면 피해자는 눈치채지 못함 | ARP 캐시를 정적(static)으로 등록 — `arp -s [게이트웨이IP] [게이트웨이MAC]` |
| **ARP Redirect** | 공격자가 스스로를 라우터라고 속여, 패킷이 항상 자신을 거쳐 실제 라우터로 가게 함(Gateway MAC 위조) | 위와 동일 계열 대응 |

### SNMP (Simple Network Management Protocol)

네트워크 장비 관리 프로토콜. **Manager**(관리 서버)가 **Agent**(관리 대상 장비)에게 정보를 요청·수집하고, Agent는 이벤트 발생 시 Manager에게 능동적으로 보고(Trap)한다.

| 구성요소 | 포트 | 방향 |
|---|---|---|
| **Polling** | **161/UDP** | Manager → Agent, 정보 요청 |
| **Trap** | **162/UDP** | Agent → Manager, 이벤트 발생 시 자발적 보고 |

> ⚠️ **혼동 주의**: "Agent가 161번, Manager가 162번을 쓴다"처럼 역할과 포트를 뒤섞어 외우기 쉽다. **"161=질의응답(주고받는 일반 통신), 162=Trap(알림 전용)"** 으로 구분해 외우면 헷갈리지 않는다.

**SNMPv3 msgSecurityParameters**

| 목적 | 파라미터 |
|---|---|
| 재전송 공격 방지 | `msgAuthoritativeEngineID`, `msgAuthoritativeEngineBoots`, `msgAuthoritativeEngineTime` |
| 위장 공격 방지 | `msgUserName`, `msgAuthenticationParameters` |
| 기밀성 | `msgPrivacyParameters` |

라우터에서 SNMP 비활성화: `Router# configure terminal` → `Router(config)# no snmp-server`

### 무선 인터넷

**인증 방식**

| 방식 | 설명 |
|---|---|
| **PSK** | 사전 공유키. 별도 인증서버 없는 소규모 망, 4-way handshake로 AP·단말이 같은 값을 갖는지 확인 |
| **EAP** | 원래 PPP용으로 개발, 현재 IEEE 802.1X 사용자 인증에 사용. 다양한 링크에 적용 가능 |

**보안 기술**

WEP(RC4 알고리즘, 초기 규격) → WPA(EAP 인증 + RC4-TKIP 암호화) → **WPA2**(EAP 인증 + **AES-CCMP** 암호화)

### Snort

실시간 트래픽 분석이 가능한 오픈소스 IDS(리눅스 설정 경로 `/etc/snort`). Rule 구조: `[action] [Protocol] [IP주소] [Port번호] -> ...`(Header) + 옵션(Body).

**Action**

| Action | 동작 |
|---|---|
| `alert` | 알람 발생 + 로그 기록 |
| `log` | 로그만 기록 |
| `pass` | 아무 처리 없이 통과 |
| `activate` | 알람 발생 + `dynamic` 룰 활성화(트리거) |
| `dynamic` | `activate`에 의해 트리거되면 로그만 기록(평소엔 비활성) |
| `drop` | 차단 + 로그 기록 |
| `reject` | 차단 + 로그 기록 + RST 또는 ICMP port unreachable 전송 |
| `sdrop` | 차단만 하고 로그는 남기지 않음(silent drop) |

**Body 옵션**

| 옵션 | 의미 |
|---|---|
| `msg` | 로그에 남을 제목 |
| `content` | payload 검사 문자열 |
| `nocase` | 대소문자 무시 |
| `offset` | 검사 시작 위치(0부터) |
| `depth` | offset부터 검사할 범위 |
| `distance` | 직전 검색 위치에서 띄울 바이트 수 |

**Suricata**: Snort의 장점을 계승하면서 대용량 트래픽 실시간 처리에 특화된 오픈소스 IDS/IPS.

### iptables

리눅스 방화벽. `iptables [테이블] [체인] [룰] [타겟]` 구조.

| 구분 | 종류 |
|---|---|
| 테이블 | `filter`(기본, 패킷 필터링) · `nat`(SNAT/DNAT 주소 변환) · `mangle`(TOS 등 헤더 조작) |
| 체인(filter 기준) | `INPUT`(들어오는 패킷) · `OUTPUT`(나가는 패킷) · `FORWARD`(경유 패킷) |
| 룰 매치 | `-p tcp/udp`(프로토콜) · `--syn`(SYN 플래그) · `-s`/`-d`(출발지/목적지 IP) · `--sport`/`--dport`(포트) |
| 타겟(`-j`) | `ACCEPT`(허용) · `DROP`(차단, 무응답) · `REJECT`(차단 + ICMP 에러 응답) · `LOG`(탐지 로그만) |

```bash
iptables -A INPUT -s [IP] -j DROP

# SYN Flooding 방어: 2초 내 30회 이상 SYN이면 차단
iptables -A INPUT -p TCP --syn --dport 80 \
  -m recent --update --seconds 2 --hitcount 30 --name SYN_DROP -j DROP
```

### DoS / DDoS

| 용어 | 설명 |
|---|---|
| **DoS** | 단일 컴퓨터로 서비스를 방해 |
| **DDoS** | 물리적으로 분산된 다수의 좀비 PC로 공격 |
| **DRDoS** | 출발지 IP를 피해자 IP로 위조해 다수의 **반사 서버**에 요청을 보내고, 반사 서버들의 응답이 피해자에게 집중되게 함. 출처 추적이 어렵고 좀비 PC 없이도 대량 트래픽 생성 가능 |
| **Unicast RPF** | 패킷의 출발지 IP를 라우팅 테이블과 대조해 IP 스푸핑을 확인하는 방지 기법 |

**주요 공격**

| 공격 | 원리 | 대응 |
|---|---|---|
| **Smurf** | 피해자 IP로 위조한 출발지로 브로드캐스트 도메인에 ICMP Echo Request 전송 → 다수의 Echo Reply가 피해자에게 집중 | `no ip directed-broadcast`(전면 비활성) 또는 신뢰 대역만 허용, Echo Reply rate-limit |
| **LAND Attack** | 출발지·목적지 IP를 모두 공격 대상 IP로 설정한 SYN 패킷 전송(IP 스푸핑 기반) | 내부 IP를 출발지로 하는 유입 패킷 차단 |
| **Slow HTTP POST(RUDY)** | Content-Length는 크게, 실제 데이터는 매우 느리게 전송해 연결을 계속 점유 | Connection/Read Timeout, 동일 출발지 IP당 동시 연결 수 제한 |
| **Slow HTTP Header** | 헤더 종료 개행(`\r\n\r\n`)을 보내지 않고 헤더를 지속 전송 | 동시 연결 임계치 설정 |
| **TCP SYN Flooding** | 다수의 SYN으로 SYN_RECEIVED 상태를 대량 유발 | SYN Cookie, IP별 SYN 임계치 |
| **TCP Connection Flooding** | 다량의 SYN으로 다수의 ESTABLISHED 상태 유발(SYN Flooding의 일종) | 위와 동일 계열 대응 |
| **UDP/ICMP Flooding** | 대량의 UDP/ICMP 패킷 전송 | 트래픽 임계치·필터링 |
| **HTTP Flooding** | 정상 핸드셰이크 후 GET/POST 대량 반복 — 적은 패킷으로도 효과적 | 행위 기반 탐지, WAF |
| **SSDP DRDoS** | UPnP 장치가 SSDP(1900/UDP)로 응답하는 특성을 이용한 반사 공격, IoT 기기 대상 | 1900번 포트 차단, 노출 장치 점검 |
| **Hash DoS** | 다수의 파라미터(`&`)로 해시 연산 리소스를 고갈 | 파라미터 수 제한 |
| **SlowRead** | TCP Window Size를 줄여 서버 응답을 아주 느리게 받아 연결을 오래 점유 | 타임아웃·연결 수 제한 |

> ⚠️ **혼동 주의**: HTTP 응답 분할(Response Splitting) 공격은 **DoS가 아니다.** 요청 파라미터가 응답 헤더로 반영될 때 개행문자(CR `%0D`/LF `%0A`)를 삽입해 응답을 여러 개로 쪼개는 기법으로, XSS·캐시 훼손 등에 악용되는 **인젝션형** 공격이다.

### Port Scan

| 스캔 | 포트 열림 | 포트 닫힘 | 특징 |
|---|---|---|---|
| **TCP Open(Full) Scan** | SYN→SYN/ACK→ACK→RST/ACK(완전 연결) | SYN→RST/ACK | 신뢰성 높지만 느리고 **로그 남음** |
| **TCP SYN(Half Open) Scan** | SYN→SYN/ACK→**RST**(연결 미완성) | SYN→RST/ACK | 로그 안 남음(스텔스). 무응답이면 필터링 의심 |
| **TCP FIN/NULL/XMAS Scan** | 무응답 | RST | 특수 플래그 조합, 로그 안 남음 |
| **TCP ACK Scan** | — (포트 개폐 판별용이 아님) | — | 방화벽이 상태 기반인지 확인용 — 필터링 시 무응답/ICMP, 아니면 RST |
| **UDP Scan** | 응답 오면 열림 | 무응답이면 불확실 | TCP보다 빠르나 결과가 불확실 |

### 기타 네트워크 보안 개념

**패킷 필터링**

| 방식 | 설명 |
|---|---|
| Ingress 필터링 | 외부→내부 유입 시, 사용되지 않는/존재하지 않는 IP 대역을 출발지로 위조한 스푸핑 차단 |
| Egress 필터링 | 내부→외부 유출 시, 출발지 IP가 반드시 우리 대역이어야 함 |
| Stateful 방화벽 | 출발지·목적지 IP/포트로 세션 상태를 저장해 정교하게 필터링 |

**기타 개념**

| 개념 | 설명 |
|---|---|
| **Tiny Fragment** | 패킷을 아주 작게 단편화해 재조합 기능이 없는 방화벽의 탐지를 우회. 대응: 재조합 기능이 있는 방화벽 사용 |
| **오탐 / 미탐** | 오탐(정상을 이상행위로 오판) vs 미탐(이상행위를 못 잡음) |
| **오용탐지** | 알려진 패턴 매칭, 오탐률 낮지만 신종 공격은 못 잡음 |
| **이상탐지** | 정상 행위 통계와 비교, 신종 탐지 가능하나 오탐 많음 |
| **Wireshark** | DNS 응답만 보기 `dns.flags.response==1`, 질의만 보기 `dns.flags.response==0` |
| **Promiscuous Mode** | NIC가 자신에게 오지 않은 패킷까지 전부 수신 — 스니핑에 악용. 대응: SSH·HTTPS 등 암호화 통신 |

**스위칭 허브 동작 원리**

Learning(MAC 테이블에 정보 저장) → Flooding(모르는 정보는 전체 전달) → Forwarding(아는 목적지로 전달) → Filtering(다른 목적지로 못 넘어가게 제어) → Aging(오래된 정보 삭제)

**TCP 3-Way Handshake**

```
SYN(seq=100) → SYN/ACK(seq=200, ack=101) → ACK(seq=101, ack=201)
```

**ACK 값 = 상대방 seq + 1**, 다음 SYN/seq 값은 직전에 받은 ack 값을 그대로 사용.

## 3. 애플리케이션 보안

### 웹 서버 설정 (Apache)

- 로그: **Access 로그**(클라이언트 요청·응답 기록) / **Error 로그**(오류·경고 기록). 경로는 `httpd.conf`의 `ErrorLog`/`CustomLog` 지시자로 확인

| 지시자 | 의미 |
|---|---|
| `KeepAlive On` | 지속 연결 사용 |
| `MaxKeepAliveRequests 100` | 하나의 연결이 허용하는 최대 요청 수 |
| `KeepAliveTimeout 100` | 연결 유지 시간(초) |
| `DirectoryIndex index.htm index.html` | 먼저 찾을 인덱스 파일 순서 |
| `CustomLog 경로 common` | 접근 로그 저장 경로·형식 |
| `LimitRequestBody` | 업로드 허용 최대 파일 크기 |

### 웹 취약점

**SQL Injection** — DB와 연결된 애플리케이션의 입력값을 조작해 의도하지 않은 쿼리 결과를 얻는 공격.

근본 대응은 **Prepared Statement**: 쿼리를 최초 1회 분석·최적화해 메모리에 저장해 두고, 이후 입력값을 SQL 구문이 아닌 **매개변수**로만 바인딩·재사용 — 성능도 좋고 인젝션도 막힌다.

| 유형 | 원리 |
|---|---|
| **Error based** | DB가 알려주는 오류 메시지에 의존해 정보를 얻음(오류 메시지 비표시로 방어) |
| **Union based** | 정상 쿼리 결과와 공격자의 쿼리 결과를 `UNION`으로 합쳐 출력시켜 정보 획득 |
| **Blind based** | 응답·오류 메시지가 없을 때 참/거짓만으로 조건을 확인하며 값을 하나씩 알아냄(반복 시도 필요) |

**기타 웹 취약점**

| 취약점 | 설명 | 대응 |
|---|---|---|
| **XSS** | 게시판·웹·메일 등에 삽입된 악성 스크립트로 쿠키·개인정보를 특정 사이트로 전송 | 입력 문자열의 HTML 특수문자(`<`,`>`,`&`,`/` 등) 이스케이프 처리 |
| **Directory Indexing** | 초기 페이지(`index.html` 등)가 없을 때 디렉터리 목록이 자동 노출 | Apache `.htaccess`의 `Options`에서 `Indexes` 제거 |
| **파일 업로드 공격** | 실행 가능한 스크립트(jsp/php/sh 등)를 첨부해 원격 제어(**웹쉘**) | `.htaccess`의 `FilesMatch`(확장자 deny/allow) · `AddType`(html로 재해석) |
| **Drive By Download** | 팝업·iframe·리다이렉트 등으로 인지 못하는 사이 악성코드 다운로드 | 브라우저·플러그인 최신화 |
| **Dropper** | 정상 앱으로 위장해 배포된 뒤, 내부에 품고 있던 코드로 새 악성코드를 생성 | 백신·행위기반 탐지 |
| **XXE** | XML 문서가 외부 개체를 참조하게 만들어 삽입된 코드 실행 — 파일 유출(`SYSTEM "file:///etc/passwd"`) 또는 엔티티 반복 참조로 메모리 고갈(Billion Laughs, DoS) | 외부 엔티티 처리 비활성화 |

### 웹 보안 방안

**쿠키 보안** — 클라이언트 로컬에 저장되는 키-값 데이터.

| 속성 | 의미 |
|---|---|
| `Secure` | HTTPS 연결에서만 전송(평문 노출 방지) |
| `HttpOnly` | 자바스크립트의 쿠키 접근 차단(끄면 XSS에 취약) |

예) `Set-Cookie: ID=redstone; Path=/; secure` → HTTPS 통신일 때만 쿠키 전송

**이메일 보안**

| 기술 | 설명 |
|---|---|
| **SPF**(Sender Policy Framework) | 발송 도메인 DNS의 TXT 레코드에 등록된 IP와 실제 송신 IP를 비교해 정당성 검증. 불일치 시 차단하는 대표적 스팸 차단 기술 |
| **DKIM**(DomainKeys Identified Mail) | 발신 서버의 개인키로 메일 헤더를 전자서명하고, 수신 측이 DNS TXT의 공개키로 검증 |
| **DMARC** | SPF와 DKIM 결과를 종합해 정책을 적용하는 기법 |
| **PGP** | 필 짐머만이 독자 개발. PEM 대비 보안성은 낮지만 구현이 쉽고 무료 배포되어 널리 사용 |

### DNS (Domain Name System)

도메인↔IP 변환 프로토콜. 포트: **53/UDP**(기본), **53/TCP**(512바이트 초과 응답 시).

| 개념 | 설명 |
|---|---|
| 목적 | 호스트 별칭 부여(하나의 서버에 여러 도메인명), 부하 분산(한 도메인에 여러 IP를 번갈아 응답) |
| 캐시·TTL | 상위 DNS 서버 부하를 줄이기 위해 캐시를 두며, TTL 동안(통상 2일 수준) 유지 |
| Zone 동기화 | `named.conf`의 `allow-transfer { 슬레이브서버IP; };`로 지정한 슬레이브만 Zone Transfer 허용 |

**공격**

| 공격 | 원리 |
|---|---|
| **DNS Cache Poisoning** | 사용자의 DNS 질의에 공격자가 **정상 응답보다 먼저** 위조 응답을 보내 캐시 서버에 조작된 정보를 심음(먼저 도착한 응답을 신뢰하는 특성 악용) → 이후 정상 응답은 폐기, 사용자는 조작된 사이트로 접속 |
| **DNS 증폭(Amplification)** | DNS 질의에 인증 절차가 없고 요청보다 응답이 크다는 점을 악용. 공격자가 중계 DNS 서버에 **ANY**(또는 TXT) 질의를 보내며 출발지를 피해자 IP로 위조 → 중계 서버가 큰 응답을 피해자에게 쏟아부음 |

### FTP (File Transfer Protocol)

클라이언트-서버 간 두 개의 연결: **21/TCP**(제어, 명령 주고받기) + **20/TCP**(실제 데이터 전송).

| 공격/기술 | 설명 | 대응 |
|---|---|---|
| **FTP Bounce** | 데이터 채널(20) 생성 시 목적지를 검사하지 않는 구조적 결함을 악용, `PORT` 명령을 조작해 제3자 포트 스캔·거짓 메일 전송 등 수행 | FTP 서버 업데이트, 1024번 미만 포트로의 데이터 접속 차단 |
| **Anonymous FTP** | `anonymous`/`ftp` 계정으로 인증 없이 접근 허용된 상태를 악용해 악성코드 업로드 | 불필요 시 비활성화: `userdel ftp`/`userdel anonymous`, vsFTP는 `anonymous_enable=NO` |
| **TFTP 공격** | **69/UDP**, 인증 절차가 없어 접근제어 미흡 시 임의 파일 접근 가능 | 불필요하면 비활성화 |
| **SFTP** | SSH(포트 **22**) 기반 암호화 FTP | — |

### 기타 애플리케이션 보안 용어

| 용어 | 설명 |

| **Pass the Hash** | 비밀번호 대신 탈취한 **해시값**으로 인증을 통과. Windows LM/NTLM 환경에서 가능, 주로 **mimikatz** 사용 |

| **웹 프록시** | 웹 서버를 대신해 응답하는 중개자. 대표 도구: Paros, Burp Suite |

### 정보보안 거버넌스

기업 거버넌스의 부분집합으로, 정보의 무결성·서비스 연속성·정보자산 보호를 위한 전략적 방향을 제시하고 위험관리·자산의 책임 있는 사용·보안 프로그램의 성패 모니터링을 보장하는 것 — **이사회·경영진의 책임**이며 정보보호·재해복구 관련 규정 준수를 포함한다.

**절차**: 통제환경 → 위험평가 → 통제활동 → 정보 및 의사소통 → 실행계획수립

### 위험관리

> 🔑 **절차 — [식분평/대계주]**
> 자산식별 → 위험분석(자산가치·중요도·기존 보안대책·취약성 평가) → 위험평가 → 정보보호 대책수립 → 정보보호 계획수립 → 주기적 검토

| 용어 | 정의 |
|---|---|
| 자산 중요도 평가 | CIA 관점에서 자산 가치를 평가해 정보보호 우선순위를 정하는 기준 |
| 취약점 | 공격자가 악용할 수 있는 시스템·응용프로그램의 약점 |
| 위협 | 조직·시스템에 손실을 끼칠 수 있는 사건·행동 |
| 우려사항 | 위협과 취약성을 하나로 통합해 평가하는 개념 |

**위험분석 접근법**: 베이스라인 접근법 · 비정형 접근법 · 상세 위험분석 · 복합 접근법

**정량적 위험분석**

| 용어 | 의미 | 계산식 |
|---|---|---|
| EF(노출계수) | 자산에 대한 손실 가능성(%) | — |
| **SLE** | 1회 사건 발생 시 예상 손실액 | 자산가치 × EF |
| ARO(연간발생률) | 연간 위험 발생 가능성(%) | — |
| **ALE** | 연간 예상 손실액 | SLE × ARO |
| ROI | 투자 대비 수익 | (ALE절감분 − 투자비용) ÷ 투자비용 × 100 |

**정성적 위험분석 유형**: 과거자료 분석법 · 수학공식법 · 확률분포법 · 점수법 · **델파이법** · **시나리오법** · **순위결정법** · **퍼지행렬법**(위험분석 요인을 정성적 언어로 표현해 기대손실을 평가)

**위험처리전략**(위험평가 이후)

| 전략 | 설명 |
|---|---|
| 위험 수용 | 위험 수준이 수용 가능하다고 판단해 그대로 진행 |
| 위험 감소 | 대책 도입. **대책 효과 = 감소한 ALE − 대책 운영 비용** |
| 위험 전가 | 보험 가입 또는 외주 위탁 |
| 위험 회피 | 위험 있는 프로세스·사업을 축소·포기 |

`DoA`(Degree of Assurance) = 수용 가능한 위험 수준

### 접근제어정책

| 모델 | 전체 명칭 | 기준 | 특징 |
|---|---|---|---|
| **DAC** | Discretionary Access Control(임의적 접근통제) | 접근 주체(소유자)의 신분 | ACL 사용 |
| **MAC** | Mandatory Access Control(강제적 접근통제) | 주체·객체의 보안 등급(레이블) | 규칙이 단순해 관리 용이 |
| **RBAC** | **Role**-Based Access Control(**역할**기반 접근통제) | 주체·객체의 역할 | 비임의적·직무기반 모델, 최소권한·직무분리 원칙, 효율적 |

> ⚠️ RBAC은 "Rule-Based"가 아니라 **"Role(역할)"**-Based Access Control이다 — 한글 번역은 맞고 영문 풀네임을 혼동하기 쉬우니 주의.

### 업무연속성계획(BCP)

> 🔑 **정의 — [재위업보]**
> 각종 재해·재난으로부터 위기관리를 기반으로 업무 연속성을 보장하는 계획

**재난복구계획(DRP) — 재해복구서비스 4종류**

| 유형 | 구성 | 특징 |
|---|---|---|
| **미러 사이트** | 주 센터와 동일 수준, **액티브-액티브** 실시간 서비스 | 백업 가장 빠름·데이터 최신성 보장, 비용 최고 |
| **핫 사이트** | 동일 수준, **액티브-스탠바이** | 수 시간 내 가동, 데이터 최신 유지 |
| **웜 사이트** | 디스크·주변기기 등 부분 설비만 보유 | 수일~수주 내 가동 |
| **콜드 사이트** | 데이터만 원격 보관, 장소만 준비 | 비용 최저, 데이터 손실 가능·복구까지 오래 걸림 |

### CC (Common Criteria) 인증

국가마다 다른 정보보호제품 평가기준을 연동·상호 인증하기 위한 **ISO/IEC 15408** 등록 국제 표준 평가·인증 제도.

| 구분 | 내용 |
|---|---|
| 정책기관 | 과학기술정보통신부 |
| 인증기관 | IT보안인증사무국(ITSCC) |
| 평가기관 | KISA, TTA 등 |
| 등급 | **EAL1~EAL7**(숫자가 높을수록 엄격), EAL0은 부적합 |

**대표 요소**

| 요소 | 설명 |
|---|---|
| **PP**(Protection Profile) | 보호프로파일 — 제품군에 대한 공통 요구사항 |
| **ST**(Security Target) | 보안목표명세서 — PP 요구사항을 실제 제품으로 구현했음을 기술한 기능명세서 |
| **TOE**(Target of Evaluation) | 평가 대상 제품·시스템 |
| **EAL** | 보증 요구사항 컴포넌트 패키지 |

예) (주)강아지가 "강IDS"로 CC 인증을 받는 경우 — PP: IDS 제품군, ST: PP 요구사항 충족을 기술한 강IDS 명세서, TOE: 강IDS.

| **ISAC**(정보공유분석센터) | 취약점·침해요인·대응방안 정보를 제공하고 침해사고 발생 시 실시간 경보·분석체계 운영. 금융·통신 등 분야별로 설립 |

## 5. 법규

> ※ 이 대단원은 원본 자료 자체가 다른 영역 대비 분량이 적어(유출통지 기간, ISMS-P 인증
> 의무대상, CISO 지정 요건처럼 실제로 자주 나오는 주제가 빠져 있음), 있는 내용만 정리했다.
> 부족한 부분은 `정보보안관리및법규` 카테고리의 개별 노트(예: 개인정보보호법 핵심, 안전성
> 확보조치, 정보보호-법률-총정리)를 함께 참고할 것.

### 정보보호 관련 법령

- 개인정보 보호법
- 정보통신망 이용촉진 및 정보보호 등에 관한 법률
- **정보통신기반 보호법** — 민간·공공을 불문하고 침해사고 발생 시 국가안전보장·경제사회에 미치는 피해규모·범위가 큰 시설의 보호를 다룸
- 위치정보의 보호 및 이용 등에 관한 법률
- 전자서명법

### 개인정보 보호법

**개인정보 수집이 가능한 경우**

- 정보주체의 동의를 받은 경우
- 법률에 특별한 규정이 있거나 법령상 의무를 준수하기 위해 불가피한 경우
- 공공기관이 법령 등이 정한 업무 수행을 위해 불가피한 경우
- 정보주체와의 계약 체결·이행을 위해 불가피하게 필요한 경우
- 개인정보처리자의 정당한 이익 달성을 위해 필요하고 명백히 정보주체의 권리보다 우선하는 경우

**개인정보 처리방침 — 포함 항목**

- 처리 목적, 처리하려는 항목, 처리·보유기간
- 파기 절차·방법
- (해당 시) 위탁·제3자 제공에 관한 사항
- 정보주체의 권리·의무·행사방법
- 개인정보 보호책임자 성명(또는 부서명)·연락처
- 안전성 확보조치에 관한 사항
- 인터넷 접속정보파일 등 자동 수집 장치의 설치·운영·거부에 관한 사항

**처리방침 게재 방법**

- 인터넷 홈페이지에 지속 게재
- 사업장 등 보기 쉬운 장소에 게시
- 관보·신문 게재
- 계약서 등에 실어 정보주체에게 발급

**영상정보처리기기 안내문 포함 내용**

- 설치 장소·목적
- 촬영 범위·시간
- 관리책임자 성명·연락처
- 그 밖에 대통령령으로 정하는 사항

### 개인정보 기술적·관리적 보호조치 기준

**개인정보취급자 비밀번호 작성 규칙**

| 조합 | 최소 길이 |
|---|---|
| 영문·숫자·특수문자 중 2종류 이상 조합 | 10자리 이상 |
| 영문·숫자·특수문자 중 3종류 이상 조합 | 8자리 이상 |

- 연속된 숫자·생일·전화번호 등 유추하기 쉬운 비밀번호 사용 금지
- 비밀번호 최대 사용기간 설정(반기별 변경 권장)

**개인정보처리시스템 접속기록**

개인정보취급자의 계정, 접속일시, 접속장소, 수행업무 등(+ 처리한 정보주체 정보)을 기록·보관한다.
