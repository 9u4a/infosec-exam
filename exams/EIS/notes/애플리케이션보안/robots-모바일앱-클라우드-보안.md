## 한 줄 정의

웹 서비스 주변의 **세 갈래 주제**를 모았다. ① 웹·파일 전송 서비스(robots.txt · FTP) ② 클라우드(서비스·배포 모델, 책임, 보안 기술) ③ 모바일 앱(딥링크 · 인증서 고정 · 관리 체계). 각각 따로 출제되므로 소제목 단위로 외운다.

## 웹·파일 전송 서비스

### robots.txt {{13-16}} {{15-2}} {{24-6}}

**로봇 배제 표준**을 따르는 일반 텍스트 파일로, 웹사이트 **루트**(`/robots.txt`)에 둔다. 검색 로봇의 접근을 **권고**할 뿐 **강제력은 없다.**

```text
User-agent: googlebot
Allow: /
User-agent: googlebot-image
Disallow: /private/
```

> [!함정] Disallow 는 위치 안내판이 된다
> 관리자 페이지·백업 경로를 `Disallow` 에 적으면 **오히려 위치를 알려주는 꼴**이다. 민감 경로는 **인증으로 보호**하고 robots 에 노출하지 않는다.

### FTP 능동 / 수동 모드 {{9-14}} {{10-2}}

| 채널 | 서버 포트 | 역할 |
|---|---|---|
| 제어 | **21** | 접속·명령 전달, 세션 내내 유지 |
| 데이터 | **20** (Active) | 파일·목록 전송 |

| | Active | Passive |
|---|---|---|
| 연결 방향 | 서버 **20번 → 클라이언트 임의 포트(1024↑)** 로 역방향 | 서버가 임의 포트를 열고 대기, **클라이언트가 접속** |
| 문제 | 클라이언트 방화벽/NAT 가 인바운드를 막으면 **목록·전송 실패** | 클라이언트 방화벽 문제 해결 |

보안: 평문이라 **FTPS**(FTP+TLS) 또는 **SFTP**(SSH) 를 쓰고, `chroot` 로 상위 디렉터리 접근을 막는다.

### FTP·파일전송 공격 {{2-3}}

| 공격 | 설명 |
|---|---|
| **TFTP** | **UDP 69**, **인증 없이** 전송 → 설정파일·부팅이미지 유출·변조 |
| **Anonymous FTP** | 익명 접속 허용 서버에서 파일 열람·업로드(웹셸)·정보 수집 |
| **FTP Bounce** | `PORT` 명령의 목적지를 검사하지 않는 결함 → FTP 서버가 **제3 시스템**으로 데이터를 보내게 해 포트스캔·우회 (방화벽 뒤 스캔) |

대응: 익명 FTP 비활성/최소화 · TFTP 미사용(필요 시 ACL·읽기전용) · `PORT` 목적지 검증 · Passive 모드 · FTPS/SFTP

## 클라우드

### 서비스 유형 {{12-6}}

| 유형 | 제공 범위 | 사용자 책임 | 예 |
|---|---|---|---|
| **IaaS** | 서버·스토리지·네트워크 | OS·미들웨어·앱·데이터 | AWS EC2 · GCP CE |
| **PaaS** | + OS·런타임·개발 플랫폼 | 앱·데이터 | App Engine · Heroku |
| **SaaS** | + 완성된 애플리케이션 | 데이터·계정 설정 | Gmail · Salesforce |

**책임 공유 모델**: 아래 계층일수록 CSP 책임↑, 위 계층일수록 이용자 책임↑

### 배포 모델 4가지

| 모델 | 설명 | 특징 |
|---|---|---|
| **Public** | 불특정 다수에게 인터넷으로 제공 | 저렴, 보안 위험 상대적으로 높음 |
| **Private** | 단일 조직 전용 | 높은 보안·높은 비용 |
| **Hybrid** | Public + Private 혼합 | 유연, 관리 복잡 |
| **Community** | 같은 목적·규제의 조직 간 공유 | 금융권·공공기관 |

### 보안 기술 3종

| 기술 | 역할 |
|---|---|
| **CASB** | 사용자 ↔ SaaS 사이 프록시 — **가시성 · 컴플라이언스 · 데이터 보안(DLP) · 위협 방어** |
| **SWG** | 인터넷 트래픽 필터링 — 악성 사이트 차단 |
| **ZTNA** | "아무도 신뢰하지 않는다" — 내부 사용자도 **매 접근마다** 인증·인가 |

**SecaaS**: 보안 솔루션 자체를 클라우드로 제공 (인증·백신·IDS·DLP·IAM). 장점은 초기 비용 절감·탄력적 확장, 단점은 인터넷 의존과 데이터 주권 문제다.

### 가상화 보안

| 구성요소 | 위협 | 대응 |
|---|---|---|
| 하이퍼바이저 | **VM Escape** | 패치 · 접근 통제 |
| VM 간 통신 | VM-to-VM 스니핑 | 가상 네트워크 세분화 (VLAN) |
| 스냅샷 | 민감 데이터 포함 유출 | 암호화 · 접근 제한 |
| 컨테이너 | 이탈 · 이미지 취약점 | 이미지 서명 검증 · 네임스페이스 격리 |

**IAM vs EAM**: EAM 은 OS·DB·서버 등 사내 자원 접근의 통합 관리이고, IAM 은 신원 확인 + 접근 제어(RBAC/ABAC) + 계정 생명주기까지 포괄하는 **확장 개념**이다.

### 서브도메인 테이크오버 {{20-9}}

외부 서비스용 서브도메인에 **CNAME** 을 걸고 서비스는 해지했지만 **DNS 레코드를 지우지 않은** 경우, 공격자가 같은 이름으로 리소스를 만들어 서브도메인을 **탈취**한다 (피싱·쿠키 탈취).

대응: 해지 시 DNS 레코드 즉시 삭제 · 소유하지 않은 리소스를 가리키는 **dangling 레코드** 정기 점검

## 모바일 앱

### 관리 체계 (BYOD 대응)

| 기술 | 역할 |
|---|---|
| **MDM** (Device) | 기기 전체 제어 — 원격 잠금·삭제, 정책 배포 |
| **MAM** (Application) | 업무 앱만 분리 관리 |
| **MCM** (Content) | 업무 문서 단위 암호화·접근 통제 |
| **EMM** | MDM + MAM + MCM 통합 |

### 딥링크 {{18-10}} {{28-12}}

앱 내 **특정 화면으로 바로 이동**시키는 URL 스킴(`myapp://pay?...`) 또는 유니버설·앱 링크다.

- 악용: 조작된 딥링크로 접속을 유도해 **인증·검증 없이 민감 화면(카드·주소) 노출**, 파라미터 조작으로 **의도치 않은 계좌이체**
- 대응: 파라미터 **서버 측 재검증** · 민감 액션은 재인증 · 화이트리스트 호스트 · `autoVerify` 앱 링크

### 인증서 고정 (Certificate Pinning) {{29-13}}

앱에 서버 인증서(또는 공개키) **지문을 미리 저장**해 TLS 연결 시 실제 인증서와 일치할 때만 통신을 허용한다. 사설 CA·프록시를 쓴 **중간자(MITM)** 공격을 막는다.

| 구분 | 내용 |
|---|---|
| 핵심 요소 | 고정 대상(리프 / 중간 CA / **공개키 SPKI 해시**) · 백업 핀(교체 대비) · 핀 만료·갱신 정책 |
| 우회 방법 | 루팅·탈옥 후 **Frida · Objection** 후킹 · 앱 리패키징(스마리 패치) · 사용자 CA 신뢰 조작 |
