## 한 줄 정의

웹 공격의 **공통 뿌리는 "입력이 해석되는 곳으로 흘러가는 것"** 이다. 이 노트는 SQL/XSS 외의 나머지를 묶었다: **OS 명령 삽입 · 파일 포함(RFI/LFI) · 웹셸 · XXE · SSRF · CRLF · 요청 스머글링 · 크리덴셜 스터핑 · 문서/광고 공격**. 서버 내부로 들어가는 길인지, 요청 경계를 흐리는 것인지로 구분해 외운다. {{2-11}} {{5-7}} {{7-7}} {{12-3}} {{16-14}} {{25-10}} {{26-4}} {{28-2}} {{29-8}}

## 대표 인젝션 3종 {{18-3}} {{27-7}}

빈칸 (A)(B)(C) 로 자주 함께 나온다.

| 명칭 | 설명 |
|---|---|
| **(A) SQL 인젝션** | DB 와 연결된 앱의 입력을 조작해 의도하지 않은 쿼리 결과를 반환 (→ `sql-injection`) |
| **(B) XSS** | 게시판·메일에 삽입된 악성 스크립트가 열람자 브라우저에서 실행 (→ `xss-csrf`) |
| **(C) 운영체제 명령어 삽입** | `system()` · `exec()` 에 사용자 입력이 그대로 전달 — `;` `\|` `` ` `` 로 명령 연결 |

공통 대응: 입력 화이트리스트 · 파라미터 바인딩 · 위험 함수 대신 안전 API · 최소 권한

## 파일 포함과 웹셸

### 파일 인클루드 — RFI vs LFI {{5-7}} {{22-5}}

| | RFI (원격) | LFI (로컬) |
|---|---|---|
| 방법 | `include($_GET['page'])` 에 `http://evil/shell.txt` | `../../etc/passwd` 등 서버 내 파일 포함 |
| 결과 | 원격 코드 실행 | 정보 노출 → **로그 포이즈닝**으로 RCE |

PHP 대응: `include`/`require` 에 사용자 입력이 들어가는지 점검 → `php.ini` 에서 **`allow_url_include = Off`** · `allow_url_fopen = Off` · **화이트리스트 파일명만** 허용

### 웹셸 (WebShell) {{7-7}}

공격자가 올린 서버측 스크립트(`.php` `.jsp` `.asp`)로 **원격 명령·파일 조작·백도어 설치**를 한다.

| 구분 | 내용 |
|---|---|
| **유입 경로** | 파일 업로드 취약점 · 확장자 우회(`shell.php.jpg`, `%00`) · RFI/LFI · **CGI 원격 명령 실행**(Shellshock — `() { :;}; ...` 로 `b.php` 생성 {{29-8}}) · SQLi `INTO OUTFILE` |
| **로그 징후** | 업로드(POST) 200 **직후** 그 파일에 `?cmd=` · `?c=` 로 `id` · `whoami` · `cat /etc/passwd` · `wget` 요청. UA 가 비거나 스크립트성 |
| **파일 징후** | 웹 루트의 최근 생성 `.php`/`.jsp` · 이미지 확장자인데 스크립트 내용 · `eval(` `base64_decode(` `system(` `assert(` · 난독화된 한 줄 |
| **프로세스·네트워크** | `www-data`/`apache` 가 `/bin/sh`·`nc` 실행 · 웹서버의 아웃바운드 연결 |

대응: 업로드 디렉터리 **실행권한·핸들러 제거** · 확장자·MIME·매직바이트 검증 · 저장명 난수화 · WAF · CGI 비활성 · 무결성 점검(AIDE/Tripwire) · 웹셸 스캐너

## 서버가 대신 요청·해석하는 공격

### XXE (XML External Entity) {{16-14}}

```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<foo>&xxe;</foo>
```

외부 엔티티 참조를 허용하면 **로컬 파일 읽기 · SSRF · DoS(Billion Laughs)** 가 가능하다.
대응: XML 파서에서 **DTD·외부 엔티티 비활성화** (`FEATURE_SECURE_PROCESSING`), 최신 파서

### SSRF (Server Side Request Forgery) {{25-10}} {{28-2}}

서버가 **외부 입력으로 HTTP 요청을 만드는 기능**을 악용해 내부망·클라우드 메타데이터(`169.254.169.254`)에 접근한다.

대응: **화이트리스트**(허용 도메인/IP 만) · 사설 대역·localhost 차단 · 리다이렉트 차단 · 응답 미반환 · 메타데이터 **IMDSv2**

> [!함정] SSRF vs CSRF — 이름만 비슷, 정반대
> | | SSRF | CSRF |
> |---|---|---|
> | 요청 주체 | **서버**가 공격자가 정한 곳으로 | **피해자 브라우저**가 표적 서버로 |
> | 노리는 것 | 서버가 닿는 **내부 자원** | 피해자 **권한**의 상태 변경 |
> | 악용하는 신뢰 | "서버는 내부망을 신뢰" | "서버는 피해자 쿠키를 신뢰" |
> | 방어 | 목적지 화이트리스트 | CSRF 토큰 · SameSite |

## 요청 경계를 흐리는 공격

### CRLF 인젝션 / HTTP 응답 분할 {{12-3}} {{22-4}}

입력에 **CR(`\r` `%0D`) + LF(`\n` `%0A`)** 를 넣어 응답 헤더를 조기 종료시키고 **두 번째 응답을 위조**한다 → 캐시 포이즈닝 · XSS · 세션 고정.
대응: 헤더에 들어가는 값에서 CR/LF 제거·인코딩

### HTTP Request Smuggling {{26-4}}

프런트엔드(프록시·LB)와 백엔드가 **요청 본문 길이를 다르게 판단**하면, 한 TCP 연결의 요청 **경계가 어긋나** 뒷부분이 다음 사용자의 요청 앞에 붙는다.

```text
POST / HTTP/1.1
Content-Length: 6
Transfer-Encoding: chunked

0            ← 프런트: TE 무시, CL=6 → 본문 "0\r\n\r\nG"
             ← 백엔드: TE 우선 → "0\r\n\r\n" 에서 요청 종료, 남은 "G" 는 다음 요청의 시작
G
```

| 유형 | 프런트 | 백엔드 |
|---|---|---|
| **CL.TE** | Content-Length | Transfer-Encoding |
| **TE.CL** | Transfer-Encoding | Content-Length |
| **TE.TE** | 둘 다 TE 를 보나 한쪽이 변형 헤더(`Transfer-Encoding : chunked`)로 우회 | |

결과: 인증 우회 · 남의 요청에 악성 프리픽스 주입 · 웹 캐시 포이즈닝
대응: 프런트·백엔드 **HTTP 파서 통일** · CL+TE 동시 요청 거부 · 백엔드까지 **HTTP/2**

## 계정·문서·광고 기반 공격

### 크리덴셜 스터핑 {{17-4}} {{30-4}}

유출된 ID/PW 목록을 다른 사이트에 **자동 대입**한다.

> [!함정] 무차별 대입·스프레이·사전 공격과의 구분
> 스터핑은 **이미 유효한 조합을 재사용**한다는 점이 다르다.

대응: **MFA** · 로그인 실패 제한 · CAPTCHA · 유출 자격증명 대조(HIBP) · 이상 로그인 탐지 · 비밀번호 재사용 금지

|---|---|---|
| **DDE** {{14-4}} {{18-4}} | MS Office 앱 간 데이터 교환 프로토콜. 문서에 `=cmd\|'/c calc'!A0` 삽입 → **열람 시 명령 실행** | DDE 비활성 · 보호된 보기 · 매크로·필드 업데이트 차단 |

## 기출 포인트

> [!암기] 서술형 3줄 답안
> - **OS 명령어 삽입**: `system()`·`exec()` 에 입력이 검증 없이 전달돼 `;` `|` `` ` `` 로 이은 명령이 서버 권한으로 실행. 안전 API · 입력 화이트리스트 · 최소 권한.
