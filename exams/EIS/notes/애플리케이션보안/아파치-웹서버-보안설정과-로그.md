## 한 줄 정의

Apache 보안은 **① 위험한 Options 끄기 → ② 요청 크기·메서드·접근 제한 → ③ 배너·PHP 설정으로 정보 숨기기 → ④ 로그로 공격 판별** 의 흐름이다. 지시자 이름과 *왜 위험한지*를 짝으로 묻는다. {{17-16}} {{20-8}} {{29-11}} {{14-8}} {{21-10}} {{19-7}} {{24-10}}

## 설정 파일

- `httpd.conf` (또는 `apache2.conf`) — 메인 설정, `Include conf.d/*.conf`
- `.htaccess` — 디렉터리별 설정 (`AllowOverride` 로 허용 범위 제어)

## `<Directory>` 위험 지시자 {{17-16}} {{20-8}} {{29-11}}

```apache
<Directory /var/www>
    Options Indexes FollowSymLinks     # ← 위험
    AllowOverride None
    Require all granted
</Directory>
```

| 지시자 | 위험 | 조치 |
|---|---|---|
| **Indexes** | 인덱스 파일이 없으면 **디렉터리 목록 노출** | `Options -Indexes` |
| **FollowSymLinks** | 심볼릭 링크로 웹 루트 밖(`/etc/passwd`)에 접근 | 제거 또는 `SymLinksIfOwnerMatch` |
| **Includes** | SSI(`<!--#exec-->`) 명령 실행 | `-Includes` 또는 `IncludesNOEXEC` |
| **AllowOverride All** | `.htaccess` 로 설정 우회 | `None` |

> [!시험] 디렉터리 인덱싱 판단 {{13-15}} {{5-15}}
> 응답 **200 OK** + 본문에 `Index of /경로` 목록이 보이면 인덱싱 성공(취약).

## 요청·접근 제한

### 주요 옵션 {{14-15}}

| 지시자 | 의미 |
|---|---|
| `Timeout 300` | 300초 무통신 시 연결 종료 (Slowloris 대응은 더 짧게) |
| `KeepAlive On` · `MaxKeepAliveRequests 100` | 커넥션 재사용, 커넥션당 최대 요청 수 |
| `KeepAliveTimeout 5` | KeepAlive 유지 시간 |
| `DirectoryIndex index.html index.php` | 디렉터리 접근 시 기본 파일·순서 |
| **`LimitRequestBody <바이트>`** | 요청 본문(업로드) 최대 크기 {{14-8}} {{21-10}} |
| `LimitRequestFields` · `LimitRequestLine` | 헤더 개수·요청라인 길이 (버퍼 오버플로 대응) |
| `ServerTokens Prod` · `ServerSignature Off` | 버전 배너 숨김 |
| `TraceEnable Off` | TRACE 차단 (XST 대응) |

### HTTP 메서드 제한

```apache
# GET, POST 외 모든 메서드(PUT/DELETE/TRACE/CONNECT 등) 차단
<LimitExcept GET POST>
    Order allow,deny
    Deny from all
</LimitExcept>
```

확인: `telnet webserver.com 80` 후 `OPTIONS / HTTP/1.0` → 응답 `Allow:` 헤더에 TRACE 등이 보이면 취약.

### 접근 제어 (Order / Deny / Allow)

```apache
# 전체 차단 후 관리자 IP 만 허용
<Directory /var/www/admin>
    Order Deny,Allow
    Deny from all
    Allow from 192.168.56.30
</Directory>
# 백업·설정 파일 확장자 차단
<Files "*.bak">
    Order Allow,Deny
    Deny from all
</Files>
```

> [!함정] Order 순서가 의미를 뒤집는다
> `Order Deny,Allow` = Deny 를 먼저 적용하고 Allow 로 **예외** (기본 거부).
> `Order Allow,Deny` = 그 반대 (기본 허용).
> 서술형에서는 **순서를 반드시 명시**한다.

## 로그 분석 {{19-7}}

| 로그 | 지시자 | 내용 |
|---|---|---|
| **Access** | `CustomLog logs/access_log combined` | 정상 접속 (IP·시각·요청라인·상태코드·크기·Referer·UA) |
| **Error** | `ErrorLog logs/error_log` | 처리 오류·모듈 경고 |

경로는 **`httpd.conf`** 의 `CustomLog` / `ErrorLog` 에서 확인한다.

### Combined 로그 필드 {{24-10}}

```text
200.3.1.4 - - [30/May/2023:01:20:01 +0900] "GET /bulletin/read.php?no=101&item=book HTTP/1.1" 200 3549 "http://ref" "Mozilla/5.0"
```

| 순서 | 필드 | 예 |
|---|---|---|
| 1 | IP | `200.3.1.4` |
| 2 · 3 | ident · 인증 사용자 | `-` `-` |
| 4 | 시각 | `[30/May/2023:01:20:01 +0900]` |
| 5 | 메서드·URL·프로토콜 | `"GET /bulletin/read.php?... HTTP/1.1"` |
| 6 | **상태코드** | `200` |
| 7 | 응답 크기 | `3549` |
| 8 · 9 | Referer · User-Agent | `"http://ref"` `"Mozilla/5.0"` |

### 공격 로그 판별

- **7-15 HTTP Request 문제점** {{7-15}}
  1. `id`·`password` 가 **GET 파라미터 평문** (URL·로그·Referer 노출) → POST + HTTPS
  2. `Cache-Control: must-revalidate` 로 캐시 미사용 → 원본 서버 부하
  3. 세션 쿠키가 평문 구간에 노출
- **17-14 유니코드 취약점** {{17-14}}: `GET /script/..%c1%1c../winnt/system32/cmd.exe?/c+dir`
  - 유니코드 인코딩 디렉터리 트래버설로 RCE 시도. 응답 **404** 면 실패(패치됨)
  - 대응: 웹서버 패치 · 입력 필터링 · 웹루트 분리 · IPS 룰

> [!암기] 상태코드 빠른 해석
> 200 성공 · 301/302 리다이렉트 · 403 금지 · 404 없음 · 500 서버 오류 → 공격 성공 여부는 대개 **200 vs 403/404** 로 판단
