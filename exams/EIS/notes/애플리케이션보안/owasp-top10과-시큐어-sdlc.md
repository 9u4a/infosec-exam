## 한 줄 정의

웹 보안의 **전체 지도**다. 개별 취약점(SQLi·XSS 등)은 각 노트에 있고, 여기서는 *어떤 취약점들이 있고(OWASP Top 10) → 개발 단계 어디서 막고(시큐어 SDLC) → 어떤 틀로 위협을 찾는지(STRIDE)* 를 정리한다. 필기·실기 공통.

## OWASP Top 10 (2021)

| 순위 | 항목 | 핵심 |
|---|---|---|
| A01 | **취약한 접근 통제** | 권한 상승 · IDOR · 강제 브라우징 |
| A02 | **암호화 실패** | 평문 전송·저장 · 약한 알고리즘 · 하드코딩 키 |
| A03 | **인젝션** | SQLi · OS 명령 · LDAP · XPath · XSS |
| A04 | **안전하지 않은 설계** | 설계 단계의 위협 모델링 부재 |
| A05 | **보안 설정 오류** | 기본 계정 · 디렉터리 인덱싱 · 불필요 기능 · 상세 오류 |
| A06 | **취약·구식 컴포넌트** | 오래된 라이브러리 (Log4j · Struts) |
| A07 | **식별·인증 실패** | 약한 비밀번호 · 세션 고정 · 크리덴셜 스터핑 |
| A08 | **SW·데이터 무결성 실패** | 검증 없는 업데이트 · 안전하지 않은 역직렬화 · CI/CD 침해 |
| A09 | **로깅·모니터링 실패** | 로그 부재 · 탐지 지연 |
| A10 | **SSRF** | 서버가 신뢰하는 내부 리소스로 요청 유도 |

> [!함정] 2017 → 2021 변화
> **XXE 는 A05 에 흡수**, **XSS 는 A03(인젝션)에 통합**, **A04 · A08 · A10 신설.**

## 시큐어 SDLC / SDL

개발 생명주기 **각 단계에 보안 활동을 내재화**한다 (사후 조치보다 저비용).

| 단계 | 보안 활동 |
|---|---|
| **요구사항** | 보안 요구사항 정의 · 규제 식별 · 오·남용 사례(abuse case) |
| **설계** | **위협 모델링(STRIDE)** · 보안 아키텍처 검토 · 공격 표면 분석 |
| **구현** | **시큐어 코딩 가이드** · 코드 리뷰 · **SAST**(정적 분석) |
| **테스트** | **DAST**(동적 분석) · 퍼징 · 모의해킹 · IAST |
| **배포/운영** | 보안 설정 하드닝 · 취약점 스캔 · 침투 테스트 · 패치 관리 |
| **폐기** | 데이터 완전 삭제 · 계정·인증서 정리 |

모델: MS **SDL** · OWASP **SAMM** · BSIMM · **행안부 SW 개발보안 가이드**(전자정부)

## 위협 모델링 — STRIDE

| 위협 | 깨뜨리는 속성 |
|---|---|
| **S**poofing (위장) | 인증 |
| **T**ampering (변조) | 무결성 |
| **R**epudiation (부인) | 부인방지 |
| **I**nformation Disclosure (정보 노출) | 기밀성 |
| **D**enial of Service | 가용성 |
| **E**levation of Privilege (권한 상승) | 인가 |

절차: 자산 식별 → 아키텍처 분해(DFD) → 위협 도출(STRIDE) → 위험 평가(DREAD) → 대응

## 시큐어 코딩 핵심 원칙

- **모든 입력을 불신** — 서버 측 화이트리스트 검증, 정규화 후 검증
- **출력 인코딩**(컨텍스트별) · **파라미터 바인딩**(SQL·명령·XML)
- **최소 권한** · 안전한 기본값(fail-safe defaults) · 다중 방어(defense in depth)
- 민감정보 하드코딩 금지 · 안전한 난수·암호 API · 오류 메시지 최소화
