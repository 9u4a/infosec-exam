## TCP Wrapper (2-6)

유닉스 호스트 기반 접근제어(방화벽 룰). `libwrap` 을 사용하는 서비스(inetd/xinetd 계열, sshd 등)에 적용.

- `/etc/hosts.allow` : 허용 정책 (먼저 평가)
- `/etc/hosts.deny` : 거부 정책
- 평가 순서: allow → deny → (둘 다 없으면) 허용. `ALL: ALL` 을 deny에 넣고 allow에서 최소 허용.
- `tcpd` 데몬이 접근을 중계하며 `/var/log/secure` 에 로그.

## 루트킷에 장악된 시스템 — 신뢰할 수 없는 기본 명령어

`ps`, `ls`, `netstat`, `find` 등이 트로이목마로 교체될 수 있음 → 대체 수단으로 교차 확인.

| 목적 | 오염 가능 명령 | 대체 |
|---|---|---|
| 프로세스 목록 | `ps` | **`lsof`**, `/proc` 직접 탐색, `ls /proc` |
| 열린 파일/포트 | `netstat` | `lsof -i`, `ss` |
| 파일 목록 | `ls` | `echo *`, `find`(신뢰 매체) |

### 삭제된 실행 파일을 가진 은닉 프로세스 (15-12)

`ls -al /proc/<PID>/exe -> /path/backdoor (deleted)` 형태.
- 이유: 공격자가 프로세스 실행 후 실행 파일을 삭제 → 경로에는 파일이 없지만 프로세스는 살아있음.
- 복구: `cp /proc/<PID>/exe /tmp/sample` 로 바이너리 추출.
- 실행 인자 확인: `cat /proc/<PID>/cmdline`, `history`.

## 분석 명령·도구

- **strace**: 프로세스의 **시스템 콜** 추적 (`strace -e trace=open,read ...`). 바이너리의 컴파일 경로·행위로 트로이목마 식별. (ltrace는 라이브러리 콜)
- **정적 분석**: PEiD(패커 식별), IDA Pro(디스어셈블), YARA(시그니처 룰) — 파일 헤더·섹션·코드 패턴을 자동 분석
- **동적 분석**: Cuckoo Sandbox 등 격리 환경에서 실행 관찰
- **샌드박스(Sandbox)**: 가상화로 격리한 테스트 환경에서 악성 파일을 실행해 실제 시스템 피해를 막고 행위를 분석하는 기술 (32-12)
