## 한 줄 정의

유닉스 하드닝은 **인증(PAM) → 계정 정책(잠금·길이) → 접속 경로(root·r-command·telnet) → 커널 파라미터 → 패치** 순으로 묻는다. OS 별 파일 이름이 달라 **"어느 OS 의 어느 파일"** 을 짝으로 외워야 한다. {{23-7}} {{24-17}} {{6-6}} {{29-1}}

## PAM (Pluggable Authentication Module) {{23-7}} {{29-1}}

인증을 모듈로 분리한 프레임워크다. 설정은 `/etc/pam.d/`, 모듈은 `/lib/security/`.

| 관리 그룹 | 역할 |
|---|---|
| **auth** | 실제 인증 — 패스워드 확인·토큰 검증 |
| **account** | 계정 유효성 — 사용 권한·만료·접속 시간·호스트 제한 |
| **password** | 패스워드 변경 정책 (복잡도·재사용) |
| **session** | 세션 전후 처리 — 로그 기록·홈 마운트·자원 제한 |

제어 플래그:

| 플래그 | 동작 |
|---|---|
| `required` | 실패해도 **계속 진행**한 뒤 최종 실패 |
| `requisite` | 실패하면 **즉시** 실패 |
| `sufficient` | 성공하면 통과로 충분 |
| `optional` | 결과에 영향 없음 |

### 계정 잠금 — pam_tally / pam_faillock {{14-11}} {{18-15}}

```text
auth required /lib/security/pam_tally.so deny=5 unlock_time=120 no_magic_root reset
```

| 옵션 | 의미 |
|---|---|
| `deny=5` | 인증 5회 실패 시 **계정 잠금** |
| `unlock_time=120` | 마지막 실패 후 120초 뒤 자동 해제 |
| `no_magic_root` | root 는 잠금 **예외** |
| `reset` | 로그인 성공 시 실패 카운터 0 으로 |

설정 파일: `/etc/pam.d/system-auth` (RHEL) · `/etc/pam.d/common-auth` (Debian)

## OS 별 설정 파일 비교

### 패스워드 최소 길이 {{24-17}}

| OS | 파일 | 설정 |
|---|---|---|
| Solaris | `/etc/default/passwd` | `PASSLENGTH=8` |
| Linux | `/etc/login.defs` | `PASS_MIN_LEN 8` (+ `pam_pwquality` / `pam_cracklib` minlen) |
| AIX | `/etc/security/user` | `minlen=8` |
| HP-UX | `/etc/default/security` | `MIN_PASSWORD_LENGTH=8` |

### root 원격 접속 제한 {{6-6}}

| OS | 파일 | 방법 |
|---|---|---|
| Solaris | `/etc/default/login` | `CONSOLE=/dev/console` |
| AIX | `/etc/security/user` | root 스탠자에 `rlogin=false` |
| Linux | `/etc/securetty` | 허용 tty 만 나열 (원격 pts 제외) |
| 공통 (SSH) | `/etc/ssh/sshd_config` | `PermitRootLogin no` |

## 위험한 원격 접속 수단

### r-command 대응 {{24-14}} {{32-14}}

`rsh` · `rlogin` · `rexec` 는 인증 없는 **신뢰 기반 접속**이라 가급적 중지하고 SSH 로 대체한다. 불가피하면 `/etc/hosts.equiv` 와 `$HOME/.rhosts` 를:

1. 소유자를 **root(또는 해당 계정)** 로 — `chown root /etc/hosts.equiv`
2. 권한을 **600 이하** 로 — `chmod 600 ...`
3. 내용에서 **`+`**(모든 호스트·사용자 허용) 를 제거하고 필요한 호스트만 명시

### Telnet 배너 노출 {{28-18}}

접속 시 OS·커널 버전이 보이면 **CVE 매핑·익스플로잇**이 쉬워지고 통신도 평문이다.

- Telnet 중지 → **SSH** 사용
- 배너에서 버전 제거 (`/etc/issue` · `/etc/issue.net`)
- root 직접 로그인 차단

## ndd 커널 파라미터 (Solaris) {{9-13}}

| 명령 | 의미 | 막는 공격 |
|---|---|---|
| `ndd -set /dev/ip ip_forward_directed_broadcasts 0` | Directed Broadcast 포워딩 차단 | **Smurf** |
| `ndd -set /dev/tcp tcp_conn_req_max_q0 512` | SYN 대기 큐(backlog) 확대 | **SYN Flooding** |
| `ndd -set /dev/ip ip_forwarding 0` | IP 라우팅 비활성 | IP spoofing 경유 |

> [!팁] Linux 대응
> `/proc/sys/net/ipv4/...` 또는 `sysctl` — `tcp_max_syn_backlog` · `tcp_syncookies=1`

## 신규 보안장비 계정 관리 {{12-12}}

1. 기본 관리자 **계정명 변경**
2. 기본 패스워드를 복잡도 규칙에 맞게 변경
3. 계정별 **최소 권한** 부여 (역할 분리)
4. 불필요·미사용 계정 삭제·잠금
5. 세션 타임아웃 · 접속 IP 제한
6. 로그인 실패 잠금 · 감사 로그 활성화

## SW 패치 종류 {{27-9}}

| 종류 | 설명 |
|---|---|
| **핫픽스** (Hot Fix) | 즉시 교정이 필요한 주요 취약점용 **긴급 패치**, 서비스팩 이후 별도 배포 |
| **업데이트** (Update) | 문제 예방·해결을 위해 **정기 배포** |
| **서비스팩** (Service Pack) | 그간의 패치·핫픽스를 **누적해 묶은** 대규모 패치 |
| **패치 관리 시스템** (PMS) | 다수 시스템의 패치 배포·검증을 중앙 관리 |
