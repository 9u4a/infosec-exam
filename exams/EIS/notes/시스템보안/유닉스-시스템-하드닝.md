## 한 줄 정의

유닉스 하드닝은 **인증(PAM) → 계정 정책(잠금·길이) → 접속 경로(root·r-command·telnet) → 커널 파라미터 → 패치** 순으로 묻는다. OS 별 파일 이름이 달라 **"어느 OS 의 어느 파일"** 을 짝으로 외워야 한다. {{23-7}} {{24-17}} {{6-6}} {{29-1}}

## PAM (Pluggable Authentication Module) {{23-7}} {{29-1}}

인증을 모듈로 분리한 프레임워크다. 설정은 `/etc/pam.d/`, 모듈은 `/lib/security/`(64비트 RHEL 은 `/lib64/security/`, 배포판별 상이).

| 관리 그룹 | 역할 |
|---|---|
| **auth** | 실제 인증 — 패스워드 확인·토큰 검증 |
| **account** | 계정 유효성 — 사용 권한·만료·접속 시간·호스트 제한 |
| **password** | 패스워드 변경 정책 (복잡도·재사용) |
| **session** | 세션 전후 처리 — 로그 기록·홈 마운트·자원 제한 |

제어 플래그:

| 플래그 | 동작 |
|---|---|
| `required` | 실패해도 **계속 진행**한 뒤 최종 실패 |
| `requisite` | 실패하면 **즉시** 실패 |
| `sufficient` | 성공하면 통과로 충분 |
| `optional` | 결과에 영향 없음 |

### 계정 잠금 — pam_tally / pam_faillock {{14-11}} {{18-15}}

```text
auth required /lib/security/pam_tally.so deny=5 unlock_time=120 no_magic_root reset
```

| 옵션 | 의미 |
|---|---|
| `deny=5` | 인증 5회 실패 시 **계정 잠금** |
| `unlock_time=120` | 마지막 실패 후 120초 뒤 자동 해제 |
| `no_magic_root` | root 는 잠금 **예외** (시험 관용 표현) |
| `reset` | 로그인 성공 시 실패 카운터 0 으로 |

- `no_magic_root` 의 man 페이지 의미는 "root 가 호출해도 카운터 증가" 로 다르다
- root 계정까지 잠그는 옵션은 `even_deny_root` 다

> [!현행] pam_tally 는 기출 당시 기준
> pam_tally·pam_tally2 는 Linux-PAM 1.5 에서 제거됐다.
> 현행은 `pam_faillock.so` (`deny=5 unlock_time=120`, `/etc/security/faillock.conf`).

설정 파일: `/etc/pam.d/system-auth` (RHEL) · `/etc/pam.d/common-auth` (Debian)

## OS 별 설정 파일 비교

### 패스워드 최소 길이 {{24-17}}

| OS | 파일 | 설정 |
|---|---|---|
| Solaris | `/etc/default/passwd` | `PASSLENGTH=8` |
| Linux | `/etc/login.defs` | `PASS_MIN_LEN 8` (+ `pam_pwquality` / `pam_cracklib` minlen) |
| AIX | `/etc/security/user` | `minlen=8` |
| HP-UX | `/etc/default/security` | `MIN_PASSWORD_LENGTH=8` |

### root 원격 접속 제한 {{6-6}}

| OS | 파일 | 방법 |
|---|---|---|
| Solaris | `/etc/default/login` | `CONSOLE=/dev/console` |
| AIX | `/etc/security/user` | root 스탠자에 `rlogin=false` |
| Linux | `/etc/securetty` | 허용 tty 만 나열 (원격 pts 제외) |
| 공통 (SSH) | `/etc/ssh/sshd_config` | `PermitRootLogin no` |

- securetty 는 기출 당시 기준 정답이다
- 현행: pam_securetty 기반이라 SSH 엔 무효, 최신 배포판은 기본 미사용

## 위험한 원격 접속 수단

### r-command 대응 {{24-14}} {{32-14}}

`rsh` · `rlogin` · `rexec` 는 인증 없는 **신뢰 기반 접속**이라 가급적 중지하고 SSH 로 대체한다. 불가피하면 `/etc/hosts.equiv` 와 `$HOME/.rhosts` 를:

1. 소유자를 **root(또는 해당 계정)** 로 — `chown root /etc/hosts.equiv`
2. 권한을 **600 이하** 로 — `chmod 600 ...`
3. 내용에서 **`+`**(모든 호스트·사용자 허용) 를 제거하고 필요한 호스트만 명시

### Telnet · FTP 배너 노출 {{28-18}}

접속 시 OS·커널 버전이 보이면 **CVE 매핑·익스플로잇**이 쉬워지고 통신도 평문이다.

- Telnet 중지 → **SSH** 사용
- 배너에서 버전 제거 (`/etc/issue` · `/etc/issue.net`)
- root 직접 로그인 차단

FTP 도 같은 원리로 대응한다.

- FTP 대신 **SFTP**, 불가피하면 `/etc/ftpusers` 에 root 등록해 직접 로그인 차단
- vsftpd: `user_list` 에 root 등록 + `userlist_enable=YES` · `userlist_deny=YES`
- 배너: `ftpd_banner=경고문` 또는 `banner_file` 로 서비스명·버전 숨김

## ndd 커널 파라미터 (Solaris) {{9-13}}

| 명령 | 의미 | 막는 공격 |
|---|---|---|
| `ndd -set /dev/ip ip_forward_directed_broadcasts 0` | Directed Broadcast 포워딩 차단 | **Smurf** |
| `ndd -set /dev/tcp tcp_conn_req_max_q0 512` | SYN 대기 큐(q0) 크기를 512 로 설정 | **SYN Flooding** |
| `ndd -set /dev/ip ip_forwarding 0` | IP 라우팅 비활성 | 라우터로 악용(경유) 방지 |

> [!팁] Linux 대응
> `/proc/sys/net/ipv4/...` 또는 `sysctl` — `tcp_max_syn_backlog` · `tcp_syncookies=1`

## 신규 보안장비 계정 관리 {{12-12}}

1. 기본 관리자 **계정명 변경**
2. 기본 패스워드를 복잡도 규칙에 맞게 변경
3. 계정별 **최소 권한** 부여 (역할 분리)
4. 불필요·미사용 계정 삭제·잠금
5. 세션 타임아웃 · 접속 IP 제한
6. 로그인 실패 잠금 · 감사 로그 활성화

## SW 패치 종류 {{27-9}}

| 종류 | 설명 |
|---|---|
| **핫픽스** (Hot Fix) | 즉시 교정이 필요한 주요 취약점용 **긴급 패치**, 서비스팩 이후 별도 배포 |
| **업데이트** (Update) | 문제 예방·해결을 위해 **정기 배포** |
| **서비스팩** (Service Pack) | 그간의 패치·핫픽스를 **누적해 묶은** 대규모 패치 |
| **패치 관리 시스템** (PMS) | 다수 시스템의 패치 배포·검증을 중앙 관리 |

## 패스워드 크래킹 · 감사 · sudo

### 크래킹 기법

| 기법 | 원리 |
|---|---|
| **사전 공격** | 단어 사전·유출 비밀번호 목록을 차례로 대입 |
| **무차별 대입** | 가능한 모든 문자 조합을 시도 (길이가 길수록 급증) |
| **레인보우 테이블** | 미리 계산한 해시 체인 표로 해시 → 평문 역추적 |
| **크리덴셜 스터핑** | 다른 곳에서 유출된 ID·PW 쌍을 그대로 대입 (재사용 악용) |

크리덴셜 스터핑 상세는 [🔗 크리덴셜 스터핑 (Credential Stuffing)](#/note/%EB%B0%98%EB%B3%B5%EC%B6%9C%EC%A0%9C%2F%ED%81%AC%EB%A6%AC%EB%8D%B4%EC%85%9C-%EC%8A%A4%ED%84%B0%ED%95%91) 참고.

| 도구 | 방식 |
|---|---|
| **John the Ripper** · **hashcat** | **오프라인** — 탈취한 해시(shadow 등)를 직접 크래킹 |
| **Hydra** | **온라인** — SSH·FTP·웹 로그인에 대입 시도 |

- 대응: 솔트 + 느린 해시(yescrypt · SHA-512 반복) → 오프라인 크래킹 비용 증가
- 대응: 계정 잠금(pam_faillock) · MFA → 온라인 대입 차단

### auditd — 커널 감사

```bash
auditctl -w /etc/passwd -p wa -k passwd_change   # 쓰기(w)·속성변경(a) 감시
ausearch -k passwd_change                        # 키로 감사 로그 검색
```

- 영구 규칙은 `/etc/audit/rules.d/*.rules`, 로그는 `/var/log/audit/audit.log`
- `-p` 권한: `r` 읽기 · `w` 쓰기 · `x` 실행 · `a` 속성 변경

### sudoers

- `/etc/sudoers` 는 **`visudo` 로만 편집** — 저장 전 문법 검사로 잠김 사고 방지
- `%wheel ALL=(ALL) ALL` — wheel 그룹에 모든 명령을 root 로 허용
- `NOPASSWD:` 남용 시 계정 탈취 = 즉시 root, 꼭 필요한 명령에만 한정
- sudo 사용 기록: `/var/log/secure`(RHEL) · `/var/log/auth.log`(Debian)

> [!함정] 솔트가 막는 것은 레인보우 테이블뿐
> 솔트는 미리 계산한 표를 무력화하지만, 계정별 **사전 공격·무차별 대입**은 그대로 가능하다. 그래서 느린 해시와 강한 비밀번호가 함께 필요하다.
