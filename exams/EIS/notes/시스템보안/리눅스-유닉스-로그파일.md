## 한 줄 정의

침해 조사의 출발점은 로그다. 유닉스 로그는 **무엇을 기록하는가(파일)** 와 **어떻게 보는가(명령)** 를 짝으로 외워야 한다. 대부분 **바이너리**라 `cat` 으로 볼 수 없다. {{1-4}} {{1-8}} {{14-6}} {{27-5}}

## 핵심 로그 한눈에

| 파일 | 경로 | 기록 내용 | 조회 |
|---|---|---|---|
| **utmp** | `/var/run/utmp` | **현재** 로그인 중인 사용자 | `who` `w` `users` |
| **wtmp** | `/var/log/wtmp` | 로그인·로그아웃·재부팅 **누적** 이력 | `last` |
| **btmp** | `/var/log/btmp` | 로그인 **실패** | `lastb` |
| **lastlog** | `/var/log/lastlog` | 사용자별 **마지막** 로그인 시각·출처 | `lastlog` |
| **pacct** | `/var/account/pacct` | 사용자가 실행한 **모든 명령** | `lastcomm` `acctcom` |
| xferlog | `/var/log/xferlog` | FTP 전송 | `cat` |
| messages | `/var/log/messages` | 시스템 전반 (커널·데몬) | `cat` `dmesg` |
| secure | `/var/log/secure` | 인증 (원격 접속·sudo) | `cat` |

Solaris 전용: **sulog**(`/var/adm/sulog`, `su` 사용 내역) · **loginlog**(`/var/adm/loginlog`, 연속 로그인 실패 기본 5회) — 둘 다 텍스트.

> [!함정] 헷갈리는 세 가지
> - **wtmp vs lastlog**: wtmp 는 *모든* 로그인 누적, lastlog 는 사용자별 *가장 최근 1건*
> - **utmp · wtmp · btmp · pacct 는 바이너리**: 전용 명령(`who`·`last`·`lastb`·`lastcomm`)이 필요하다
> - **Solaris 실패 로그인 = loginlog(텍스트)**, Linux 는 btmp(바이너리)

침해 징후: 로그 삭제·조작. `wtmp` 를 변조하면 `last` 출력에 **공백이나 역순**이 나타난다.

### Solaris ↔ Linux 대응

| 용도 | Solaris | Linux |
|---|---|---|
| 최근 로그인 | `lastlog` | `lastlog` |
| 실패 로그인 | `loginlog` | `btmp` |
| su 기록 | `sulog` | `secure` / `auth.log` 에 통합 |

## syslog 메시지 구조 {{23-5}}

`/var/log/messages` 의 한 줄은 보통 5개 항목이다.

```text
Mar 29 14:23:57   alex     kernel:    [295087.236116]   Call Trace: ...
  ①생성일시       ②호스트명  ③프로세스명  ④프로세스 번호(PID)   ⑤상세 메시지
```

③은 `kernel` · `systemd[1]` · `sshd[2345]` 처럼 **로그를 남긴 프로세스명**이고, 대괄호 안이 PID 다.

### rsyslog 설정 — `/etc/rsyslog.conf`

형식은 `facility.priority   action` 이다.

| 구성 | 값 |
|---|---|
| **facility** | auth · authpriv · cron · daemon · kern · mail · syslog · local0~7 |
| **priority** (높은 → 낮은) | emerg > alert > crit > err > warning > notice > info > debug |

예: `authpriv.*  /var/log/secure` · `*.info;mail.none  /var/log/messages`
