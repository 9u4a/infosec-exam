## 한 줄 정의

엔드포인트(PC·서버·모바일) 보안은 **막기(EPP) → 잡아내기(EDR) → 새나가지 않게(DLP·DRM) → 모바일 통제(MDM)** 로 층을 쌓는다. 각 솔루션이 **무엇을 지키는지**를 구분하는 게 핵심이다. {{16-5}} {{24-8}} {{29-4}}

## EPP vs EDR {{16-5}}

> [!시험] 2027 실기 출제기준 항목 1-4-9
> 「보안장비 및 네트워크 장비별 보안특성 파악하기」 — "EDR 및 EPP(백신) 솔루션과의 차이를 이해할 수 있다." (2027년 시행 출제기준)

**EDR 정의**(미 OMB M-22-01): 엔드포인트 데이터를 **실시간·연속으로 모니터링·수집**하고, **규칙 기반 자동 대응·분석** 기능을 결합한 것. 다형성 악성코드·APT·피싱 같은 고도화 위협에 필요한 가시성을 준다.

| | **EPP** | **EDR** |
|---|---|---|
| 목적 | **예방** — 알려진 위협 차단 | **탐지·대응** — 침입 후 행위 포착 |
| 방식 | 시그니처 · 평판 · 정적 휴리스틱 | 행위 분석 · 이상 탐지 · 이벤트 상관 |
| 대응 | 격리(quarantine)·삭제 | 단말 망 격리 · 프로세스 종료 · 원격 조사 |
| 한계 | 맞춤형·신종·정상 도구 악용에 약함 | 경보가 많고 분석 인력 필요 |

- 시험 답은 위 전통적 구분(EPP=예방, EDR=탐지·대응)으로 쓴다
- 다만 Gartner 정의상 EPP 제품이 EDR 기능을 통합하는 추세다 (2차 인용)
- 확장형: **XDR** = 여러 보안 제품 데이터를 자동 수집·상관하는 통합 탐지·대응 (Gartner, 2차)
- **MDR** = 원격 SOC(관제) 서비스 + 단말 격리·계정 잠금 같은 봉쇄 조치 (Gartner, 2차)

### 시그니처 백신의 한계 (NIST SP 800-83)

- 시그니처 = 알려진 악성코드 특성 집합 → **알려진 것과 일부 변종**만 식별
- 피해자마다 다른 맞춤형 공격엔 시그니처 기반 통제가 **따라가지 못한다**
- 그래서 여러 탐지 기법을 겹치는 **다층 방어**를 권고한다
- APT 는 수주~수년 잠복, 제거하려면 OS 재설치·백업 복원이 필요한 경우가 많다
- 정상 도구 악용(LOTL)·파일리스는 파일 시그니처가 없어 행위 기반 탐지가 필요

### EDR 수집 텔레메트리 (MITRE ATT&CK 데이터 컴포넌트)

| 수집 대상 | ATT&CK 데이터 컴포넌트 |
|---|---|
| 프로세스 생성·부모-자식 관계 | Process Creation (DC0032) |
| 명령줄·스크립트 실행 | Command Execution (DC0064) |
| 파일 생성·변경 | File Creation / Modification |
| 레지스트리 키 변경 | Windows Registry Key Modification |
| 네트워크 연결 생성 | Network Connection Creation |
| DLL 등 모듈 로드 | Module Load (DC0016) |

### EDR 대응 기능 (제품 문서 예: MS Defender)

| 기능 | 내용 |
|---|---|
| **단말 격리** | 망에서 분리 → 공격자 제어·유출·측면 이동 차단 |
| **프로세스 중지·파일 격리** | 실행 중 프로세스 종료 + 파일 격리 + 지속성 레지스트리 삭제 |
| **앱 실행 제한** | 허용된 프로그램만 실행 |
| **라이브 응답** | 원격 셸로 포렌식 수집·스크립트 실행 |
| **조사 패키지 수집** | 네트워크 연결·DNS 캐시 등 단말 상태 수집 |
| **원격 백신 검사** | 감염 단말 즉시 스캔 |

- 위 목록은 Microsoft Defender for Endpoint 공식 문서의 대응 동작 기준
- **롤백**(변경 되돌리기)은 표준 정의가 아니라 **제품별 기능**이다
- 위협 헌팅·타임라인 분석도 EDR 의 대표 활용이다

## DLP — 내부 정보 유출 방지 {{24-8}} {{29-4}}

**PC 에이전트 + 네트워크 센서**로 이동 경로를 감시·차단·기록한다.

| 배치 | 통제 대상 |
|---|---|
| **엔드포인트 DLP** (에이전트) | 오프라인 · USB · 인쇄 |
| **네트워크 DLP** (게이트웨이) | 메일 · 웹 |
| **스토리지 DLP** | 서버에 저장된 데이터 스캔 |

- 감시 채널: USB · 메일 첨부 · 메신저 · **웹 파일 업로드** · 인쇄 · 화면 캡처
- **HTTPS** 같은 암호화 통신도 에이전트/프록시에서 복호화해 검사
- 콘텐츠 인식: 정규식(주민번호·카드번호) · 지문(fingerprint) · 키워드 · 문서 분류 태그

### 인접 솔루션

| 솔루션 | 역할 |
|---|---|
| **DRM** | 문서 **자체를 암호화**하고 열람·편집·인쇄·기간 권한 부여 → 밖으로 나가도 무력 |
| **CASB** | SaaS 사용 가시성·통제 (섀도우 IT 탐지, 업로드 차단) |
| **NAC** | 접속 단말 **인증 + 무결성 점검**(백신·패치), 미달 시 격리·치료 |
| **워터마킹** | 출력물·화면에 사용자·시각 표시 → 유출 시 추적 |
| **EFS / BitLocker** | 디스크·파일 암호화 (분실·도난 대비) |

## MDM · BYOD 모바일 보안 {{22-13}} {{30-14}}

| 기술 | 개념 |
|---|---|
| **MDM** | **기기 전체**를 원격 관리 — 정책 적용 · 앱 화이트리스트 · 원격 잠금/**삭제(wipe)** · 탈옥·루팅 탐지 · 카메라 제어 |
| **MAM** | 업무용 **앱 단위** 관리·배포·삭제 (개인 영역은 간섭 안 함) |
| **컨테이너화** | 한 기기 안에서 업무/개인 영역을 **논리적으로 분리**, 업무 데이터는 암호화 컨테이너 저장·상호 복사 차단 |
| **모바일 가상화** | 업무용·개인용 **OS(가상 머신)** 를 각각 구동해 완전 격리 |
| **MCM** | 업무 문서의 안전한 배포·열람(뷰어) 통제 |

- BYOD 의 고민: **사생활 침해 vs 통제 · 분실·도난 · 비인가 앱** → 컨테이너화가 절충안
- 통합 관리: **EMM**(MDM+MAM+MCM), 더 넓게 **UEM**(PC 까지)

> [!함정] 컨테이너화 vs 모바일 가상화
> 둘 다 업무/개인 분리지만, 컨테이너화는 **한 OS 안의 논리적 분리**, 모바일 가상화는 **OS 를 둘 띄우는 완전 격리**다.
