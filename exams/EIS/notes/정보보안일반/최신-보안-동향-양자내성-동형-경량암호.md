## 한 줄 정의

- **양자내성암호(PQC)**: 양자컴퓨터로도 풀기 어려운 수학 문제 위에 세운 공개키 암호
- **동형암호(HE)**: 암호문을 복호화하지 않고 그대로 연산하는 암호
- **경량암호**: 회로 크기·전력·메모리를 줄여 저사양 기기용으로 설계한 암호

## 양자내성암호 (PQC)

### 양자 위협 — Shor · Grover · HNDL

| 양자 알고리즘 | 공격 대상 | 결과 |
|---|---|---|
| **Shor** | 소인수분해·이산대수 (RSA·DH·ECC) | 공개키 암호 무력화 → 교체 필요 |
| **Grover** | 대칭키·해시 전수조사 | 가속은 되지만 키 길이로 대응 가능 |

- NIST FAQ: Grover 로 공격자는 "최대 2배 긴 키"까지 공격할 수 있을 수 있다
- 그러나 NIST 는 "AES 128 will remain secure for decades" 라고 본다
- NIST: AES 128·192·256 을 계속 써도 된다 (IR 8547: 각각 PQ 보안 범주 1·3·5)
- **HNDL**(harvest now, decrypt later): 지금 암호문을 수집해 두고 양자컴퓨터로 나중에 해독
- IR 8547 은 HNDL 을 전환이 시급한 주된 이유로 명시한다 → 장기 기밀 데이터부터 전환

### NIST PQC 표준

| 표준 (발표) | 이름 | 원 제출 | 용도 | 안전성 기반 |
|---|---|---|---|---|
| **FIPS 203** (2024.8.13) | ML-KEM | CRYSTALS-KYBER | 키 캡슐화(KEM) | 모듈 격자 MLWE |
| **FIPS 204** (2024.8.13) | ML-DSA | CRYSTALS-Dilithium | 전자서명 | MLWE + SelfTargetMSIS |
| **FIPS 205** (2024.8.13) | SLH-DSA | SPHINCS+ | 전자서명 | 해시 함수 역상 저항성 |
| FIPS 206 (개발 중) | FN-DSA | FALCON | 전자서명 | 격자 (FALCON 계열, 원문 미확인) |
| HQC (2025.3.11 선정) | HQC-KEM | HQC | KEM (ML-KEM 백업) | 오류정정부호(코드) |

- 파라미터: ML-KEM-512/768/1024, ML-DSA-44/65/87 (보안 범주 2/3/5)
- **FIPS 206**: IR 8547 최종본(2026.10)에도 "개발 중" — 2026-11 현재 미발행
- **HQC**: 격자와 다른 수학(코드) 기반 백업. NIST 는 최종 표준을 2027년으로 예상
- 추가 전자서명 공모: 2026.5 IR 8610 으로 후보 9개가 3라운드 진출

### NIST IR 8547 전환 일정

IR 8547 「Transition to Post-Quantum Cryptography Standards」 — 초안 2024.11.12 → **최종 2026.10.27**.

| 구분 | 2030년 이후 | 2035년 이후 |
|---|---|---|
| RSA·ECDSA·EdDSA (FIPS 186 서명) | Deprecated (사용 가능·위험 수용) | Disallowed (금지) |
| DH·MQV·ECDH·RSA 키 설정 (SP 800-56A/B) | Deprecated | Disallowed |

- 종전 SP 800-57 의 "112비트 공개키 2031.1.1 금지" 계획을 위 일정으로 대체
- 112비트 대칭 표준은 2030년 금지, SHA-1 은 2030 이후 FIPS 검증 모듈에서 금지
- 미 연방 고민감 시스템은 더 이르다: 키 설정 2030.12.31 · 서명 2031.12.31 까지 PQC

## 동형암호 (Homomorphic Encryption)

### 원리와 구분

암호문끼리 연산한 뒤 복호화하면 평문끼리 연산한 결과가 나온다. 데이터를 클라우드·AI 에 맡겨도 평문을 보여주지 않는다.

| 구분 | 가능한 연산 | 예 |
|---|---|---|
| **PHE** (부분 동형) | 덧셈 **또는** 곱셈 한 가지만, 횟수 무제한 | RSA(곱셈), Paillier(덧셈) |
| **SHE** (준 동형) | 덧셈·곱셈 둘 다, 그러나 제한된 횟수 | 잡음 누적으로 연산 깊이 제한 |
| **FHE** (완전 동형) | 덧셈·곱셈 모두 무제한 → 임의 연산 | BGV·BFV·CKKS·TFHE |

- RSA 곱셈 동형: E(m1)·E(m2) = (m1·m2)^e mod n
- **Gentry (STOC 2009)**: 이상 격자 기반 최초 FHE, 잡음을 줄이는 **부트스트래핑** 제시

### 주요 FHE 스킴

| 스킴 | 연산 대상 | 출처 |
|---|---|---|
| **BGV** | 정수(모듈러) 정확 연산 | Brakerski·Gentry·Vaikuntanathan |
| **BFV** | 정수(모듈러) 정확 연산 | Fan·Vercauteren (Brakerski 스킴 이식) |
| **CKKS** | **근사 실수** 연산 (AI·통계에 적합) | Cheon·Kim·Kim·Song, ASIACRYPT 2017 |
| **TFHE** | 비트·게이트 단위, 빠른 부트스트래핑 | Chillotti 외, J. Cryptology 2019 |

- 국산 **HEaaN**: 크립토랩의 CKKS 기반 완전동형암호 라이브러리

### 표준 진행 (2026-11)

| 표준 | 내용 | 상태 |
|---|---|---|
| ISO/IEC 18033-6:2019 | 부분 동형: 지수 ElGamal · Paillier | 발행 (2019.5) |
| ISO/IEC 28033-1 | FHE 일반 (General) | FDIS 단계 |
| ISO/IEC 28033-2 | 모듈러 정수 정확 연산 (BGV·BFV) | DIS 투표 종료 |
| ISO/IEC 28033-3 | 근사 수 연산 (CKKS 계열) | 발행 절차 중 |

### 한계

- 평문 연산보다 **매우 느리다** (특히 곱셈·부트스트래핑)
- 암호문 크기가 평문보다 크게 **팽창**한다 (정량 수치는 스킴·파라미터마다 다름)
- 연산할수록 잡음이 쌓여 부트스트래핑이 필요하다

## 경량암호 (Lightweight Cryptography)

센서·RFID·스마트카드 같은 저전력·저메모리 기기를 위해 회로 크기·전력·메모리를 줄인 암호다.

### NIST SP 800-232 — Ascon

2025.8.13 최종 발표. 「Ascon-Based Lightweight Cryptography Standards for Constrained Devices」

| 함수 | 기능 |
|---|---|
| **Ascon-AEAD128** | 인증 암호화(AEAD) — 기밀성 + 무결성 동시 |
| **Ascon-Hash256** | 해시 함수 |
| **Ascon-XOF128** | 확장 출력 함수(XOF) |
| **Ascon-CXOF128** | 사용자 지정(customized) XOF |

- IR 8547: Ascon-AEAD128 = 고전 128비트, PQ 보안 범주 1

### 국산 경량 블록암호

| 알고리즘 | 블록 | 키 | 라운드 | 구조 · 표준 |
|---|---|---|---|---|
| **LEA** | 128비트 | 128/192/256 | 24/28/32 (확인 필요) | ARX · ISO/IEC 29192-2:2019 수록 |
| **HIGHT** | 64비트 | 128비트 | 32 (확인 필요) | ISO/IEC 18033-3:2010 수록 (64비트 블록) |
| **CHAM** | 64/128비트 | 128/256 | 88/112/120 (확인 필요) | ARX · 국내 표준 번호 확인 필요 |

- **ARX** = 덧셈(Addition)·회전(Rotation)·XOR 만 사용 → S-box 없이 작고 빠름
- HIGHT: CHES 2006 발표, USN·RFID 대상, 0.25μm 공정 3048 게이트
- CHAM-64/128·128/128·128/256 = 블록/키 비트. 2019 개정판(Revised CHAM)에서 라운드 증가
- LEA 라운드 수(24/28/32)·KS X 3246 번호는 확인 필요

### 국제 표준 ISO/IEC 29192-2:2019 (경량 블록암호)

| 알고리즘 | 블록 | 키 |
|---|---|---|
| PRESENT | 64비트 | 80 / 128 |
| CLEFIA | 128비트 | 128 / 192 / 256 |
| **LEA** (국산) | 128비트 | 128 / 192 / 256 |

- SIMON·SPECK(NSA 제안)은 29192-2 추가가 **2018.4 ISO 에서 거부**됨 (언론 보도 기준)

## 세 기술 비교

| | 양자내성암호 | 동형암호 | 경량암호 |
|---|---|---|---|
| 해결 문제 | 양자컴퓨터의 공개키 해독 | 처리 중 데이터 노출 | 저사양 기기의 자원 부족 |
| 핵심 | 격자·해시·코드 기반 난제 | 암호문 상태로 연산 | 작은 회로·ARX·AEAD |
| 대표 | ML-KEM · ML-DSA · SLH-DSA | BGV · BFV · CKKS · TFHE | Ascon · LEA · HIGHT · CHAM |
| 표준 | FIPS 203/204/205 | ISO/IEC 18033-6 · 28033 | SP 800-232 · ISO/IEC 29192-2 |
| 국내 | KpqC 4종 | HEaaN | LEA · HIGHT · CHAM |

> [!함정] 양자컴퓨터는 모든 암호를 깨지 않는다
> 치명적인 쪽은 **공개키**(Shor). 대칭키·해시는 Grover 로 가속될 뿐이고, NIST 는 AES-128 도 계속 사용 가능하다고 본다. "AES-256 필수"는 NIST 공식 입장이 아니다.

> [!함정] 날짜·상태 혼동
> 확정 PQC FIPS 는 **203·204·205 세 개뿐**(2024.8.13). FIPS 206(FN-DSA)·HQC 는 아직 표준 미발행. IR 8547 은 2026.10 **최종본**이며 2030 = Deprecated, 2035 = Disallowed.

> [!함정] 동형암호 표준의 ElGamal 은 "지수 ElGamal"
> ISO/IEC 18033-6 의 ElGamal 은 지수(Exponential) ElGamal 로 덧셈 동형이다. 경량암호도 "약한 암호"가 아니라 자원을 줄인 암호다.

> - 국산 경량 블록암호 LEA·HIGHT·CHAM 의 블록 크기 구분
