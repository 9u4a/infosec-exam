## 한 줄 정의

**해시**는 *키 없는 지문*, **MAC** 은 *비밀키가 들어간 지문*, **전자서명**은 *공개키가 들어간 지문*이다. 키가 붙을수록 **인증 → 부인방지**까지 강해진다. 여기에 *키를 어떻게 관리·분배하는가* 가 이어진다. `암호학-기초` 의 확장이며 필기·실기 공통이다.

## 해시함수

### 요구 조건

| 성질 | 의미 |
|---|---|
| **압축성** | 임의 길이 입력 → 고정 길이 출력 |
| **효율성** | h(x) 계산이 빠름 |
| **역상 저항성** (일방향성) | h(x) = y 일 때 y 로부터 x 를 찾기 불가 |
| **제2 역상 저항성** (약한 충돌 저항성) | x 가 주어질 때 h(x) = h(x′), x′ ≠ x 인 x′ 찾기 불가 |
| **충돌 저항성** (강한 충돌 저항성) | h(x) = h(x′) 인 임의의 쌍 (x, x′) 찾기 불가 |

### 생일 공격 (Birthday Attack)

n 비트 해시의 충돌을 찾는 데 약 **2^(n/2)** 번의 시도면 충분하다 (생일 역설).

> [!함정] MD5 가 취약한 이유
> 128비트 해시(MD5)의 충돌 저항성은 실질 **64비트** 다. 안전한 해시는 **256비트 이상**(SHA-256)을 권장한다.

### 주요 알고리즘

| 알고리즘 | 출력 | 상태 |
|---|---|---|
| **MD5** | 128비트 | **충돌 발견 (2004) — 사용 금지** |
| **SHA-1** | 160비트 | **충돌 발견 (2017, SHAttered) — 폐기** |
| **SHA-2** (224/256/384/512) | 224~512 | 안전, 현재 표준 |
| **SHA-3** (Keccak) | 224~512 | 스펀지 구조, SHA-2 대안 |
| **HAS-160** | 160비트 | 국산 (KCDSA 용) |
| RIPEMD-160 | 160비트 | 비트코인 주소 등 |

비밀번호 저장은 일반 해시가 아니라 **bcrypt / scrypt / Argon2 / PBKDF2** (솔트 + 의도적 반복)를 쓴다.

## MAC (메시지 인증 코드)

메시지 + **비밀키**로 만든 인증 태그다 → **무결성 + (송신자) 인증**. 키를 양쪽이 모두 가지므로 **부인방지는 ✗**.

| 종류 | 방식 |
|---|---|
| **HMAC** | 해시 기반 — `H(K⊕opad ‖ H(K⊕ipad ‖ M))`. 가장 널리 쓰임 |
| **CMAC / CBC-MAC** | 블록 암호(AES) 기반 |
| **GMAC** | 갈루아 필드 기반, GCM 모드의 인증부 |

**AEAD** (인증 암호): 암호화 + 무결성을 한 번에 — AES-GCM · ChaCha20-Poly1305

> [!암기] 해시 < MAC < 전자서명
> **해시** (키 없음, 무결성만) → **MAC** (대칭키, 인증, 부인방지 ✗) → **전자서명** (공개키, 부인방지 ✓, 느림)

## 키 관리

### 생명주기

> 생성 → 분배(전달) → 저장 → 사용 → 갱신(교체) → 폐기(파기) → 복구/보관

- **키 길이**: 대칭 128비트+ · RSA 2048비트+ · ECC 256비트+
- **키 분리 원칙**: 용도별로 다른 키 (암호화 키 ≠ 서명 키 ≠ KEK)
- **KEK** (Key Encrypting Key): 데이터 암호화 키(DEK)를 다시 암호화해 보관
- **키 위탁** (Key Escrow): 키를 신뢰기관에 분할 보관 → 합법적 감청·복구 (프라이버시 논란)
- **HSM**: 키 생성·저장·연산을 전용 하드웨어에서 (변조 방지)

### 키 분배 프로토콜

| 프로토콜 | 특징 |
|---|---|
| **KDC 방식** | 중앙 서버가 세션키 분배. Kerberos 의 기반. KDC 가 SPOF |
| **Needham-Schroeder** | KDC 기반 세션키 분배 + 상호 인증. **재전송 공격에 취약** (옛 세션키 재사용) |
| **Kerberos** | Needham-Schroeder + **타임스탬프**로 재전송 방지 (→ 접근통제-모델) |
| **Diffie-Hellman** | KDC 없이 두 당사자가 키 합의 (인증 필요) |
| **공개키 기반 분배** | 상대 공개키로 세션키를 암호화해 전송 |

## 난수 생성

| 종류 | 특징 |
|---|---|
| **PRNG** (의사난수) | 시드로부터 결정적 생성 → 시드가 노출되면 예측 가능 |
| **CSPRNG** (암호학적 안전) | 다음 비트 예측 불가, 역추적 불가. `/dev/urandom` · CTR_DRBG |

약한 난수 → 키·IV·논스·세션 ID 가 예측됨 → **심각한 취약점**이다.
