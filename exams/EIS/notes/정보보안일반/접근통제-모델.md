## 한 줄 정의

접근통제는 **"누가(주체) 무엇에(객체) 어떻게 접근하는가"** 를 정하는 일이며, 시험은 *정책 모델(DAC/MAC/RBAC) → MAC 세부 모델(BLP/Biba) → 식별·인증·인가 → 생체인증 → SSO/Kerberos* 순으로 묻는다. {{3-4}} {{11-2}} {{14-1}} {{14-13}} {{20-4}} {{27-1}}

## 정책 모델 — DAC / MAC / RBAC

| 모델 | 기준 | 특징 | 취약점 |
|---|---|---|---|
| **DAC** (임의적) | 신원 (**소유자 재량**) | 소유자가 권한 부여/회수, 대부분 OS 기본 | 트로이목마·권한 전파에 약함 |
| **MAC** (강제적) | **보안 등급(레이블)** | 시스템이 주체·객체 등급을 강제 비교, 소유자도 재량 없음 (보안 OS·군) | 유연성 낮음, 구현 복잡 |
| **RBAC** (역할 기반) | **역할(직무)** | 사용자 → 역할 → 권한 매핑, 대규모 조직에 효율, 최소권한·직무분리 적용 용이 | — |

| | 권한 주체 | 정책 변경 | 대표 예 | 시험 문장 |
|---|---|---|---|---|
| DAC | 객체 **소유자** | 소유자 재량 | UNIX 파일 권한, ACL | "소유자가 자신의 판단으로 권한 부여" |
| MAC | **시스템(관리자)** | 소유자 불가, 중앙 강제 | SELinux, 군용 보안 OS | "모든 객체에 보안등급(레이블) 부여, 규칙 강제" |
| RBAC | **역할 관리자** | 역할–권한 매핑 | ERP, 대규모 조직 | "직무(역할)에 따라 권한 부여, 인사이동 시 역할만 변경" |

## MAC 세부 모델

| 모델 | 초점 | 규칙 |
|---|---|---|
| **BLP** (Bell-LaPadula) | **기밀성** | 단순보안 **no read up** · `*`-속성 **no write down** → 기밀의 하향 유출 차단. 강한 `*`-속성은 같은 등급만 쓰기 |
| **Biba** | **무결성** | **no read down** (하위 무결성 읽기 금지) · **no write up** (상위 무결성 쓰기 금지) → 저품질 정보의 상향 오염 차단 |
| **Clark-Wilson** | 무결성 (상업용) | 정형화된 트랜잭션 · **직무 분리** · IVP(검증 절차) + TP(변환 절차)를 통해서만 CDI(제약 데이터) 접근 |
| **Chinese Wall** (Brewer-Nash) | 이해충돌 방지 | 이미 접근한 회사와 **경쟁 관계** 회사의 데이터 접근 차단 (접근 이력에 따라 동적) |

> [!암기] 방향 외우기
> **BLP = 기밀성 = 위로 못 읽고 아래로 못 쓴다** (비밀은 위에서 아래로 안 샌다)
> **Biba = 무결성 = 아래를 못 읽고 위로 못 쓴다** (오염은 아래에서 위로 안 간다)

- BLP 한계: **무결성·가용성 미고려** · 은닉 채널(covert channel) · 등급 하향(declassification) 미규정
- **Lattice(격자) 모델**: 등급 + 카테고리(부서)의 지배관계를 격자로 표현 — BLP·Biba 의 수학적 기반

### RBAC 심화

| 단계 | 내용 |
|---|---|
| RBAC0 | 기본 (사용자–역할–권한, 세션) |
| RBAC1 | + **역할 계층** (상위 역할이 하위 역할 권한 상속) |
| RBAC2 | + **제약** (정적 직무분리 SoD, 상호배타 역할, 최대 인원) |
| RBAC3 | RBAC1 + RBAC2 통합 |

**정적 SoD** = 역할 **할당 시점**에 상충 역할 동시 부여 금지 · **동적 SoD** = 한 **세션**에서 동시 활성화 금지

확장: **ABAC**(속성 기반 — 주체·객체·환경 속성으로 정책 판단, 가장 유연) · PBAC · 혼합

## 식별 · 인증 · 인가 · 책임추적성

| 단계 | 의미 | 예 |
|---|---|---|
| **식별** | 나는 누구다 주장 | 아이디 입력 |
| **인증** | 그 주장이 참임을 증명 | 비밀번호 · OTP · 지문 |
| **인가** | 인증된 주체에게 자원 접근 권한 부여 | 권한 검사 (ACL) |
| **책임추적성** | 행위를 특정 주체에 연결·기록 | 감사 로그 · 부인방지 |

### 인증 요소

| 유형 | 예 | 약점 |
|---|---|---|
| **지식** (SYK) | 비밀번호 · PIN · 패턴 | 추측·유출·재사용 |
| **소유** (SYH) | OTP 토큰 · 스마트카드 · 공인인증서 · 휴대폰 | 분실·도난·복제 |
| **존재** (SYA) | 지문 · 홍채 · 정맥 · 얼굴 · 음성 | 위조·오인식, 변경 불가 |
| (행위) | 서명 형태 · 타이핑 리듬 · 걸음걸이 | 정확도 낮음 |
| (위치) | GPS · IP 기반 | 보조 수단 |

> [!함정] 다요소 인증은 "서로 다른 유형"
> 2요소/다요소 인증은 **서로 다른 유형 2개 이상**이다. **비밀번호 + PIN = 지식 2개 → 다요소 아님.**

### 생체인증 정확도

| 지표 | 의미 | 낮을수록 |
|---|---|---|
| **FAR** (오수용률, Type II) | 타인을 본인으로 잘못 승인 | **보안**이 강함 |
| **FRR** (오거부율, Type I) | 본인을 타인으로 거부 | **편의성**이 좋음 |
| **CER / EER** | FAR = FRR 이 되는 지점 | **우수한 장비** |

임계값을 높이면 FAR↓ FRR↑ (보안↑ 편의성↓), 낮추면 반대 — **트레이드오프**.

## SSO 와 Kerberos

| 방식 | 설명 |
|---|---|
| **Kerberos** | 대칭키 기반 티켓. 사내망(Windows AD) |
| **SAML 2.0** | XML 어서션. 기업 ↔ SaaS 연동 (IdP–SP) |
| **OAuth 2.0** | **인가(권한 위임)** — 인증 아님 |
| **OIDC** | OAuth 2.0 위에 **인증** 계층 (ID 토큰, JWT) |

### Kerberos (자주 출제)

구성: **KDC**(= AS 인증서버 + TGS 티켓발급서버) · 클라이언트 · 서버. 포트 88.

1. 클라이언트 → **AS**: 인증 요청 → **TGT** + 클라이언트–TGS 세션키 발급 (사용자 비밀번호 파생 키로 암호화)
2. 클라이언트 → **TGS**: TGT 제시하며 서비스 티켓 요청 → **서비스 티켓** + 클라이언트–서버 세션키 발급
3. 클라이언트 → **서버**: 서비스 티켓 제시 → 검증 후 서비스 제공 (상호 인증)

| 장점 | 단점 |
|---|---|
| 비밀번호가 네트워크에 흐르지 않음 · SSO · 상호 인증 · 재전송 방지(타임스탬프) | **KDC 가 SPOF·집중 표적** · **시계 동기화 필수**(5분) · 비밀번호 추측 · Pass-the-Ticket · **Golden Ticket**(krbtgt 해시 탈취) |

## 접근통제 구현 메커니즘

| 방식 | 관점 | 특징 |
|---|---|---|
| **ACL** | 객체 중심 (이 파일에 누가 접근 가능한가) | 관리 쉬움, 주체별 권한 파악 어려움 |
| **Capability** | 주체 중심 (이 사용자가 접근 가능한 객체) | 위임 쉬움, 회수 어려움 |
| **접근통제 행렬** | 주체 × 객체 표 | ACL·Capability 의 원형 |
| **보안 레이블** | MAC 에서 등급·카테고리 태그 | |
