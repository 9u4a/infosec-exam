## 로컬 프록시 도구 (4-6, 25-7, 31-17)

브라우저와 웹 서버 사이에서 HTTP/HTTPS 요청·응답을 **가로채 수정·재전송·분석**.

| 도구 | 비고 |
|---|---|
| **Burp Suite** | 사실상 표준. Proxy·Repeater·Intruder·Scanner |
| **OWASP ZAP** | 무료·오픈소스 |
| **Paros** | 초기 도구 |
| **Fiddler** | .NET 기반, HTTPS 복호화 옵션 필요 |

### Fiddler로 HTTPS가 안 보일 때 (31-17)

- 원인: **"Decrypt HTTPS traffic"** 옵션 비활성 → TLS 암호문만 보임.
- 해결: Tools → Options → HTTPS → *Decrypt HTTPS traffic* 체크 → Fiddler **루트 CA 인증서**를 신뢰 저장소에 설치(중간자 방식).
- 원리: Fiddler가 서버↔클라이언트 사이에서 TLS를 종단(=의도된 MITM).

## Telnet으로 HTTP 메서드 확인 (4-9, 20-1, 27-8)

```
telnet webserver.com 80
OPTIONS / HTTP/1.1
Host: webserver.com
(빈 줄)
```
→ 응답 `Allow:` 헤더에 지원 메서드 목록. **PUT·DELETE·TRACE** 가 열려 있으면 위험.
- 대응: 불필요 메서드 차단(`<LimitExcept GET POST>`), `TraceEnable Off`.

## 진단 방식 3분류 — 언제 무엇을

| 방식 | 시점 | 보는 것 | 못 보는 것 |
|---|---|---|---|
| **SAST**(정적/화이트박스) | 빌드 전·코딩 중 | 소스코드 데이터 흐름·패턴 | 런타임·설정·환경 이슈 |
| **DAST**(동적/블랙박스) | 실행 중(스테이징·운영) | 실제 요청/응답, 인증 후 동작 | 코드 내부, 도달 못한 경로 |
| **IAST**(대화형) | 테스트 중(에이전트 계측) | 실행되며 코드·요청을 동시에 | 계측 오버헤드 |
| **SCA**(구성요소 분석) | 상시 | 오픈소스 라이브러리 CVE·라이선스 | 자체 코드 로직 |

- 시험 팁: "소스 없이 실행 중인 사이트 점검" = DAST(블랙박스), "개발 초기 코드 검토" = SAST(화이트박스), "정상·비정상 입력을 대량으로 넣어 크래시 유발" = **퍼징**(DAST 계열).

## 블랙박스 · 화이트박스 · 그레이박스

| | 블랙박스 | 그레이박스 | 화이트박스 |
|---|---|---|---|
| 사전 정보 | 없음(외부자 시각) | 일부(계정·일부 문서) | 전부(소스·설계·계정) |
| 현실성 | 실제 공격자와 유사 | 균형 | 낮음 |
| 커버리지 | 낮음 | 중 | 높음 |

## 블랙박스 vs 화이트박스 (13-6, 22-9)

| | 블랙박스 (DAST) | 화이트박스 (SAST) |
|---|---|---|
| 대상 | 실행 중인 애플리케이션, **소스 미확인** | **소스 코드** |
| 방식 | 외부 인터페이스·구조 분석, 요청/응답 관찰 | 코드 정적 분석, 데이터 흐름 추적 |
| 장점 | 실환경 반영, 언어 무관 | 취약 지점 정확, 개발 초기 적용 |
| 단점 | 커버리지 낮음, 원인 파악 어려움 | 오탐, 런타임 이슈 못 잡음 |
| 도구 | Burp, ZAP, 웹스캐너 | Fortify, SonarQube, Coverity |
| 중간 | **IAST**(실행 중 계측), **퍼징** | |

## 퍼징 (Fuzzing) — 25-9, 31-8

프로그램에 **의도적으로 잘못된 형식·무작위·경계값 데이터**를 대량 입력하여 크래시·예외·메모리 오류로 취약점·버그를 찾는 동적 테스트.
- 종류: 뮤테이션(정상 입력 변형) / 제너레이션(문법 기반 생성) / 커버리지 가이드(AFL, libFuzzer).
- 웹·프로토콜·파일 파서·API에 적용.

## 서술형 3줄 요약 답안

- **로컬 프록시**: 브라우저↔서버 사이에서 HTTP(S) 요청·응답을 가로채 수정·재전송하는 도구(Burp·ZAP). 클라이언트 측 검증 우회, 파라미터 변조, 세션 분석에 쓴다. HTTPS를 보려면 프록시의 **루트 CA를 신뢰**시켜 의도된 MITM으로 복호화한다.
- **퍼징**: 비정상·경계값·무작위 데이터를 대량 입력해 크래시·예외로 취약점을 찾는 **동적** 기법. 뮤테이션·제너레이션·커버리지 가이드 방식.
- **SAST vs DAST**: 소스코드를 정적 분석하는 SAST는 개발 초기에 원인 지점을 정확히 잡지만 런타임 이슈를 못 보고, 실행 중 앱을 외부에서 시험하는 DAST는 실환경을 반영하나 코드 내부·미도달 경로를 못 본다 → 병행이 원칙.

## 웹 방화벽 (9-4)

- **ModSecurity**: Trustwave가 개발한 공개용 WAF. **Apache·IIS·Nginx** 모듈로 동작. OWASP CRS 룰셋 사용.
- 탐지: 시그니처(블랙리스트) + 화이트리스트 + 이상 점수(anomaly scoring).

## CBD 개발 — 분석 단계 진단 산출물 (25-13)

SW 보안약점 진단원이 CBD(컴포넌트 기반 개발) **분석 단계**에서 검토:
① **요구사항 정의서** — 기능·비기능(보안) 요구사항 합의 ② **요구사항 추적표(추적 매트릭스)** — 단계별 산출물 일관성 추적
③ **보안 요구사항 명세** — 인증·인가·암호화·로깅 등 보안 항목 정의 ④ **위협·위험 분석서** — 자산·위협 식별, 대응 방안.
