## 대칭키 vs 비대칭키

| | 대칭키 (비밀키) | 비대칭키 (공개키) |
|---|---|---|
| 키 | 암·복호화 동일 | 공개키 / 개인키 쌍 |
| 속도 | 빠름 (대용량) | 느림 (100~1000배) |
| 키 분배 | **어려움** (사전 공유 필요) | 쉬움 (공개키 배포) |
| 키 개수 (N명) | **N(N-1)/2** | 2N |
| 용도 | 데이터 암호화 | 키 교환, 전자서명, 인증 |
| 알고리즘 | AES, SEED, ARIA, 3DES, ChaCha20 | RSA, ECC, ElGamal, DH |

→ 실무: **하이브리드** (비대칭키로 대칭 세션키를 안전하게 전달)

## 블록 암호 운영 모드

| 모드 | 특징 |
|---|---|
| ECB | 블록별 독립 암호화 → 패턴 노출 (사용 금지) |
| CBC | 이전 암호블록과 XOR, IV 필요 |
| CTR | 카운터를 암호화해 스트림처럼, 병렬 가능 |
| GCM | CTR + 인증(GMAC) = **AEAD** (기밀성+무결성) |

## 해시 함수

특성: 압축성 · **일방향성** · 약한 충돌 저항성 · 강한 충돌 저항성
용도: 무결성, 전자서명, 비밀번호 저장(+salt+반복), MAC
- 안전: SHA-256, SHA-3, bcrypt/scrypt/Argon2(비밀번호용)
- 폐기: **MD5, SHA-1** (충돌 발견)

## Diffie-Hellman 키 교환

공개: p(소수), g(원시근). Alice 비밀 a, Bob 비밀 b.
- Alice→Bob: `g^a mod p`, Bob→Alice: `g^b mod p`
- 공유키: 둘 다 `g^(ab) mod p` 계산 → 이것이 대칭키
- 이산대수 문제에 안전. **인증 없어 MITM 취약** → 서명/인증서와 결합. (EC)DHE는 PFS 제공

## SSL / TLS

**핸드셰이크**: ①ClientHello/ServerHello(암호군 협상) ②서버 인증서 검증(CA 공개키) ③키 교환(RSA 또는 (EC)DHE로 Premaster Secret 공유) ④세션키 유도 ⑤Change Cipher Spec → **대칭키로 데이터 암호화**
- **비대칭키**: 인증서 검증 + 세션키 재료 교환
- **대칭키**: 실제 데이터 암·복호화 (속도)
- **레코드 프로토콜**: 단편화 → 압축 → MAC 추가 → 암호화 → 헤더 추가
- **TLS 1.3**: 1-RTT(재개 시 0-RTT), 취약 알고리즘 제거, (EC)DHE만
