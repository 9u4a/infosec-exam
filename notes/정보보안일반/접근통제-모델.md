## 정책 모델

| 모델 | 기준 | 특징 | 취약점 |
|---|---|---|---|
| **DAC** (임의적) | 신원 (소유자 재량) | 소유자가 권한 부여/회수, 대부분 OS 기본 | 트로이목마·권한 전파에 약함 |
| **MAC** (강제적) | 보안 등급(레이블) | 시스템이 주체·객체 등급 강제 비교, 소유자도 재량 없음 (보안 OS, 군) | 유연성 낮음, 구현 복잡 |
| **RBAC** (역할 기반) | 역할(직무) | 사용자→역할→권한 매핑, 대규모 조직 관리 효율, 최소권한·직무분리 적용 용이 | — |

## MAC 세부 모델

| 모델 | 초점 | 규칙 |
|---|---|---|
| **BLP (Bell-LaPadula)** | **기밀성** | **no read up**(하위→상위 읽기 금지), **no write down**(상위→하위 쓰기 금지, `*`-속성) → 기밀 정보의 하향 유출 차단 |
| **Biba** | **무결성** | **no read down**, **no write up** → 저품질 정보의 상향 오염 차단 |
| **Clark-Wilson** | 무결성 (상업용) | Well-formed transaction, **직무 분리**, TP(변환 절차)를 통해서만 CDI 접근 |
| **Chinese Wall (Brewer-Nash)** | 이해충돌 방지 | 이미 접근한 회사와 경쟁 관계인 회사 데이터 접근 차단 (동적) |

## 접근통제 3단계

**식별(Identification)** → **인증(Authentication)** → **인가(Authorization)** → (책임추적성 Accountability)

인증 요소: 지식(비밀번호) · 소유(OTP·스마트카드) · 존재(생체) · 행위(서명·타이핑 패턴) → 2개 이상 = **MFA**

## 접근통제 매커니즘

- **ACL** (객체 중심: 이 파일에 누가 접근 가능한가)
- **Capability** (주체 중심: 이 사용자가 접근 가능한 객체 목록)
- **접근통제 행렬** (주체 × 객체)
- **보안 레이블**
