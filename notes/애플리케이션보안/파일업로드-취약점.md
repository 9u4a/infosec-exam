## 위험

실행 가능한 서버사이드 스크립트(.php/.jsp/.asp)를 업로드 → **웹셸** → 원격 명령 실행, 파일 조작, DB 접근, 권한 상승, 추가 백도어.

## 검증 우회 기법

| 대상 | 우회 |
|---|---|
| **확장자 블랙리스트** | 대소문자 혼용(`shell.pHp`), 대체 확장자(`.php3` `.php4` `.php5` `.php7` `.pht` `.phtml` `.phar` `.pgif` / `.jspx` `.jspf` / `.asa` `.cer` `.aspx`), 이중 확장자(`shell.php.jpg` ↔ 서버가 앞을 읽으면 `shell.jpg.php`) |
| **끝문자 트릭** | `shell.php.` (마지막 점) · `shell.php%20` (공백) · `shell.php::$DATA` (NTFS ADS) → OS가 제거하고 저장 |
| **Content-Type(MIME) 검사** | 프록시(Burp)로 `Content-Type: image/jpeg` 로 변조 |
| **매직바이트/시그니처 검사** | 파일 앞에 `GIF89a;` · `\xFF\xD8\xFF`(JPEG) 등을 붙이고 뒤에 `<?php ...?>` (polyglot) |
| **Null 바이트** | `shell.php%00.jpg` → 검증은 `.jpg`, 저장은 `.php` (PHP < 5.3.4 등 구형) |
| **경로 조작** | 파일명에 `../` → 웹루트 외/다른 경로에 저장 |
| **`.htaccess` 업로드** | 확장자 화이트리스트가 `.htaccess` 를 막지 않으면 → `AddType application/x-httpd-php .jpg` 업로드 후 `shell.jpg` 실행 |
| **이미지 리사이징 우회** | 서버가 GD로 재저장하면 폴리글랏이 깨짐 → EXIF 필드(`Comment`)에 페이로드를 넣고 LFI와 결합 |
| **경쟁 조건(Race)** | 업로드 직후 검증·삭제 전 짧은 순간에 `shell.php` 를 반복 요청해 실행 |

### 실무형 지문 패턴 (23-13 / 29-14)

프록시로 `test.php` → `test.php.jpeg` / `test.jpeg.php` / `test.php;.jpg` 등을 시도.
- 정규식이 `\.(jpg|jpeg|png|gif)$` 만 확인하고 `preg_match` 결과를 잘못 쓰면 우회.
- 서버 설정(`AddHandler`, `<FilesMatch>`)이 `.php` 를 부분 매칭하면 `test.php.jpeg` 도 PHP로 실행.

## 공격 성공 조건

1. 확장자/MIME 검증 통과
2. 크기 제한(`LimitRequestBody`) 통과
3. 업로드 경로에서 **스크립트 실행 가능** (핸들러 매핑, 웹루트 내)

## 대응

| 계층 | 조치 |
|---|---|
| 검증 | 확장자 **화이트리스트**(.jpg .png .pdf …) + MIME + 매직바이트 다중 검증 |
| 저장 | **웹 루트 외부**에 저장, 다운로드는 별도 로직 / 파일명 **난수화** |
| 실행 차단 | 업로드 디렉토리 **스크립트 실행 권한·핸들러 제거** |
| 크기 | Apache `LimitRequestBody`, PHP `upload_max_filesize`·`post_max_size` |

### .htaccess 로 실행 차단 (Apache)
```apache
<FilesMatch "\.(ph|php[3457]?|phtml|sh|cgi|pl|jsp|asp)$">
    Require all denied            # 직접 URL 호출 차단
</FilesMatch>
AddType text/html .php .php3 .phtml    # 스크립트를 실행 불가한 MIME으로 재지정
php_flag engine off                     # 해당 디렉토리 PHP 엔진 비활성화
```

### IIS
- 업로드 폴더의 '스크립트 및 실행 파일' 실행 권한 제거
- 핸들러 매핑에서 해당 확장자 제거
