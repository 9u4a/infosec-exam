## 설정 파일

- `httpd.conf` (또는 `apache2.conf`) — 메인 설정. `Include conf.d/*.conf`.
- `.htaccess` — 디렉터리별 설정 (`AllowOverride` 로 허용 범위 제어).

## `<Directory>` 보안 지시자 (17-16, 20-8, 29-11)

```apache
<Directory /var/www>
    Options Indexes FollowSymLinks     # ← 위험
    AllowOverride None
    Require all granted
</Directory>
```

| 지시자 | 위험 | 조치 |
|---|---|---|
| **Indexes** | 인덱스 파일 없을 때 **디렉터리 목록 노출** (Directory Listing/Indexing) | `Options -Indexes` (또는 Indexes 삭제) |
| **FollowSymLinks** | 심볼릭 링크로 웹 루트 밖(`/etc/passwd` 등) 접근 | 제거 또는 `SymLinksIfOwnerMatch` |
| **Includes** | SSI(`<!--#exec-->`) 명령 실행 | `-Includes` 또는 `IncludesNOEXEC` |
| **AllowOverride All** | `.htaccess` 로 설정 우회 | `None` |

> 디렉터리 인덱싱 판단(13-15, 5-15): 응답 **200 OK** + 본문에 `Index of /경로` 목록 → 성공.

## 주요 옵션 (14-15)

| 지시자 | 의미 |
|---|---|
| `Timeout 300` | 300초 동안 통신 없으면 연결 종료 (Slowloris 대응은 더 짧게) |
| `KeepAlive On` / `MaxKeepAliveRequests 100` | 커넥션 재사용, 커넥션당 최대 요청 수 |
| `KeepAliveTimeout 5` | KeepAlive 유지 시간 |
| `DirectoryIndex index.html index.php` | 디렉터리 접근 시 찾을 기본 파일·순서 |
| **`LimitRequestBody <바이트>`** | 요청 본문(업로드) 최대 크기 제한 (14-8, 21-10) |
| `LimitRequestFields`, `LimitRequestLine` | 헤더 개수·요청라인 길이 제한 (버퍼 오버플로 대응) |
| `ServerTokens Prod` / `ServerSignature Off` | 버전 배너 숨김 |
| `TraceEnable Off` | TRACE 메서드 차단 (XST 대응) |

## 로그 (19-7)

| 로그 | 지시자 | 내용 |
|---|---|---|
| **Access 로그** | `CustomLog logs/access_log combined` | 정상 접속 (IP, 시각, 요청라인, 상태코드, 크기, Referer, User-Agent) |
| **Error 로그** | `ErrorLog logs/error_log` | 처리 오류, 모듈 경고 |

경로 확인 파일: **`httpd.conf`** 의 `CustomLog` / `ErrorLog` 지시자.

### Combined 로그 형식 (24-10)

```
200.3.1.4 - - [30/May/2023:01:20:01 +0900] "GET /bulletin/read.php?no=101&item=book HTTP/1.1" 200 3549 "http://ref" "Mozilla/5.0"
```
IP · ident · 인증사용자 · [시각] · "메서드 URL 프로토콜" · **상태코드** · 응답크기 · "Referer" · "User-Agent"

### 공격 로그 판별

- **7-15 HTTP Request 문제점**: ① `id`·`password` 가 **GET 파라미터 평문** (URL·로그·Referer에 노출) → POST + HTTPS ② `Cache-Control: must-revalidate` 로 캐시 미사용 → 원본 서버 부하 ③ 세션 쿠키 평문 구간 노출.
- **17-14 유니코드 취약점**: `GET /script/..%c1%1c../winnt/system32/cmd.exe?/c+dir` → 디렉터리 트래버설(유니코드 인코딩) 통한 RCE 시도. 응답 **404** = 실패(패치됨). 대응: 웹서버 패치, 입력 필터링, 웹루트 분리, IPS 룰.
- 상태코드 빠른 해석: 200 성공 / 301·302 리다이렉트 / 403 금지 / 404 없음 / 500 서버오류. 공격 성공 여부는 대개 **200 vs 403/404** 로 판단.
