## robots.txt (13-16, 15-2, 24-6)

- **로봇 배제 표준(Robots Exclusion Protocol)** 을 따르는 일반 텍스트 파일. 웹사이트 **루트 디렉터리**(`/robots.txt`)에 위치.
- 검색 로봇(크롤러)의 접근 허용/제한을 **권고**할 뿐 강제력 없음.
- 문법:
  ```
  User-agent: googlebot
  Allow: /
  User-agent: googlebot-image
  Disallow: /private/
  ```
- **보안 주의**: 관리자 페이지·백업 경로를 `Disallow` 에 적으면 오히려 **위치를 알려주는 꼴** → 민감 경로는 인증으로 보호하고 robots에 노출하지 않는다.

## FTP 능동/수동 모드 (9-14, 10-2)

| 채널 | 포트(서버) | 역할 |
|---|---|---|
| 제어 채널 | **21** | 클라이언트가 접속·명령 전달, 세션 내내 유지 |
| 데이터 채널 | **20**(Active) | 파일·디렉터리 목록 전송 |

- **Active 모드**: 서버가 **20번 → 클라이언트의 임의 포트(1024↑)** 로 역방향 연결.
  클라이언트 방화벽/NAT가 이 인바운드를 막으면 **목록·전송 실패**.
- **Passive 모드**: 서버가 데이터용 임의 포트를 열고 대기, **클라이언트가 접속**. → 클라이언트 방화벽 문제 해결(클라이언트에서 `passive`/`pasv` 설정).
- 보안: 평문 전송 → **FTPS**(FTP+TLS) 또는 **SFTP**(SSH) 사용, `chroot` 로 상위 디렉터리 접근 차단.

## 서브도메인 테이크오버 (20-9)

클라우드/외부 서비스용으로 서브도메인에 **CNAME** 을 걸어 두고 서비스는 해지했지만 **DNS 레코드를 안 지운** 경우 →
공격자가 그 서비스에 같은 이름으로 리소스를 생성해 서브도메인을 **탈취** → 피싱·쿠키 탈취.
- 대응: 서비스 해지 시 DNS 레코드 즉시 삭제, 소유하지 않은 리소스를 가리키는 dangling 레코드 정기 점검.

## 모바일 딥링크 (18-10, 28-12)

앱 내 **특정 화면으로 바로 이동**시키는 URL 스킴(`myapp://pay?...`) / 유니버설·앱 링크.
- 악용: 조작된 딥링크로 접속 유도 → 인증·검증 없이 민감 화면(카드정보·주소) 노출, 파라미터 조작으로 **의도치 않은 계좌이체**.
- 대응: 딥링크 파라미터 **서버 측 재검증**, 민감 액션은 재인증, 화이트리스트 호스트, `autoVerify` 앱 링크 사용.

## 인증서 고정 (Certificate Pinning) — 29-13

1) **정의/목적**: 앱에 서버 인증서(또는 공개키) 지문을 **미리 저장**, TLS 연결 시 실제 인증서와 일치할 때만 통신 허용 → **중간자(MITM)** 공격(사설 CA·프록시) 방지.
2) **핵심 요소**: ① 고정 대상(리프 인증서 / 중간 CA / **공개키 SPKI 해시**) ② 백업 핀(교체 대비) ③ 핀 만료·갱신 정책.
3) **우회 방법**: ① 루팅/탈옥 후 **Frida·Objection** 으로 검증 함수 후킹 ② 앱 리패키징(스마리 패치) ③ 사용자 CA 신뢰 + `network_security_config` 조작.
