| 유형 | 예 |

## SET (Secure Electronic Transaction)

Visa·MasterCard가 만든 신용카드 전자결제 표준. **PKI + 이중서명** 기반.

### 참여자

카드소지자, 상점(Merchant), **지불 게이트웨이(PG)**, 발급사(Issuer), 매입사(Acquirer), 인증기관(CA).

### 이중 서명 (Dual Signature)

목적: **상점은 지불정보(PI, 카드번호)를 못 보고, 은행은 주문정보(OI)를 못 보게** 하면서 둘의 연결은 증명.

1. OI 해시(H(OI)), PI 해시(H(PI)) 계산
2. 두 해시를 연결 → 그 값의 해시(POMD) 계산
3. POMD를 **카드소지자 개인키로 서명** = 이중서명
4. 상점에 `OI + H(PI) + 이중서명` 전달 → 상점은 OI만 보고 검증 가능
5. PG(은행)에 `PI + H(OI) + 이중서명` 전달 → 은행은 PI만 보고 검증 가능

- 장점: 강력한 보안·부인방지. 단점: **복잡·느림·인증서 배포 부담** → 실패, SSL/3-D Secure로 대체.

## SSL/TLS 기반 결제

- 구간 암호화만 제공 → 상점 서버에는 카드번호가 평문으로 보임(SET과 차이).
- 실무에서는 **PG사가 카드정보를 대신 처리**(상점은 토큰만 보관) + **PCI-DSS** 준수.

## 3-D Secure

카드 결제 시 **발급사 인증 페이지**로 리디렉션해 추가 인증(비밀번호·OTP·앱 승인).
- 3개 도메인: 발급사(Issuer) · 매입사(Acquirer) · 상호운용(카드사 네트워크).
- 2.0은 리스크 기반 인증(디바이스·행동 분석)으로 마찰 감소.

## OTP (일회용 비밀번호)

| 방식 | 설명 |
|---|---|
| **시간 동기(TOTP)** | 시드 + 현재 시각(30~60초). 시계 오차 허용창 |
| **이벤트 동기(HOTP)** | 버튼 누른 횟수(카운터) 기반 |
| **질의응답(Challenge-Response)** | 서버 챌린지에 응답값 계산, 동기화 불필요 |

- OTP 토큰/카드/앱. 금융권 이체 시 공인인증서 + OTP 조합.

## 전자화폐 요건

- **익명성(불추적성)**: 사용 내역으로 신원 추적 불가 (은닉서명 활용)
- **오프라인성**: 결제 시 은행 온라인 연결 불필요
- **이중사용 방지(Double Spending)**: 같은 전자화폐 재사용 탐지
- **양도성**: 제3자에게 이전 가능
- **분할성**: 액면을 나눠 사용

## 에스크로 (결제대금 예치)

구매자 대금을 **제3자(에스크로 사업자)가 보관** → 구매자가 물품 수령·확인 후 판매자에게 지급.
- 비대면 거래 사기 방지. 전자상거래법상 일정 금액 이상 통신판매는 **에스크로 등 소비자보호 장치 의무**.

## 관련 표준·제도

- **PCI-DSS**: 카드 데이터를 다루는 모든 주체의 보안 요구사항(12개 항목).
- **전자금융거래법**: 금융회사·전자금융업자 안전성 확보, CISO, 사고 배상책임.
- **전자서명법 / 본인확인기관**: 온라인 실명 확인 대체 수단.
