## 방화벽 유형 (동작 계층별)

| 유형 | 동작 계층 | 방식 | 장점 | 단점 |
|---|---|---|---|---|
| **패킷 필터링** | 3~4 (네트워크/전송) | IP·포트·플래그로 정적 허용/차단 | 빠름, 저비용, 투명 | 상태 추적 못 함, 세션 스푸핑·단편화 취약, 로깅 빈약 |
| **스테이트풀 인스펙션** | 3~4 + 세션 | 연결 상태 테이블 유지, 응답 패킷만 허용 | 패킷필터 + 세션 추적, 성능 양호 | 애플리케이션 계층 공격은 못 막음 |
| **애플리케이션 게이트웨이(프록시)** | 7 (응용) | 서비스별 프록시가 연결 대리, 페이로드 검사 | 강력한 인증·로깅·콘텐츠 필터 | 느림, 서비스별 프록시 필요, 확장성↓ |
| **서킷 게이트웨이** | 5 (세션) | SOCKS 등, 세션 단위 중계(내용 검사 X) | 내부 IP 은닉, 범용 | 애플리케이션 검사 없음, 클라이언트 수정 필요 |
| **하이브리드 / 상태ful 프록시** | 혼합 | 위 방식 조합 | 균형 | 복잡·고가 |
| **차세대 방화벽(NGFW)** | 3~7 | 앱 인식 + 사용자 인식 + IPS + TLS 검사 | 통합 가시성 | 성능 부하, 고가 |

- **UTM**: 방화벽+IPS+안티바이러스+VPN+웹필터를 한 장비로 (중소규모).
- **WAF**: 웹 애플리케이션 전용(계층 7), SQLi·XSS 방어 — 범용 방화벽과 별개.

## 방화벽 정책 원칙

- **화이트리스트(Deny All, 명시 허용)** 가 원칙 — 필요한 것만 연다.
- **최소 규칙**, 규칙 순서 최적화(자주 매칭되는 것 위로), 마지막에 `deny any + log`.
- **송신(egress) 필터링**도 설정 — 내부 → 외부 비인가 트래픽(C2, 데이터 유출) 차단.
- 규칙 정기 검토, 불필요·중복·shadow 규칙 제거.

## 구축 아키텍처

### 베스천 호스트 (Bastion Host)

- 내부망과 외부망 사이의 **요새 호스트** — 강력히 하드닝, 불필요 서비스 제거, 로깅 집중.
- 공격의 1차 표적이므로 침해 시 피해 최소화 설계.

### 스크리닝 라우터 (Screening Router)

- 경계 라우터에서 ACL로 1차 패킷 필터링. 단독으로는 취약.

### 스크린드 호스트 (Screened Host) — 단일 홈드/듀얼 홈드

```
인터넷 ─ 스크리닝 라우터 ─ 베스천 호스트 ─ 내부망
```
- 라우터(패킷 필터) + 베스천(프록시) 2단계 방어.
- 라우터가 뚫리면 내부망 직접 노출 위험(단일 홈드).
- **듀얼 홈드 호스트**: NIC 2개인 베스천이 유일한 통로, 라우팅 비활성 → 반드시 프록시 경유.

### 스크린드 서브넷 (Screened Subnet) — DMZ

```
인터넷 ─ 외부 라우터 ─ [ DMZ: 웹·메일·DNS 서버 ] ─ 내부 라우터 ─ 내부망
```
- 외부·내부 라우터 사이에 **완충 지대(DMZ)** 구성.
- 외부에서 접근이 필요한 공개 서버는 DMZ에, 내부망은 별도 보호.
- 가장 안전한 구성. 외부 라우터 침해돼도 내부 라우터가 방어.
- **비용·관리 복잡도 최고**.

## 방화벽 우회·한계

- 내부자 위협, 백도어·터널링(HTTPS·DNS 터널), 암호화 트래픽 미검사, 무선 AP·모뎀 우회, 애플리케이션 취약점.
- → 다계층 방어(IDS/IPS, 엔드포인트, NAC, 로그 분석)와 병행.
