## VPN 개념

공중망(인터넷) 위에 **가상의 전용 회선**을 만들어 기밀성·무결성·인증을 제공.
- 목적: 원격 접속(재택), 지사 간 연결, 전용선 대체(비용 절감).
- 핵심 기술: **터널링 + 암호화 + 인증 + 키 관리**.

## 터널링 프로토콜 계층별

| 프로토콜 | 계층 | 특징 |
|---|---|---|
| **PPTP** | 2 (데이터링크) | MS 주도, GRE + PPP. 구현 쉬움, **MS-CHAPv2·MPPE 취약** |
| **L2F** | 2 | Cisco, 인증만(암호화 X) |
| **L2TP** | 2 | PPTP + L2F 결합, 자체 암호화 없음 → 보통 **L2TP/IPSec** |
| **IPSec** | 3 (네트워크) | IETF 표준, AH/ESP, 사이트 간 VPN 주력 |
| **SSL/TLS VPN** | 4~7 | 브라우저 기반, 사용자 단위 접근제어 |
| **OpenVPN** | 4 (TLS 기반) | 오픈소스, UDP/TCP |
| **WireGuard** | 3 | 경량·고속, 최신 암호 |

## VPN 구성 형태

| 형태 | 설명 |
|---|---|
| **사이트 대 사이트 (게이트웨이-게이트웨이)** | 본사↔지사 라우터/방화벽 간 터널. 사용자는 VPN 인지 못 함. IPSec **터널 모드** |
| **원격 접속 (호스트-게이트웨이)** | 재택 사용자 PC ↔ 본사 VPN 게이트웨이. VPN 클라이언트 필요(IPSec) 또는 브라우저(SSL) |
| **호스트 대 호스트** | 서버↔서버 직접. IPSec **전송 모드** |

## IPSec VPN vs SSL VPN

| 항목 | IPSec VPN | SSL VPN |
|---|---|---|
| 계층 | 3 (네트워크) | 4~7 (전송~응용) |
| 클라이언트 | **전용 클라이언트 설치** 필요 | **브라우저만**(Clientless) 또는 경량 에이전트 |
| 접근 범위 | 네트워크 전체(넓음) | 애플리케이션/URL 단위(세밀한 제어) |
| 방화벽/NAT 통과 | NAT-T 필요, 까다로움 | 443 포트라 대부분 통과 |
| 적합 | 지사 연결, 항상 연결 | 재택·외부·협력사 원격 접속 |
| 보안 우려 | 단말이 사내망에 완전 편입 | 공용 PC 사용 시 흔적·세션 탈취 |

## PFS (Perfect Forward Secrecy, 전방향 비밀성)

- 매 세션마다 **임시(ephemeral) DH 키**로 세션키 생성 → 서버 개인키가 나중에 유출돼도 **과거 트래픽은 복호화 불가**.
- IPSec: IKE Phase 1/2에서 DH 그룹 재협상 옵션.
- TLS: `ECDHE`·`DHE` 암호군 사용 시 제공(정적 RSA 키 교환은 PFS 없음).

## VPN 보안 고려사항

- 강한 인증(인증서 + MFA), 스플릿 터널링 제한(모든 트래픽을 VPN 경유), 접속 단말 무결성 점검(NAC 연동), 세션 타임아웃·재인증, VPN 게이트웨이 패치(취약점 표적 다수).
