> 최신 정보보안기사 범위. robots-모바일앱 노트의 IaaS/PaaS/SaaS 정의와 연계.

## 가상화 구조

| 유형 | 설명 | 예 |
|---|---|---|
| **Type 1 (베어메탈) 하이퍼바이저** | 하드웨어 위에 직접 실행 | ESXi, Hyper-V, Xen, KVM |
| **Type 2 (호스트형) 하이퍼바이저** | 호스트 OS 위에서 실행 | VirtualBox, VMware Workstation |
| **컨테이너** | 호스트 커널 공유, 프로세스 수준 격리 | Docker, containerd |

- VM = 완전 격리(각자 OS), 무거움 / 컨테이너 = 가벼움·빠름, 커널 공유 → 격리 약함.

## 가상화(VM) 보안 위협

| 위협 | 설명 |
|---|---|
| **VM Escape (탈출)** | 게스트 VM에서 하이퍼바이저·호스트로 침투 → 다른 VM 전체 장악 |
| **VM Hopping** | 같은 호스트의 다른 VM으로 이동 |
| **VM Sprawl** | 관리되지 않는 VM 난립 → 패치 누락·공격 표면 확대 |
| **하이퍼재킹 (Hyperjacking)** | 악성 하이퍼바이저를 하위에 삽입 |
| **자원 고갈** | 한 VM이 CPU·메모리 독점 → 다른 VM DoS |
| **VM 이미지·스냅샷 유출** | 이미지에 남은 크리덴셜·데이터 |
| **부채널 (Side-channel)** | 공유 캐시·CPU를 통한 정보 유출 (co-residency) |

- 대응: 하이퍼바이저 최소화·패치, VM 간 네트워크 분리(마이크로세그멘테이션), 이미지 무결성·서명, 테넌트 격리, 스냅샷 암호화.

## 컨테이너 보안

- 위협: **컨테이너 탈출**(권한 있는 컨테이너, 커널 취약점), 취약한 베이스 이미지, 시크릿 하드코딩, 과도한 권한(`--privileged`), 레지스트리 변조.
- 대응:
  - 이미지: 신뢰 레지스트리, 취약점 스캔(Trivy·Clair), 서명(Notary/Cosign), 최소 베이스(distroless).
  - 런타임: 비루트 실행, `--cap-drop ALL`, 읽기 전용 파일시스템, seccomp/AppArmor/SELinux 프로파일, 리소스 제한(cgroups).
  - 오케스트레이션(K8s): RBAC, NetworkPolicy, Pod Security Standards, 시크릿은 etcd 암호화·외부 볼트, 관리 API 인증.

## 클라우드 책임 공유 모델

| 계층 | IaaS | PaaS | SaaS |
|---|---|---|---|
| 데이터·계정·접근관리 | **이용자** | **이용자** | **이용자** |
| 애플리케이션 | 이용자 | 이용자 | CSP |
| OS·미들웨어·런타임 | 이용자 | CSP | CSP |
| 가상화·물리 인프라 | CSP | CSP | CSP |

> "클라우드는 안전하다"가 아니라 **"클라우드는 안전하게 쓸 수 있다"** — 설정·계정 관리는 늘 이용자 몫. 대부분의 클라우드 사고 원인은 **잘못된 설정(오픈 버킷, 과도한 IAM 권한)**.

## 클라우드 보안 위협 (CSA)

데이터 유출, **잘못된 설정·부적절한 변경 관리**, 취약한 IAM, 계정 탈취, 내부자, 안전하지 않은 API, 제한된 가시성, 공급망.

## 클라우드 보안 솔루션·인증

| 항목 | 설명 |
|---|---|
| **CASB** | 이용자↔클라우드 사이 프록시 — 가시성, 접근통제, DLP, 위협 탐지 |
| **CSPM** | 클라우드 설정 오류 지속 점검 |
| **CWPP** | 클라우드 워크로드(VM·컨테이너·서버리스) 보호 |
| **SASE** | SD-WAN + 클라우드 보안(SWG·CASB·ZTNA·FWaaS) 통합 |
| **CSAP (클라우드보안인증)** | 국내 공공기관용 클라우드 서비스 보안 인증(KISA), IaaS/SaaS/DaaS 등급제 |
| **ISO 27017 / 27018** | 클라우드 보안통제 / 클라우드 개인정보(PII) 보호 |
