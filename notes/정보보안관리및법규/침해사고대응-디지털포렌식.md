## 침해사고 대응 7단계

사고 전 준비 → 사고 탐지 → **초기 대응** → 대응 전략 체계화 → 사고 조사(포렌식·원인 분석) → 보고서 작성 → 복구 및 해결(재발 방지)

> '초기 대응'(초동 조치·확산 차단·증거 보존 시작)과 '대응 전략 체계화'의 순서 주의

NIST(SP 800-61): 준비 → 탐지·분석 → 봉쇄·근절·복구 → 사후 활동

## 디지털 포렌식 5대 원칙

| 원칙 | 내용 |
|---|---|
| **정당성** | 적법한 절차로 수집 (위법수집증거 배제) |
| **재현성** | 같은 조건 → 같은 결과 |
| **신속성** | 즉시 대응 (휘발성 데이터 소실 방지) |
| **연계보관성 (Chain of Custody)** | 수집 → 이송 → 분석 → 보관 → 제출 각 단계 책임자·시각·방법 기록 |
| **무결성** | 원본과 동일함을 **해시**로 증명, 쓰기방지장치로 이미징 후 사본 분석 |

## 증거 수집 우선순위 (휘발성 순서)

레지스터·캐시 → 메모리(RAM) → 네트워크 연결·프로세스 상태 → 임시 파일 → 디스크 → 원격 로그 → 물리 백업

## 분석 유형

- **정적 분석**: 실행하지 않고 파일 구조·문자열·시그니처·디스어셈블 (PEiD, IDA, Ghidra, YARA)
- **동적 분석**: 격리 환경(**샌드박스**)에서 실행 후 행위·네트워크·시스템 변경 관찰 (Cuckoo, Any.Run)
- anti-VM / anti-debugging 회피 기법에 주의

## 로그 분석 포인트

- 유닉스: `utmp`/`wtmp`/`btmp`/`lastlog`/`pacct`, `/var/log/messages`·`secure`
- 웹: access log(공격 요청), error log
- 삭제된 실행 파일: `/proc/<PID>/exe (deleted)` → `cp /proc/<PID>/exe 복원경로`
- `ps` 변조 의심 시: `/proc` 직접 조사, `lsof`, 정적 컴파일 도구
