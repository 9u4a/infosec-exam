## 한눈에 — 위험관리 큰 그림

```
위험관리(Risk Management)  ── 전체 과정, 수용가능 수준으로 위험 유지 ──
 │
 ├─ 1) 위험평가(Risk Assessment)
 │     위험 식별 → 위험 분석(규모 산출) → 위험 평가(DoA와 비교·우선순위)
 │
 ├─ 2) 위험처리(Risk Treatment) : 감소 · 회피 · 전가 · 수용
 │
 └─ 3) 사후관리 : 잔여위험 확인 → 모니터링 · 재평가 · 개선
```

- **위험분석 ⊂ 위험평가 ⊂ 위험관리** (분석은 평가의 일부, 평가는 관리의 일부).
- 위험처리 4방안 상세는 **위험 처리(대응) 방안** 노트, 세부 절차 표준 비교는 **위험관리 절차·국제표준** 노트 참고.

## 헷갈리는 용어 딱 구분

| 헷갈리는 쌍 | 구분 포인트 |
|---|---|
| **위협 vs 취약점** | 위협 = 밖에서 오는 **나쁜 사건의 원인**(해커, 화재, 악성코드) · 취약점 = 자산이 **스스로 가진 약점**(미패치, 약한 암호). 위협은 없앨 수 없고 취약점은 보완 가능 |
| **취약점 vs 위험** | 취약점은 **조건**, 위험은 위협이 취약점을 악용해 손실이 날 **가능성·크기**(결과) |
| **위험분석 vs 위험평가** | 분석 = 위험의 **크기(위험도)를 산출** · 평가 = 그 위험도를 **DoA와 비교**해 "처리할지/받아들일지" 우선순위 결정 |
| **접근법 vs 방법론** | 접근법 = 분석의 **범위·깊이를 어떻게 잡나**(베이스라인/비정형/상세/복합) · 방법론 = 위험 값을 **어떻게 매기나**(정성적: 델파이·시나리오 / 정량적: ALE 계산). 서로 다른 축이며 조합해서 씀 |
| **위험 감소 vs 위험 회피** | 감소 = 대책을 넣어 위험 **낮추고 사업은 계속** · 회피 = 사업/기능 **자체를 포기** |
| **위험 전가 vs 위험 수용** | 전가 = 손실 비용을 **제3자(보험·외주)에게** · 수용 = 아무것도 안 하고 **내가 감수** |
| **DoA vs 잔여위험** | DoA = 조직이 정한 **목표선(허용 한도)** · 잔여위험 = 대책 후 **실제 남은 위험**. `잔여위험 ≤ DoA` 여야 완료 |

### 시험 문장 → 정답 (즉답 키워드)

| 지문에 이런 표현이 나오면 | 정답 |
|---|---|
| "전문가 집단을 구성하여 **토론**으로 분석" | **델파이법** |
| "어떤 사건도 기대대로 발생하지 않는다는 전제로 결과 추정" | **시나리오법** |
| "모든 시스템에 **표준화된 체크리스트**로 기본 보호수준 일괄" | **베이스라인(기준선) 접근법** |
| "구조적 방법론 없이 **경험자의 지식**으로" | **비정형 접근법** |
| "**고위험 영역은 상세 분석**, 나머지는 베이스라인" | **복합(혼합) 접근법** |
| "자산가치 × 노출계수", "연간 예상 손실액" | **정량적 분석** (SLE, ALE — 정량적 위험분석 노트) |
| "수용 가능한 목표 위험 수준" | **DoA** |
| "위험을 그대로 받아들이고 사업 진행" | **위험 수용(보유)** |
| "보험/외주로 손실을 제3자에게" | **위험 전가(이전)** |

## 구성 요소

- **자산(Asset)**: 조직이 보호해야 할 유·무형의 모든 것 (정보, HW, SW, 시설, 인력, 이미지).
- **위협(Threat)**: 자산에 손실을 초래할 수 있는 원치 않는 사건의 **잠재적 원인·행위자**. (발생 가능성으로 측정)
- **취약점(Vulnerability)**: 위협의 이용 대상이 되는 자산의 **잠재적 약점** (기술적·관리적·물리적).
- **위험(Risk)** = f(자산, 위협, 취약점) — 보통 `위험 = 자산가치 × 위협 × 취약점`.
- 30회 16번 포인트: 취약점이 **없거나** 보호대책이 갖춰져 있으면, 위협이 발생해도 손실은 발생하지 않는다.

## 자주 나오는 파생 용어

- **보호대책(Safeguard/Countermeasure)**: 위험을 줄이기 위한 관리적·물리적·기술적 대책.
- **잔여위험(Residual Risk)**: 보호대책 적용 후에도 남는 위험.
- **DoA (Degree of Assurance, 수용가능한 위험 수준)**: 경영진이 승인한 목표 위험 수준. 잔여위험 ≤ DoA 여야 함.

## 위험 분석 방법론

| 접근법 | 특징 |
|---|---|
| 베이스라인 접근법 | 표준 체크리스트로 일괄 적용. 빠르지만 조직 특성 반영 부족 |
| 비정형 접근법 | 전문가 경험에 의존. 소규모에 적합, 일관성 낮음 |
| 상세 위험 분석 | 자산·위협·취약성 정밀 분석. 정확하지만 비용·시간 큼 |
| 복합 접근법 | 고위험 영역만 상세 분석 + 나머지는 베이스라인. 실무에서 가장 많이 사용 |

### 접근법 상세 (자주 빈칸/서술 — 4-4, 20-3, 22-14, 27-13, 29-9)

| 접근법 | 개념 | 장점 | 단점 |
|---|---|---|---|
| **베이스라인(기준선)** | 모든 시스템에 **표준화된 체크리스트**로 기본 보호 수준 일괄 적용 | 빠름·저비용, 전문성 불필요 | 조직 특성 미반영, 과잉/과소 보호 |
| **비정형(비정형화) 접근법** | 구조적 방법론 없이 **경험자의 지식**으로 분석 | 신속, 소규모 적합 | 일관성·재현성 낮음, 분석자 역량 의존 |
| **상세 위험 분석** | 정립된 모델로 **자산·위협·취약성** 정밀 분석·평가 | 정확, 근거 명확, 변화 대응 용이 | 시간·비용·전문 인력 많이 필요 |
| **복합(혼합) 접근법** | **고위험 영역 = 상세 분석**, 나머지 = 베이스라인 | 정확성·속도 균형, 자원 효율 | 고위험 영역을 **잘못 식별**하면 분석 낭비·부적절 대응 |

### 위험 분석 방법론 (2-2, 9-8, 13-7, 20-2, 21-8, 30-10)

- **정성적**
  - **델파이법**: 전문가 집단의 **토론·설문**으로 위협·취약성 분석. 짧은 기간에 도출, 추정 정확도는 낮음.
  - **시나리오법**: "어떤 사건도 기대대로 발생하지 않는다"는 전제로, 일정 조건에서 발생 가능한 결과들을 추정.
  - **순위결정법(순위 척도)**: 위험 항목의 상대적 우선순위를 매김.
  - **퍼지 행렬법**: 언어적 평가값(높음/중간/낮음)을 근사 추론.
- **정량적**: 과거자료 분석법, 수학공식 접근법, 확률분포법(몬테카를로) → **ALE = SLE × ARO**, `SLE = 자산가치(AV) × 노출계수(EF)`
- 정성적: 계산 없이 빠름, 주관적 / 정량적: 객관적 수치·비용편익 분석 가능, 시간·데이터 필요.
