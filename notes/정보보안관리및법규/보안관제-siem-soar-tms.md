## 통합 로그·이벤트 관리 계보

| 솔루션 | 세대 | 특징 |
|---|---|---|
| **ESM** (Enterprise Security Mgmt) | 1세대 | 방화벽·IDS 등 **보안장비 로그**를 통합 관제, 실시간 상관분석 |
| **SIEM** (Security Information & Event Mgmt) | 2세대 | 보안장비 + **서버·앱·네트워크 등 전 IT 로그**를 **빅데이터** 기반으로 수집·통합·분석. 장기 저장, 컴플라이언스 리포트, 포렌식 (31-12, 32-5) |
| **SOAR** (Security Orchestration, Automation & Response) | 3세대 | 2015 가트너 제시. **AI/자동화 플레이북**으로 경보 분류·대응까지 자동 수행, SIEM보다 진보 (25-12) |
| **TMS** (Threat Management System) | — | 전사 IT 인프라 위협정보를 수집·분석·경보·관리. 외부 **공신력 있는 기관의 위협정보**를 실시간 수집·연동 (16-8) |
| **XDR** | 최신 | 엔드포인트·네트워크·메일·클라우드 탐지를 상관분석 |

## SIEM 주요 기능 — 로그 처리 단계 (1-6)

| 단계 | 내용 |
|---|---|
| **로그 수집** | 대상 시스템의 에이전트/SNMP/syslog로 로그를 중앙 서버에 저장 |
| **로그 분류** | 이벤트 발생 누적 횟수 등 유사 정보를 그룹핑 |
| **로그 변환(정규화)** | 서로 다른 포맷을 공통 스키마로 표준화 |
| **로그 분석(상관분석)** | 룰·통계·머신러닝으로 위협 탐지, 경보 발생 |

## 네트워크 보안관제 시스템의 3대 기술 구성요소 (29-15)

1. **에이전트(수집 센서)**: 서버·네트워크·보안장비에 설치되어 로그·이벤트를 수집해 중앙으로 전송
2. **정보 수집(관리) 서버**: 에이전트가 보낸 데이터를 수집·정규화·상관분석·처리하고 DB에 저장
3. **콘솔(관제 화면)**: 분석 결과·경보를 시각화하고 관제 요원이 조회·대응하는 인터페이스

## 보안관제 절차 (탐지 → 분석 → 대응)

```
수집(로그·이벤트) → 탐지(룰·시그니처·이상행위) → 분석(정탐/오탐 판정, 심각도 등급)
 → 대응(차단·격리·조치 요청) → 보고·전파 → 사후관리(룰 튜닝·재발방지)
```

- **1차(관제) 대응**: 24×365 모니터링, 경보 1차 판단, 단순 차단.
- **2차(심층) 분석**: 정밀 분석, 포렌식, 침해 여부 확정, 위협 헌팅.
- 지표: 탐지 건수, **오탐률(FP)**, MTTD(평균 탐지 시간), MTTR(평균 대응 시간).

## 보안관제 유형

| 유형 | 설명 | 장단점 |
|---|---|---|
| **자체 관제** | 조직이 직접 SOC 운영 | 내부 이해도↑, 비용·인력 부담 |
| **파견 관제** | 전문업체 인력이 고객사에 상주 | 통제 용이, 인건비 |
| **원격 관제** | 관제업체 센터에서 원격 모니터링 | 비용 효율, 내부 맥락 부족 |
| **클라우드 관제** | SECaaS, 관제 기능을 클라우드로 | 빠른 도입, 데이터 위탁 이슈 |

## 위협 인텔리전스 (CTI)

- **IOC** (침해지표): 악성 IP·도메인·해시·URL — 즉시 차단용, 단기 가치
- **TTP** (전술·기법·절차): 공격자의 행동 패턴 (MITRE ATT&CK) — 오래 가는 가치
- **STIX**(위협정보 표현 표준) / **TAXII**(교환 프로토콜) 로 기관 간 공유
- 출처: 상용 피드, KISA C-TAS, ISAC, OSINT

## 정보공유분석센터 (ISAC) — 13-2

침해사고 발생 시 **실시간 경보·분석 체계**를 운영하며 **금융·통신 등 분야별** 정보통신기반시설을 보호하는 업무를 수행하는 기관(정보공유분석센터).
- 근거: 정보통신기반보호법 §16. 회원사 간 취약점·침해정보 공유, 분야별 관제.
- 유관: **KISA**(민간 종합, C-TAS 위협정보 공유), **국가사이버안보센터**(공공), 금융보안원(금융 ISAC).
