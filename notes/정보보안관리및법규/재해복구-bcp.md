## 재해복구센터(DRS) 4유형

| 유형 | 구성 | RTO | RPO | 비용 |
|---|---|---|---|---|
| **미러(Mirror)** | 주센터와 동일, **Active-Active** 실시간 이중 서비스 | 즉시 | **0** | 최고 |
| **핫(Hot)** | 동일 설비 Stand-by, 데이터 실시간/근실시간 | 수시간 | 수분~수시간 | 높음 |
| **웜(Warm)** | 핵심 시스템만 부분 구축 + 주기 백업 | 수일 | 수시간~수일 | 중간 |
| **콜드(Cold)** | 공간·전원만, 데이터만 원격 보관 | **수주** (가장 김) | 수일 | 최저 |
| 상호지원협약 | 두 기관이 서로 시스템 이용 협약 | — | — | 낮음 (실효성 한계) |

- **RTO** (Recovery Time Objective): 목표 **복구 시간** (재해~서비스 재개까지 허용 시간, "얼마나 빨리")
- **RPO** (Recovery Point Objective): 목표 **복구 시점** (마지막 백업~재해 사이 = **데이터 손실 허용량**, "얼마나 최근 데이터까지")
- **MTD/MTPD** (Maximum Tolerable Downtime): 이 시간을 넘으면 조직이 회복 불가 → **RTO < MTD** 여야 함
- **WRT** (Work Recovery Time): 시스템 복구 후 데이터 검증·업무 정상화에 걸리는 시간. **MTD = RTO + WRT**
- **RCO** (Recovery Consistency Objective): 복구된 데이터의 정합성 목표

### 타임라인

```
       [재해 발생]
 ...데이터 ──RPO──▶ | ◀── RTO ──▶ [시스템 복구] ◀── WRT ──▶ [업무 정상화]
   마지막 정상 시점                       └────────── MTD ──────────┘
```

- RPO 0 = 실시간 동기 복제(미러), RPO 수시간 = 주기적 백업(콜드/웜).
- 미러가 RTO·RPO 최소, 콜드가 최대. 데이터 갱신 많으면 미러는 동기화 부하·비용 급증.

### 국제 표준 복구 등급 (SHARE 7 Tier, 참고)

Tier 0(백업 없음) → Tier 1(오프사이트 백업) → … → Tier 6(무손실, 자동 전환) → Tier 7(완전 자동화 무중단). 국내 DRS 4유형과 대응: 콜드≈Tier 1~2, 웜≈Tier 3~4, 핫≈Tier 5~6, 미러≈Tier 7.

## BCP (업무 연속성 계획) 5단계

1. **프로젝트 착수** — 범위·정책·조직
2. **BIA (업무영향분석)** — 핵심 업무 식별, 중단 시 재무·법규·평판 영향 산정, **RTO/RPO 결정**
3. **복구 전략 개발** — 대체 사이트·인력·데이터 백업 전략
4. **복구 계획 수립** — 절차서·매뉴얼 작성
5. **테스트 및 유지보수** — 모의훈련, 현행화

## BCP vs DRP

- **BCP**: 조직 전체 업무 지속 (인력·시설·프로세스 포함) — 상위 개념
- **DRP** (재해복구계획): IT 시스템·데이터 복구에 집중 — BCP의 하위

## BCP 테스트(모의훈련) 유형 (강도 낮음 → 높음)

| 유형 | 내용 | 업무 영향 |
|---|---|---|
| **체크리스트(점검표)** | 계획서·연락망·자원 목록을 서면 검토 | 없음 |
| **워크스루(구조적 검토)** | 관계자가 모여 시나리오별 대응 절차를 토론 | 없음 |
| **시뮬레이션** | 가상 재해 시나리오로 대응 역할극(실제 복구는 안 함) | 낮음 |
| **병행(Parallel) 테스트** | 백업센터에서 실제 시스템을 가동, 운영센터와 **병행** 처리 결과 비교 | 중간 |
| **전체 중단(Full-interruption)** | 운영센터를 실제로 내리고 백업센터로 **완전 전환** | 높음(위험) |

## 백업 방식

| 방식 | 백업 대상 | 백업 시간 | 복구 시간 | 복구 절차 |
|---|---|---|---|---|
| **전체(Full)** | 전체 데이터 | 김 | 빠름 | 1개 세트로 복구 |
| **증분(Incremental)** | **직전 백업(전체/증분) 이후** 변경분 | 짧음 | 느림 | Full + **모든 증분** 순서대로 |
| **차등(Differential)** | **마지막 Full 이후** 변경분(누적) | 점점 김 | 빠름 | Full + **마지막 차등 1개** |

- 아카이브 비트: 전체·증분은 백업 후 비트 해제(변경 추적), 차등은 해제 안 함.
- **GFS (Grandfather-Father-Son)**: 일(Son)–주(Father)–월(Grandfather) 순환 보관 정책.
- **3-2-1 규칙**: 사본 3개, 서로 다른 매체 2종, 1개는 원격지(오프사이트).
- 백업 매체 세대 관리, 정기 복구 테스트, 원본과 분리 보관·암호화.
