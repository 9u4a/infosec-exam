## 용어 위계 (4-5, 15-9, 26-12)

| 용어 | 정의 |
|---|---|
| **위험관리 (Risk Management)** | 자산의 위험을 **수용 가능한 수준으로 유지**하기 위해 위험을 분석하고 **비용 대비 효과적인** 보호대책을 마련·구현·모니터링하는 **전체 과정** |
| **위험분석 (Risk Analysis)** | 자산·위협·취약성을 식별·분류하고 위험의 종류와 규모(위험도)를 산출 |
| **위험평가 (Risk Assessment / Evaluation)** | 산출된 위험도를 **DoA와 비교**해 처리 우선순위 결정 |
| **위험처리 / 대책 선정** | 감소·회피·전가·수용 중 선택 |

## 절차 표준 한 장 비교 (여러 버전이 나와서 헷갈림)

가운데 뼈대는 모두 같다: **식별 → 분석 → 평가 → 처리 → 모니터링**. 표준마다 이름·묶음만 다름.

| 공통 단계 | 국내 위험관리 단계 | ISO 27005 | ISO 31000 | 자산분석 절차 |
|---|---|---|---|---|
| (준비) | 위험관리 전략·계획 수립 | 상황 설정 | **상황 확립(Context)** | — |
| **식별** | 위험 식별 | 위험 식별 | 위험 식별 | 자산 식별 → 자산가치·의존도 평가 |
| **분석** | 위험 분석 | 위험 분석 | 위험 분석 | 위협 평가 → 기존대책 평가 → 취약성 평가 |
| **평가** | 위험 평가 | 위험 평가(Evaluation) | 위험 평가 | 위험 평가(위험도 산출) |
| **처리** | 대책 선정 → 이행계획 → 구현 | 위험 처리(Treatment) | 위험 처리 | — |
| (계속) | 모니터링·개선 | 위험 수용 · 소통 · 모니터링 | 모니터링·검토 + 소통·자문(전 과정) | — |

- "**Assessment**"(평가)는 넓게 쓰면 식별+분석+평가 전체, 좁게 쓰면(Evaluation) DoA 비교 단계만. 지문 문맥으로 판단.
- ISO 31000 특징 키워드: **상황 확립**, 전 과정 **소통·자문 + 모니터링·검토**.
- ISO 27005 특징 키워드: 정보보안 **전용**, 위험 처리 후 **위험 수용**을 별도 단계로.

## 위험관리 단계 (23-11, 31-7)

```
위험 식별 → 위험 분석 → 위험 평가 → 정보보호 대책 선정
          → 대책 이행계획 수립 → 대책 구현 → (모니터링·개선)
```
- 31-7 빈칸: (A) 위험 분석 (B) 위험 평가 (C) 정보보호 대책 구현.
- 23-11: (A) 위험분석 (B) 위험평가.

## 정보자산 분석 절차 (18-8, 23-12, 30-12)

1. **자산 식별** — 보호 가치 있는 자산 목록화 (형태·소유자·관리자·특성 포함)
2. **자산 가치 및 의존도 평가** — CIA 기준 중요도 산정
3. 위협 평가
4. 기존 보안대책 평가
5. **취약성 평가**
6. 위험 평가(위험도 산출)

## ISO 27005 위험평가 절차 (17-9)

| 단계 | 내용 |
|---|---|
| **위험 식별 (Risk Identification)** | 손해 발생의 근원을 밝히기 위해 자산·위협·현 통제·취약점 식별 |
| **위험 분석 (Risk Analysis)** | 발생 가능성 × 결과로 위험 수준 산정(정성/정량) |
| **위험 평가 (Risk Evaluation)** | 위험 수준을 위험 수용 기준과 비교, 처리 우선순위 결정 |

→ 이후 **위험 처리(Risk Treatment)** + 위험 수용 + 위험 소통 + 모니터링/검토.

## ISO 31000 (24-7)

일반 리스크 관리 프레임워크. 위험평가(Risk Assessment) = **위험 식별 → 위험 분석 → 위험 평가**.
- 상황 확립(Context) → 위험평가 → 위험처리 → 전 과정에 소통·자문 + 모니터링·검토.

## 취약성 평가 (32-4)

**위험원(공격자·위협) 관점에서 IT 시스템의 약점을 식별·검증**하는 방법.
- 자동 스캐너(Nessus, OpenVAS) + 수동 점검(설정·소스) + 모의해킹(침투 테스트)로 검증.
- "우려사항 관점"이 아니라 "위협원이 악용 가능한 약점" 관점이라는 점이 포인트.

## 목표 위험 수준 포함 (5-8)

위험 평가 시 잠재적·알려진 **위협**과 **취약점**으로 인한 피해 + 현 통제의 실패 가능성·영향을 평가하며,
반드시 **목표(수용 가능) 위험 수준(DoA)** 을 포함해 비교 기준으로 삼아야 한다.

## 위험관리 계획서 (28-10)

위험관리 방법·절차(수행 인력·기간·대상·방법·예산 등)를 구체화한 문서.
이에 따라 정기적으로 또는 필요 시점에 위험 평가를 수행한다.
